# Doc9/Doc10 Shared Link Diagnostics Proposal
Canonical language: English; [Japanese companion](../ja/documentation_links.md).
Status: non-normative, selected diagnostic/provenance design under the dispatch screening rule; no registry activation, code/schema allocation or implementation. [Spec24.2](../../../spec/en/24.documentation_generation.md#242-cross-referencing-and-hyperlinks) fixes warning/degradation semantics; [Doc prerequisite inputs](../../mizar-doc/en/link_prerequisites.md) own producers and allocations.

## Exact Meanings And Descriptors
Each row proposes family `Documentation`, default severity `Warning`, phase `Documentation`, category `DocumentationWarning`; semantic name equals permanent meaning key. Initial lifecycle is active only upon adoption, with empty aliases, retirement marker and replacements. Summary is the English text before the colon below. Follow [registry metadata/compatibility](./registry.md#descriptor-metadata); existing attachment and Markdown/tag meanings remain unchanged.
| Semantic name / meaning key | Summary: exact condition |
|---|---|
| `documentation.link.unresolved` | Documentation reference is unresolved: an eligible occurrence has no target after the required complete search, no matching section in the bound complete section index, or unavailable/unsupported interpreted destination classification under spec24.2. |
| `documentation.link.ambiguous` | Documentation reference is ambiguous: the applicable complete lookup yields multiple distinct full target identities after duplicate-route collapse; multiple current-module hits are definitive without imports. |
| `documentation.link.incomplete_input` | Documentation link inputs are incomplete: required import/closure/citation/allocation/section-index coverage is unavailable or incomplete, preventing the affected reference, module-page, section-index or UsedBy completeness claim. |
Numeric codes, `since` adopting revision and normative `doc_url`: UNSELECTED until separate coherent adoption/allocation. No numeric slot is reserved; names and summaries are selected proposal choices, not owner Qs.

## Structured Identity And Details
Use existing [String/List detail values](./failure_record.md#markdowntag-occurrence-details) and `stable_detail_key = semantic_name`. Every draft has exactly these detail keys; absent values use empty Lists, never guessed zero/empty identity strings. Identity encodings reuse that owner's lowercase publication hash, full module tuple, optional-version/lock Lists and canonical unpadded decimal u64 Strings.
`documentation.link.subject` is `[publication, module, target, scope, occurrence]`. Target is empty if unavailable, `["module"]` for the bound module, or `["item", origin_id, fqn]` for a verified export; enclosing publication/module completes its identity. Scope is `reference|module_page|section_index|used_by`. Occurrence is `[block, start, end, form]` for references, using Doc8 logical half-open offsets and `code|explicit|see`; it is empty for input-level subjects. Preserve true block ordinals and full subject identities even with mapped primaries.
`documentation.link.reference` is `[raw, interpreted]` for references, where interpreted is an empty or singleton String List; otherwise empty. `documentation.link.section_version` is an empty or singleton String List retaining the exact bound specification version. `documentation.link.candidates` is a List of distinct `[publication, module, origin_id, fqn]` target tuples; sort by existing full module identity order, exact FQN, origin, publication hash. It is empty for unresolved and input-only subjects; incomplete reference searches may retain authenticated known candidates without claiming completeness.
`documentation.link.causes` is a List of `[reason, affected]` pairs. Affected is the authenticated `[publication, module, target]` identity or empty when unavailable; never infer an endpoint. Unresolved reasons are `target_absent|section_absent|classification_unavailable`; ambiguity uses `multiple_targets`. Incomplete reasons are `imports_unavailable|imports_partial|closure_unavailable|closure_partial|citations_unavailable|citations_partial|citation_endpoint_unmapped|page_unavailable|page_collision|label_unavailable|anchor_collision|sections_unavailable|sections_partial`. Retain all independently established causes, deduplicate identical pairs and sort by reason then affected using the existing detail comparator. Unresolved/ambiguous drafts carry their single applicable reason with empty affected.
`documentation.link.routes` is a List of `[candidate, kind, position, endpoint]` tuples for known candidates. Candidate uses the tuple above; kind is `current|import|closure`; position is a singleton decimal import-vector ordinal List for import, otherwise empty; endpoint is the authenticated `[publication, module]` queried directly. The subject supplies the querying module. Closure means inventory membership, not a dependency walk: never enumerate paths through cycles. Sort by kind in the stated order, numeric position, endpoint full module/publication identity, then candidate order above; collapse identical tuples while retaining distinct import positions. Input-only/unresolved subjects use an empty List. Routes never establish target multiplicity or a lookup winner.
`documentation.link.citation_coverage` is empty except for UsedBy subjects, where it is `[closure_state, closure, coverage_state, examined]`. States are `unavailable|incomplete|complete`; closure is the authenticated finite inventory of `[publication, module]` pairs in full module identity/publication order. Examined is the producer's List of `[publication, module, origin_id, fqn, parts]` theorem entries, in candidate order; parts lists the actually examined `body|proof` portions in that order without duplicates. Missing coverage retains an unavailable state and empty examined List, not complete-empty; missing closure retains its own unavailable state. These are explicit scope projections, not guessed hashes, source reconstruction or a shared wire schema.

## Locations, Precedence, Deduplication And Ordering
For a reference, choose the first complete contiguous source-bound mapped destination segment (inline code: its label contents; @see: its ref slot); retain remaining mapped segments as secondary spans in logical encounter order, without bridging gaps. If no usable primary exists, reuse the [Documentation block provenance primary](./failure_record.md#documentation-primary-locations) with the true block ordinal. Adoption must explicitly extend its applicability to these descriptors; raw paths, artifact offsets and labels do not bind source.
Input-level warnings have no invented block. Propose a module-scope Documentation provenance primary containing authenticated publication and full module identity, without a block ordinal; a verified item subject remains in details. It has no SourceId/span/EOF, line/column, underline or excerpt. CLI identifies publication/module after `  --> documentation ` and appends `scope`, scope value and verified item identity when present. This location extension requires separate adoption/support; it is not an existing implemented variant.
Use the same Documentation source key to group a module's scope and block locations; order scope primaries before block primaries, with blocks still ordered numerically. Scope dedup identity includes its distinct location kind and full publication/module identity. Existing [deduplication](./aggregator.md#deduplication-identity), [canonical comparator](./aggregator.md#ordering-and-handles), presentation tie-breaker and stale-snapshot rules otherwise remain unchanged. Mapped ties follow existing code/details order; do not introduce a traversal sort or guess future numeric code order.
Emit one warning per reference subject, choosing incomplete before ambiguous before unresolved when required inputs are missing; a definitive current-module result does not depend on unused import inputs. Allocation is required only after a unique target is established: missing destinations of ambiguous candidates cannot override complete lookup ambiguity. Complete successful references, external URLs, ordinary expression/code spans and suppressed optional aliases emit none. Missing @see slots and Doc8 failed-view blocks remain solely Doc8's warnings; do not invent eligible references from their fallback text. Lower-reader integrity/schema/binding/currentness refusals retain errors and suppress dependent presentation drafts.
Emit one input-level completeness warning for each affected module-page, section-index or theorem UsedBy subject with all its causes. Reference warnings remain separate from scope warnings, but duplicate reports of the same subject/cause set collapse. Multiple workers or routes cannot multiply one warning; distinct logical occurrences remain distinct through details even at coincident mapped locations. Citation occurrence details remain in the producer graph; a UsedBy warning identifies the affected target and coverage, never an invented citing occurrence.
Unresolved/ambiguous references retain safe unlinked text; incomplete outputs are visibly unavailable, never empty-complete. These remain default presentation warnings; existing suppression/profile rules apply after allocation. Profile promotion can fail only documentation quality, preserving code/default severity, proof validity, published verification inputs and extraction acceptance. No fixes, new suppression syntax, shared wire schema or renderer diagnostics are proposed.
