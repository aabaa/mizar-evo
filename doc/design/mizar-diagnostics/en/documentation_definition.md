# Documentation Diagnostics Definition Proposal
Canonical language: English; [Japanese companion](../ja/documentation_definition.md).
Status: historical proposal; owner approved DD-Q1–DD-Q7 option ① on 2026-11-18. Current normative definitions and adoption are owned by [spec22](../../../spec/en/22.error_handling_and_diagnostics.md#2268-documentation-attachment-warnings) and [registry](./registry.md#documentation-attachment-allocation). The proposal and alternatives below record the pre-adoption state; option ② is not authorized.

## Authority And Fixed Boundaries
[Spec22](../../../spec/en/22.error_handling_and_diagnostics.md#2211-error-code-system-e-series) owns permanent severity-prefixed codes; [registry gaps](./registry.md#deferred-code-space-gaps) prohibit Documentation allocation/publication until a later specification update. [Internal05](../../internal/en/05.documentation_extraction.md#diagnostics) calls the phase family `Documentation`, separately from `Extraction`; this proposal covers only [Doc7 attachment outcomes](../../mizar-doc/en/comments.md#residual-association-definitions).
Approved comment Q1–Q8 option ① remains binding. In particular, attachment failures are default presentation warnings retaining text/provenance, without repair or inferred verified identity. This inherited Warning requirement is not a new severity selection. No E/I descriptor is proposed. Profile promotion may fail the documentation build without changing code identity, proof validity or extraction policy; lower-reader integrity/staleness/schema failures and preprocessing diagnostics retain their original meaning.
The registry keeps ownership of allocation and compatibility validation. The current [PhaseFamily](../../../../crates/mizar-diagnostics/src/registry.rs) assigns one default severity per family and maps prefix plus number to that family; it has neither `Documentation` nor `Extraction`. DD-Q1 asks how a later update represents Documentation, not whether Doc7 can use another existing family.

## Candidate Range And Attachment Descriptors
Candidate A is `W0400`–`W0499`, with five initial rows below; candidate B is `W0700`–`W0799`, translating each row by +300. Both lie outside existing warning ranges/allocations. Neither reserves the intervening or unused numbers, an E/I range, or any Extraction range; unused numbers within an adopted range would remain unallocated.
Every row is a candidate descriptor, conditional on DD-Q1–DD-Q6. `phase_family` would be `Documentation` and `default_severity` Warning. The table's suffix combines with `documentation.attachment.` to form the proposed `semantic_name`; DD-Q4 controls the separate stable `meaning_key`.

| Candidate A code | Name suffix | Condition / proposed English `summary` |
|---|---|---|
| `W0400` | `orphan` | No eligible module or adjacent named-item candidate for the documentation block. |
| `W0401` | `unresolved_target` | Adjacent documentation target lacks supported verified identity, label or target boundary. |
| `W0402` | `ambiguous` | Multiple identities or contradictory candidate/range associations remain for the documentation block. |
| `W0403` | `unverified_target` | Documentation target is invalid or unverified. |
| `W0404` | `unresolved_coordinates` | Required documentation association coordinates are absent or cannot be related to the verified target. |

DD-Q3 alternatively groups unresolved-target, unverified-target and unresolved-coordinates under one descriptor; all five existing conditions and presentation outcomes still apply. Neither mapping sets precedence, multiplicity or deduplication when conditions overlap. Existing deterministic ordering applies; any additional emission-policy definition remains a prerequisite rather than an enumeration-order fallback.
For a future first allocation, candidate metadata is `status = active`, no aliases, no retirement marker and no replacement codes. DD-Q5 proposes the `since` and `doc_url` policy; the final values must identify that actual allocation, never this unapproved proposal. [Allocation](./registry.md#allocation-rules), [retirement](./registry.md#retirement-rules) and [compatibility](./registry.md#compatibility-validation) rules still apply: code/prefix/family/default severity/meaning key are permanent, retired descriptors remain and numbers are never reissued. Semantic-name renames require aliases; message text is not identity.

## Locations And Adoption Prerequisites
An available preserved block range is the primary location; available candidate ranges may be related locations. Preserve the owning publication/module/item provenance and mapped source positions, without inventing candidate locations. Missing association coordinates need not imply a missing block range: a representable block range can still locate `unresolved_coordinates`. Deliberate private-doc omission alone is neither an orphan nor a missing-comment warning.
When no usable source-bound primary location exists, [spec22 locations](../../../spec/en/22.error_handling_and_diagnostics.md#2212-source-span-and-context-display) and the current [record model](../../../../crates/mizar-diagnostics/src/failure_record.rs) allow non-range locations only for SourceLoad codes. A preserved artifact offset alone does not establish a loaded-source binding. Do not fabricate a span/EOF or disguise a Documentation warning as SourceLoad. DD-Q7 exposes this separate representation gap; choosing a range and descriptors alone cannot close it.
Missing source, optional missing-comment lints, Markdown/tags, links/UsedBy, math/rendering and all Extraction diagnostics remain later definitions; no catch-all descriptor is proposed for them. Source-integrity refusal is never downgraded to `unresolved_coordinates`. Deterministic diagnostics preserve source order and full identities under the existing shared ordering/profile rules; no warning text becomes a key.
After owner decisions, a separate authorized update must synchronize the paired normative owners selected by DD-Q6, then registry/record specifications, implementation and descriptor/compatibility/location tests before real Doc7 adoption. This proposal supplies neither implementation coverage nor permission to emit codes. Doc7 remains parked until those prerequisites and its own contract are ready; Doc8 remains dependent. Approving this proposal does not complete either task or broader phase 16.

## Owner Q-Decisions — All Unselected

| DD-Q4 — stable meaning keys | Use each selected `documentation.attachment.<suffix>` semantic name as its immutable meaning key. | Use immutable keys `documentation.attachment.v1.<suffix>` while retaining the selected unversioned semantic names; later renaming never changes a key or transfers meaning. |

| DD-Q7 — unavailable primary location | Specify a Documentation-specific non-range location grounded in publication/module/block provenance in paired spec22 and shared record owners, then implement/test it before adoption.
