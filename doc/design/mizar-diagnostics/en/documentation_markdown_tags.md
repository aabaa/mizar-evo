## Candidate Meanings And Descriptors
This section spells out MT-Q1①, not an adopted registry. All seven meanings retain offending text; tag conditions use the approved field model, not renderer output. A missing name/ref/version slot is absence, not a malformed-token grammar: opaque backticks, links, entities or non-ASCII whitespace never justify an extra syntax warning. Missing required bodies use approved W/non-W source nonemptiness; markup-only bodies count as nonempty.

| Candidate semantic name / meaning key (MT-Q2①) | English summary / exact condition |
|---|---|
| `documentation.tag.missing_slot` | A known tag lacks its required name, reference or version slot: `@param`, `@see`, `@since`, `@deprecated` respectively. |
| `documentation.tag.missing_body` | A required explanatory body is empty for `@returns`, `@requires`, `@ensures`, or after `@deprecated version`. |
| `documentation.tag.duplicate` | A later known-tag occurrence violates the approved same-target raw duplicate rule: same `@param` name, repeated singleton (`@returns`, `@since`, `@deprecated`), or identical raw tag/payload for repeatable `@requires`, `@ensures`, `@see`. |
| `documentation.tag.metadata_mismatch` | Available authoritative metadata establishes that a named parameter is absent from a complete list, or that `@returns` targets an item with no return value. |
| `documentation.markdown.unmatched_math_delimiter` | An eligible math opener has no valid matching closer under the approved protected-boundary rules; preserve its literal spelling/CommonMark parse. |
| `documentation.markdown.empty_display_math` | A paired display-math candidate has only W in its interior; preserve its full literal spelling without a math node. |
| `documentation.markdown.conversion_failure` | A real inability to derive or map the Markdown/tag presentation view requires raw fallback for the affected block. |

Duplicate scope includes separate source-ordered blocks attached to the same full-provenance target; never merge/overwrite occurrences. Unknown/lookalike tags, undocumented parameters, absent/partial parameter membership metadata, unavailable return metadata and unresolved `@see` refs do not create these warnings. Partial metadata cannot establish absence; required-slot/duplicate checks still apply. Do not compare prose with formal formulas or infer signatures, version syntax or reference validity.
Descriptor policy: family `Documentation`, default severity `Warning`; phase `Documentation`, category `DocumentationWarning` are inherited constraints, not new choices. Each eventual descriptor needs its own unassigned numeric code, selected semantic name, immutable meaning key, table summary and MT-Q7 provenance metadata. Candidate initial lifecycle is active, with empty aliases, retirement marker and replacement codes; actual activation occurs only in adoption. [Registry metadata](./registry.md#descriptor-metadata), [allocation](./registry.md#allocation-rules), [retirement](./registry.md#retirement-rules) and compatibility remain binding. Renames retain permanent meaning keys and aliases; messages never define identity. W0400–W0404 remain attachment-only; no other slot is reserved here.

## Locations, Emission And Profiles
Every candidate preserves validated publication, complete module identity, verified target where available, block ordinal and the original raw text/maps. Use only real source-bound mapped ranges. Discontiguous container/Q3 mappings never justify a synthetic contiguous range; MT-Q3 exposes the primary/related-range choice. If no usable source-bound primary exists, MT-Q3 proposes reuse of the existing [Documentation provenance location](./failure_record.md#documentation-primary-locations), whose normative use currently covers attachment warnings; later adoption must explicitly extend applicability. A path, label or artifact offset is not a SourceId or loaded-source binding. Never invent a span/EOF, line/column, candidate identity or new location variant.
For an actual conversion/map failure, use independently retained valid raw-block mapping/provenance for fallback and location; never depend on the failed view to locate itself. Lower-reader integrity/staleness/schema refusal remains its original error and cannot become a presentation warning or successful read. MT-Q4–MT-Q6 define candidate occurrence identity, overlap and block-failure precedence; no enumeration-order fallback or silently lost occurrence is authorized by this proposal.
Preserve source block/line/tag order in derived products and duplicate comparisons. Shared [deduplication](./aggregator.md#deduplication-identity), [canonical order](./aggregator.md#ordering-and-handles) and [Documentation ordering](./aggregator.md#documentation-locations) remain unchanged, including numeric block ordinals and full identities. Diagnostic record order follows that comparator, not a second source-order sort; it can differ from tag traversal for coincident locations. No numeric code order is guessed before allocation. New occurrence distinctions must be machine details under MT-Q4, never message text, storage order or worker order; no shared schema/API or dedup change is adopted.
Warnings remain default presentation warnings with retained text and default-build fallback. Existing documentation-profile promotion may fail that documentation build only; it changes neither code/default severity nor proof validity, published verification inputs or extraction acceptance. This proposal adds no profile flags, suppression syntax, automatic fixes or warning escalation; later allocated codes must follow applicable spec22 warning controls. Missing source/comment, attachment, links/UsedBy and downstream math/HTML rendering diagnostics stay with their owners. Doc9 Q1–Q10 and Doc11 Q1–Q12 remain unselected and are not prerequisites decided here.
