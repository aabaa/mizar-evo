# Artifact Source Comment Projection
Canonical language: English; [Japanese companion](../ja/comment_projection.md).
Status: definitions and structural codec for the approved emission-time projection; producer-to-publication integration remains open. Artifact owns this data contract; [VerifiedArtifact](./verified_artifact.md#ownership) retains schema/version/hash authority.

## Ownership And Handoffs
The owner-selected [Doc6 Q1](../../mizar-doc/en/comments.md#owner-q-decisions) projects source-derived comments/maps into published artifacts at emission. Source rereading is not the comment transport or a fallback. Optional bound source loading remains available for snippets/source links under its existing owner.
1. **Frontend producer:** [preprocessing](../../mizar-frontend/en/preprocess.md#comments-and-doc-comments), backed by Lexer trivia and Session [maps](../../mizar-session/en/source_map.md#data-structures), collects exact comment text, source positions and adjacency evidence from the genuine captured source. Its result is source metadata, not verified attachment. Syntax supplies syntactic item/annotation candidates; verified export producers retain semantic item identities.
2. **IR projection:** [ArtifactProjectionService](../../mizar-ir/en/projection.md#ownership) consumes those producer records with their sealed, readable current-snapshot output lineage and the corresponding verified item records. It checks source/module/lineage agreement and converts only stable data into the Artifact-owned shape in an unpublished draft; it neither reparses source nor invents verified targets.
3. **Driver orchestration:** [captured-source binding](../../mizar-driver/en/frontend_adapter.md#native-captured-sources) retains the actual source and maps through producer → IR → emission. It supplies matching snapshot/package/source and verified outputs, then uses the existing ArtifactCommit/store/manifest validation and atomic publication boundary. No reloading, replacement SourceId or post-publication sidecar supplies missing comments. OpenBuffer/InternalOnly drafts gain no package-publication eligibility.
4. **Artifact reader and Doc:** the validating reader supplies the projection only with its validated enclosing artifact. Doc's [published-input plan](../../mizar-doc/en/doc_build.md#full-build-and-index-inputs) binds that artifact to the selected publication/current request; [comments](../../mizar-doc/en/comments.md) groups, attaches and derives Markdown afterwards. Neither Artifact nor IR performs Doc attachment, tag parsing, link resolution or rendering.
These are required handoffs, not an integrated callable route. Frontend supplies genuine metadata, IR supplies the validated unpublished comment draft, and Artifact supplies a structural codec; Driver retention/emission, Artifact publication integration and Doc consumption remain required before Doc7 can use the route. Existing empty documentation side tables and `documentation_ref` do not implement it.

## Availability And Identity
Unavailable means the profile or producer did not supply a complete comment projection. Available means the collection for this captured source is complete; zero doc lines is available-empty, while an empty `:::` body is a present line. A supported projection must represent availability explicitly; absence in legacy profiles means unavailable, never an empty collection. A partially collected or malformed payload cannot claim available or be downgraded to unavailable after validation failure.
The enclosing verified artifact owns module identity, normalized package-relative source path/hash and genuine captured origin/version. Retain full package/version/module identity, source-frame lengths and normalization/preprocessing identity needed to interpret the records; never bind by basename, FQN prefix, source range or lexical hash alone. Comment-only edits may preserve the lexical reuse hash while changing the source hash and published projection.
Publication binding is external to the payload: selected manifest/publication hash plus its full module entry and source identity bind the validated enclosing artifact. Do not embed its own final publication/artifact digest as a circular self-reference. Captured SourceId remains a nonportable association under the existing provenance policy, not a stable projected coordinate key, registry membership or currentness proof.
Item landmarks pair source-adjacent syntactic candidates with original verified export origin/FQN and the full owning module/publication context. A producer must supply the actual item/attached-annotation boundaries needed for association; formula ranges or export-name matching cannot substitute. Missing or conflicting verified target information remains unresolved for Doc diagnostics. Do not invent labels or publish raw AST/IR handles, storage generations, local absolute paths or worker identities.

## Text, Coordinates And Adjacency
Available data preserves ordered raw `:::` lexemes, including markers, whitespace and empty bodies, their line boundaries and exact source spans. Ordinary comments are not documentation text, but their positions and other intervening source/trivia/annotation boundaries must remain sufficient to determine adjacency without rereading source. Preserve physical blank lines and distinguish an item-attached annotation from a standalone annotation; source order cannot be replaced by collection enumeration order. Do not preselect module/item attachment or settle module-leading trivia/multiple-block semantics here.
Name each coordinate frame: original captured Disk bytes or OpenBuffer text, normalized loaded source, preprocessed lexical text, and later derived Markdown. Ranges are half-open byte offsets in a declared frame; lengths and valid UTF8 boundaries must agree. Retain the portable loading/preprocess mapping information needed for every projected line, gap and target landmark, including BOM removal, normalized newlines and removed-comment segments. Session's runtime map/bridge handles themselves are not serialized.
Compose lexical → loaded → original maps only within the bound source. Exact mappings, composite anchors and degraded/generated positions retain their distinctions; a primary anchor is not proof of an exact source slice or adjacency. Missing coverage, foreign frames, out-of-bounds spans or incompatible lengths/hashes refuse the affected input, never fabricated exact locations. Projection availability does not imply every queried lexical position has an exact authored range.
At emission the genuine source producer validates text slices, frame lengths, UTF8 boundaries and map correspondence against its captured text. The reader checks serialized structure, bounds, frame/source bindings and map consistency that the payload makes checkable; hashes authenticate the selected publication, not an independent proof of source derivation. A validly hashed caller-created record does not become a genuine producer output or verified attachment.
Doc owns [Q3 body derivation and reverse mapping](../../mizar-doc/en/comments.md#markdown-and-structured-tags). Existing Frontend `raw_body` removes only the marker and must not be mistaken for this derived body. Markdown/tag products are not emitted in this projection.

## Compatibility, Hashes And Refusals
The structural codec does not extend normal1.0/1.1/1.2 or Builtin2.0 in place. Preserve their exact fields, bytes/hash projections, rejection order and version bounds; they provide no projected comments. Unsupported versions and unknown/missing required fields remain errors; never retry a failed reader as another profile or recover comments from source.
Within a projection-capable profile, availability, raw text, ordered spans/landmarks, stable frame/map content and source/origin bindings participate in stable implementation and full Artifact hashes. They are published local metadata, not importer-visible semantic interface fields; interface participation remains the existing export/dependency projection under the same enclosing version. Existing version framing and declared local exclusions remain; no comment-specific exclusion hides content. This does not promise equal interface hashes across schema versions or across changed semantic exports.
Canonical serialization preserves source/line/segment order and semantic vector order, with existing canonical object-key ordering; worker, map insertion and input enumeration order cannot alter equivalent output. Reject conflicting/duplicate records for the same projected source occurrence, without imposing a global unique-range rule on unrelated items or anchors.
Version/schema/path/hash/source/module/provenance mismatches, invalid mappings and incompatible producer lineage retain lower-owner integrity refusals and produce no usable comment payload or partial publication. Unavailable valid legacy input may still support semantic Doc pages. Orphan/ambiguous attachment and tag/Markdown presentation warnings belong to Doc and retain text; they cannot hide integrity failures or affect proof validity, reuse or extraction acceptance.

## Structural Codec Profile
[`comment_projection`](../../../../crates/mizar-artifact/src/comment_projection.rs) exposes `CommentedArtifact` and validating JSON reader/writer under independent family `mizar-artifact/commented-verified-artifact`, exact version `1.0`. The envelope contains a validated normal1.2 artifact and required `comments`: null is unavailable; a complete object with retained original/loaded/lexical text, portable loading/preprocess maps, raw comments, whitespace and source-ordered landmarks is available. Optional target pairs refer to enclosing exports; they do not prove attachment or producer lineage.
Envelope interface hashing retains the export/dependency projection under envelope framing; implementation/full hashes include all comments. Existing local exclusions apply beneath `artifact`. The enclosing artifact supplies full identity/origin; normalized frame text must match its source hash. The reader validates serialized bounds, maps and bindings, without promoting caller-created data to genuine metadata.
This profile is a structural transport prerequisite. Existing manifest/store publication dispatch does not select this envelope; Driver emission, current publication binding and Doc consumption remain separate handoffs.
