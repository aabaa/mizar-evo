# Crate Plan: mizar-artifact

> Canonical language: English. Japanese companion: [../ja/00.crate_plan.md](../ja/00.crate_plan.md).

This plan starts the autonomous crate-development workflow for
`mizar-artifact` tasks 1-22 in [todo.md](./todo.md). The crate is an
infrastructure crate for stable published projections, not a language-behavior
crate; `.miz` test-first additions are therefore not required unless a future
task changes syntax, static semantics, proof semantics, diagnostics, parser
recovery, or soundness-boundary behavior.

## Responsibility

Owned behavior:

- canonical UTF-8 JSON serialization, schema-version compatibility checks, and
  separated semantic/diagnostic hashes for published artifacts;
- `ModuleSummary`, `RegistrationSummary`, `ProofWitnessRef`, and
  `VerifiedArtifact` schema records consumed by downstream tools and producer
  crates;
- content-addressed artifact blobs, named artifact writes with temp-and-rename
  atomicity, and corruption/hash validation on reads;
- package artifact manifests and manifest transactions with deterministic entry
  ordering and old-or-new reader visibility;
- interface-hash and implementation-hash input construction for
  `mizar-cache` consumers.

Out of scope:

- compiler-internal cache records, cache-key trust decisions, dependency-slice
  validation, cluster-db storage, or proof-reuse policy (`mizar-cache`);
- building resolver/checker/VC/kernel/proof outputs that feed the projection
  (`mizar-resolve`, `mizar-checker`, `mizar-vc`, `mizar-kernel`,
  `mizar-proof`);
- source identity, source maps, and build snapshots (`mizar-session`);
- changing language syntax, static semantics, proof acceptance, diagnostics, or
  parser recovery.

## Exit Criteria

- no blocking/high specification contradiction remains;
- no source behavior remains outside design docs and Rust tests within the
  crate-owned infrastructure scope;
- tasks 1-16 and 18-22 are complete, with task 17 explicitly deferred as

- review-only test sufficiency review after tests are added;
- review-only implementation review after implementation;
- review-only source/documentation consistency and quality-score review before
