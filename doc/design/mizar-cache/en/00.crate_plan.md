# Crate Plan: mizar-cache

> Canonical language: English. Japanese companion: [../ja/00.crate_plan.md](../ja/00.crate_plan.md).

## Responsibility

Owned behavior:

- construct canonical cache keys from normalized identities, hashes, schema versions, and verifier policy inputs;
- compute and validate dependency fingerprints, dependency slices, and conservative rebuild triggers once their producer crates expose stable inputs;
- store internal cache records and content-addressed blobs under `cache_dir`;
- validate proof-reuse records against accepted proof-witness hashes or deterministic discharge hashes without granting proof authority;
- maintain `cluster-db/` indexes, origin metadata, and import-scoped views for verified registration and cluster contributions;
- treat every cache hit as an optimization over clean-build behavior, with miss fallback for missing, incomplete, unsupported, or untrusted data.

Out of scope:

- proof authority, kernel acceptance, certificate checking, proof search, proof-witness selection, or upgrading externally attested evidence to kernel-verified status;
- generation of VCs, `ObligationAnchor`s, canonical VC fingerprints, local-context fingerprints, or accepted proof witnesses;
- build scheduling, task invalidation graph ownership, IR storage handles, artifact publication, or manifest authority;
- changes to language syntax, static semantics, proof semantics, diagnostics, existing `.miz` tests, existing expectations, or `doc/spec`.

## Exit Criteria

Hard gates for task 1:

- crate scaffold matches task 1 and does not implement later behavior;
- known gaps are classified as `test_gap`, `spec_gap`, `design_drift`, or `external_dependency_gap` with deferred actions;
- design/source docs agree on task 1 scope and module names;
- boundary discipline is preserved: cache remains an optimization, not proof authority;
- required verification commands pass or have explicit reasons if unrun;
- review-only agents report no unresolved blocking/high findings.

Hard gates for full crate completion:

- all module specs exist in English and Japanese before their implementation tasks;
- no source behavior remains absent from specs and tests;
- cache hits are fail-closed and clean-build equivalent;
- complete dependency slices/footprints are required for reuse;
- proof reuse validates all required evidence and never upgrades externally attested evidence;
- `cluster-db` contains only accepted importer-visible contributions;
- source, tests, and bilingual docs are synchronized;
- required verification commands pass;
- a read-only review assigns a valid quality score of at least 90/100.

Verification commands:

```sh
cargo test -p mizar-cache
cargo clippy -p mizar-cache --all-targets -- -D warnings
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
```

Review expectations:

- implementation-spec/design review before implementation;
- test sufficiency review after tests are added;
- full implementation review after code changes;
- source/documentation consistency review before verification;
- final handoff prompt for the next task with recommended reasoning setting.
