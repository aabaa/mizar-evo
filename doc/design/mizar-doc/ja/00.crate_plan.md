## Responsibility
phase16 の documentation/extraction は stable artifact を消費し、意味解析・証拠検証の再実行や公開入力の変更を行わない。
## Specification Items
spec §§23.5/24、architecture [13](../../architecture/ja/13.documentation_and_extraction.md)、internal [05](../../internal/ja/05.documentation_extraction.md) の消費側境界に従い、公開入力の読み取りと planning を扱う。
## Relevant Tests
mizar-test の既存実 registration fixture を published-input・export-index・native-source の構造的検証に用い、Doc lint guard は workspace 方針を扱う。元の fixture/expectation は変えない。
## Design And Source Inventory
英日 [reader](./artifact_reader.md)、[build-input owner](./doc_build.md)、[comments owner](./comments.md) が API を所有する。Cargo、`src/lib.rs`、`src/artifact_reader.rs`、`src/doc_build.rs`, `src/comments.rs`, `src/markdown.rs`、`tests/lint_policy.rs` が最初の crate を構成し、残る module inventory は [TODO](./todo.md) が保持する。
## Known Gaps And Drift
公開入力の読み取り、raw export index、optional hash 確認付き native Disk text/map は既存 Artifact/Session API を使う。planning は選択 publication を current snapshot に結び未解決 index 入力を保ち、native lexical input は既存 Lexer 前処理を使う。package Doc producer、実行投影、runtime readiness、phase15 統合は別の課題として残す。
## Coverage Audit Impact
chapter24 audit と SCA-002 に artifact-reader owner を登録し、rendering/extraction 全体の coverage は未完了に保つ。
