# Doc13 Render 前提条件の補完提案
正規言語: 英語。[英語正本](../en/render_prerequisites.md)。
状態: [Doc13 候補①](./render.md) の render/wire 提案は、採用済み Q3 href と下記の限定的な in-memory G1 identity、G2 destination、G3 coordinate 引渡しと限定 G4 opaque client と URL 方針診断の前提を除き非規範的である。schema 登録や page renderer 実装は認可しない。以下は内部の presentation/serialization 提案を定めるもので、他の所有者の意味と readiness は引き続き gate される。

## 採用済み G1 identity binding
Artifact の `project_frontend_identity` は元 source に束縛された不変の identity product を捕捉し、Driver は `PublishedSourceMetadata::identity()` に保持する。source/snapshot lineage は Driver が所有する。producer は native `src/<components>.miz` の成分を Session の既存 module identifier 検証規則と厳密な canonical module identity に照合する。FQN や任意の artifact 文字列から成分を作らない。非 ASCII native identifier を含む不正・非 lossless path は拒否する。
互換性 binding は verified-artifact `1.2` と `resolver-symbol-kind-v1` で、語彙は `predicate`, `functor`, `mode`, `attribute`, `structure`, `selector`, `registration`, `theorem`, `lemma`, `algorithm`, `scheme`, `template`, `synonym`, `antonym`, `redefinition`, `builtin`。未知 spelling や版はこの product を拒否する。汎用 Artifact reader の opaque kind 方針は維持する。保存済み Public/Reexported export を保持するが、Driver の意味的 export 生成を拡張しない。
`authenticate_doc_identities` は選択した current plan と明示的な有限 publication inventory を再検証し、module ごとに完全な product 一つと元 artifact/publication/source との厳密な binding を要求する。不変結果は module Ord と FQN/origin export 順を保持し、complete-empty module、重複 FQN、version、reexport、optional lock identity、厳密な表示文字列を失わない。欠落・重複・外部・stale・不一致 product は全体を拒否する。内部 owner 引渡しであり、提案 tuple/JSON/rendering や Doc13 全体の整合採用ではない。残る readiness 義務は gate されたまま。
Native Driver の lock/config commitment は owner-framed 表現を用いる。Doc4 の [認証済み native 経路](./doc_build.md#package-planning) は真正な Driver capture/publication 証拠を Doc10/G1 の再検証まで保持する。通常の raw 経路では従来どおり拒否する。真正な元 publication は明示的な dependency inventory でも利用できる。

## 採用済み G2 destination allocation
`allocate_doc_destinations` は認証済み G1 identity と Doc10 入力を消費し、module/publication/export の完全かつ厳密な coverage を要求する。Q1 version/module/専用 item path を生成して不変の対の引渡しを返す。`allocations()` は Doc9 module-page destination を保持し、`dedicated_item` は同じ厳密 export の専用 page、FQN fragment、検証済み optional alias を供給する。label 欠落・曖昧性や full id 衝突は product 全体を拒否する。
caller は生成 version root に束縛された完全な補助 page/section namespace を宣言する。生成・補助 path を予約 `index.html`、`search.json`、`cross-references.json`、`assets/` subtree と合わせ、暗黙 directory と ASCII 大小文字の spelling 衝突も検査する。勝者選択や suffix で衝突を修復しない。section coverage は既存 Doc10 validator の下で独立に保持し、従来の supplied-table interface の policy は維持する。
採用対象は限定的な G2 allocation 前提条件だけである。file を出力せず、renderer、wire/schema、source routing、後続 gate、publication の readiness を供給しない。

## 採用済み G3 source coordinates
`authenticate_doc_sources` は選択した current plan と明示的な有限 publication inventory を再検証し、Artifact が検証した元 projection を保持する。source binding は完全 module identity、publication hash、厳密な packaged relative source path と補足的な Session `hash_text(original)` を使う。正規化 source hash だけでは元 byte 座標を識別できない。legacy/null projection は unavailable のままとし、矛盾する publication/path/source/frame や map binding は拒否する。
不変 handoff は同じ projection に対して Q3→loaded→original と元 citation lexical→loaded→original の順序付き segment を合成する。map 交差処理は Session が所有し、Doc は consumer の境界と UTF-8 境界を検証する。独立に map できた segment は部分 coverage でも保持し、container、削除 comment、map 欠落の隙間を橋渡ししない。coverage は complete/incomplete/unavailable を区別する。Artifact occurrence span は loaded AST frame を保持し、`citation_ranges` は記述された lexical endpoint を復元して合成し、`lexical_ranges` は明示的な lexical segment を受け取る。citation ordinal、反復/自己 occurrence、endpoint/examination coverage は変更しない。
採用対象は限定的な G3 coordinate 前提条件だけである。reference 遭遇順/classification は Doc8/9、source-view/行 routing は Q3、劣化 summary は Q4/MT に残し、採用済み block-local recovery を保持する。Doc13 全体の整合採用、rendering、後続 gate は別途必要である。

## Adopted G4 Opaque Client Prerequisite
Doc11 Q6/Q7/Q12 と Doc13 Q6/Q11 の opaque 部分だけを [math runtime](./math.md) と [render transport](./render.md#adopted-opaque-math-transport) として採用する。実 Doc8 payload/順序/provenance、独立した accessible client failure、固定 local asset/設定に限定する。共有 build diagnostic の割当/発行は diagnostics が保持する。残る Q12 診断と検出・発行 witness、完全 template、残る math 依存、G5、整合 Doc13、schema/publication、Doc23/24、全 credit は未解決のままとする。

## Identity と allocation の引渡し
[Doc4](./doc_build.md#index-inputs-and-later-completion) の認証済み publication と完全 export inventory を、[Doc10 前提条件](./link_prerequisites.md) の producer/validation 義務に従って消費する。export visibility は Public と Reexported を含み、完全 identity ごとに一件を保持して、異なる identity の重複 FQN を統合しない。各 projection は検証済みの元 module/export と publication への束縛を保持しなければならない。
この提案 JSON だけに、module key `M = [package_id, package_version, lock_identity, module_components, edition, publication_hash]` と item key `I = [package_id, package_version, lock_identity, module_components, edition, origin_id, publication_hash]` を定義する。文字列は所有者の厳密な spelling を保持し、null は lock identity 不在のみ。version は Doc4 が必須とする保存文字列で、合成しない。hash は所有する Hash の小文字 hexadecimal encoding とし、interface/source hash ではない。module components は権威ある文字列の順序付き配列。既存 ModuleSummaryIdentity は module-path 文字列一つを保存し、採用済み G1 引渡しが認証済み lossless 構造化 path 束縛を供給する。wire の整合採用は別途必要であり、FQN 分割や区切りの推測を禁じる。これらの tuple は Artifact storage を改訂しない。
key 順はこの束縛を通じて既存の完全 ModuleSummaryIdentity Ord を比較し、item は続いて厳密 FQN、origin、最後に publication hash を比較する。符号化済み JSON text や解析した version で整列しない。`fqn`、`kind`、`signature` は VerifiedExport の厳密な fully_qualified_name、export_kind、rendered_signature 文字列を projection する。kind は opaque な所有者文字列で新 enum ではなく、採用済み G1 引渡しが実 producer vocabulary と version 束縛を所有する。未知 spelling を名前や statement から推測しない。利用可能な空 display string は空を保ち、unavailable metadata は空文字列ではない。
render allocation handoff は各 `M` の module page と各 `I` の module-entry/dedicated-item destination、厳密 FQN id、権威ある label、検証済み optional alias を供給する。論理 destination `D = [path_components, fragment]` は root-relative な権威ある path 成分と厳密 fragment 文字列を使う（null は fragment 不要時のみ）。`cross-references.json` を含む Q1/Q2 destination 集合全体を [page/anchor/section 規則](./link_prerequisites.md#validated-page-anchor-and-section-allocations) で検証し、identity の勝者選択や suffix による衝突修復をしない。束縛は一 item の両 destination を記録し、Doc9 の module-page 参照先を変えない。
search href は version output root から、page link は実際の包含 page からの相対として、採用済み Q3 の成分ごとの percent-UTF8 と完全 fragment encoding だけを用いて構成する。DOM id は厳密 FQN を属性 escape して保持する。例えば論理 `p/é%#.html` と fragment `m.é%#` は `p/%C3%A9%25%23.html#m.%C3%A9%25%23` となる。これは Q1 filesystem spelling と異なる。version-bound section destination には認証済み section inventory が必要で、source link には引き続き packaged source/maps と明示的に束縛した source-view/行規約が必要。ここでは source route や行を捏造しない。

## 検索 encoding と compatibility の提案
Q7 の envelope key 順 `format_version, package_version, items` と record key 順 `identity, fqn, kind, summary, signature, href` を保持する。format version は候補 JSON 整数 `1`、identity は `I`、package_version は選択済み保存文字列、kind/signature は上記 projection、href は専用 page と完全 FQN fragment。item は上記 identity 順で、未記述/reexported item を含む選択済み export 全件を含める。dependency は明示的な documented export 経由だけで入る。complete-empty export は `items:[]` と serialize する。
summary は `""` を含む Q4 の厳密な projection 文字列、または comment の既知不在だけを表す null。unavailable input は search readiness を止め、null や record 省略に変換しない。採用済み Doc8 raw-block conversion/map recovery は warning 付きで既定 build を継続する。劣化 summary は Q4/MT 共同 gate のままで、新たな Q8 producer refusal ではない。その projection 定義までは統合 search 実装の readiness はない。
search と補助 JSON は Q11 の BOM なし compact UTF-8、宣言した key 順、不要 whitespace なし、末尾一 LF を使う。quote と backslash、および全 U+0000–001F を小文字 `\u00hh` で escape し、他 Unicode は正規化せず literal とし `/` を escape しない。重複/未知 key、不正 shape/type、不正 UTF-8、未対応 format version は incompatible として拒否し、coerce や部分 record の消費をしない。以下の ordinal/offset は browser number の切捨てを避けるため canonical なゼロ埋めなし十進 u64 文字列とする。null は明示した意味だけを持ち、wildcard identity ではない。
version 1 は正確にこの field と shape を持つ。wire shape、値の解釈、kind vocabulary 束縛、順序の変更には別途レビュー済み compatibility/version 判断が必要。この提案は schema identifier を予約しない。Q9 の client matching/順序は変えず、load/parse incompatibility は空 match 集合ではなく unavailable と表示する。Q11 の renderer/template/toolchain と pinned asset identity はこれらの wire record 外の再現性入力のまま。

## Cross-reference と UsedBy serialization の提案
選択済み version root の候補 `cross-references.json` は key を `format_version, package_version, references, citations, used_by, coverage` の順とし、同じ version/byte/compatibility 規則を使う。search および opt-in machine-readable DocIndex とは分離する。認証済み Doc9 resolution/coverage 結果を表し、参照解決や direct-by producer の捏造をしない。
reference record の key 順は `subject, form, reference, state, targets, routes, destinations, provenance`。subject は `[M, target]` で、target は当該 module に束縛された `["module"]` または `["item", origin_id, fqn]`。form は `code|explicit|see`、reference は `[raw, interpreted]` で interpreted の null は unavailable 時だけ。state は `resolved|unresolved|ambiguous|incomplete` とし、Doc9 の結果を再計算せず保持する。通常 URL link は semantic edge ではない。unresolved や同位置のものも含め権威ある occurrence を全て保持し、conversion 失敗 block の occurrence は捏造しない。
target key は `["item", I]` または `["section", inventory_publication_hash, specification_version, section_id]` で、section key は version-bound inventory の認証済み publication 束縛を必要とする。targets は所有者が認証した参照 class だけを含み、item candidate は item identity 順、section candidate は厳密な version、id、publication の文字列順とする。module target と class 混在配列は無効。classification 不在は所有者の unresolved handoff を保持し、target を推測しない。既知 candidate は重複させない。resolved は target 一つ、unresolved はゼロ、ambiguous は複数とし、incomplete は一意性を意味せず既知 candidate を保持できる。routes は `[target_key, kind, position, endpoint_M]` で `current|import|closure` を使い、position は権威ある import ordinal 以外 null。[共有 link route 順序](../../mizar-diagnostics/en/documentation_links.md#structured-identity-and-details) を適用し、循環 route 探索はせず、section target は module-query route を持たない。destinations は検証済み既知 candidate ごとに一つの `[target_key, D]` を targets 順で並べ、target/destination row の重複は無効とする。allocation 欠落は incompleteness を保持し、href 推測や active ambiguous link にしない。
reference provenance の key 順は `block, occurrence, logical_range, mapping, segments`。block/occurrence は元のゼロ始まり source 順 ordinal を保持し、logical_range は Doc8 extracted-block byte 座標の `[start,end]`。mapping は `complete|incomplete|unavailable`。segments は元の遭遇順で `[source_binding, start, end]` を保持し、source_binding は source/map producer が認証した `[M, packaged_relative_path, source_content_hash]`、offset は元の UTF-8 byte 座標の半開区間とする。非連続 segment を橋渡ししない。unavailable mapping は空 segment 配列とし、ゼロ範囲を捏造しない。独立に map できた segment は incomplete map でも保持する。source 順 ordinal や座標束縛の欠落は producer gate のままで、serialization は出力列挙から推測しない。
reference は subject の module/item 順（module subject が item より先）、block ordinal、occurrence ordinal、最後に記載順の form で整列する。producer は反復/同範囲 occurrence を含む元の論理遭遇順に ordinal を束縛しなければならず、reference を重複除去しない。mapped offset は provenance であり整列の代替ではない。論理 reference range は必須のまま。unavailable conversion view は Doc8 recovery で扱い、reference record を捏造しない。
citation record の key 順は `citing, cited, by_ordinal, target_ordinal, provenance`。endpoint は item key とし、[Artifact 所有の元 ordinal](./link_prerequisites.md#artifact-owned-direct-by-producer) を使う。cited が null になるのは unmapped endpoint だけで、その occurrence を保持し coverage を incomplete とする。citation provenance は上記同様 `mapping, segments` を使い、map 不在でも by/target ordinal が構文を識別する。citing identity、数値としての by ordinal、target ordinal 順で整列し、反復/自己/cross-package citation を保持する。`@see`、Markdown link、used_axioms はこれらの record を供給しない。
coverage の key 順は `closure_state, closure, citation_state, examined`。state は `unavailable|incomplete|complete`。closure は module/publication 順の `M` の明示的有限配列。examined は producer が列挙した theorem の `[I, parts]` を item 順に並べ、parts は実際に調査済みの `body|proof` をこの順で重複なく記録する。[既存 coverage 義務](./link_prerequisites.md#artifact-owned-direct-by-producer) を projection するもので、空 vector だけでは complete coverage にならない。closure と examination の state は独立とし、endpoint 欠落/unmapped から complete な citation_state を得ない。
used_by は producer が分類した選択済み theorem ごとに一 record とし、key 順は `target, state, citing`。record は target の item identity 順に整列する。state は coverage state のいずれかが unavailable なら unavailable、それ以外でいずれかが incomplete なら incomplete、その他は complete。citing は Doc9 display 順の重複なし reverse-mapped direct citing item key とし、occurrence record は別に lossless に保持する。complete-empty list には完全な認証済み closure/examined coverage と incoming direct edge 不在が必要。incomplete list は既知 edge を保持するが明示 unavailable と表示し、網羅的としない。completeness はその closure に対するもので、全外部 dependent に対してではない。

## 順序付き readiness gate
各 gate は独立に検査できる所有者 evidence を必要とし、文章による定義や screening は合格 witness ではない。
1. 限定的な [G1 identity 引渡し](#採用済み-g1-identity-binding) は、完全 export に対する kind/version 互換性と認証済み lossless module 成分を採用する。必要な Doc13 ① render/wire interface の整合採用は別途行い、採用済み Doc8/9 と Q3 href を保持する。この前提条件だけでは Doc13 は ready にならない。
2. Doc10 import/closure/direct-by 入力と render page/id/alias/section allocation を供給・認証する。complete-empty、incomplete、refusal state、反復/自己/cross-package citation、予約名/file-directory/case 衝突、label 不在、非 ASCII href を実証する。lower-reader integrity/schema/currentness failure は error のまま。
3. 限定的な [source-coordinate 引渡し](#採用済み-g3-source-coordinates) は認証済みの元 byte segment を供給する。元順序の reference 遭遇/classification は Doc8/9 の作業に残し、source-view/行 routing は別途定義する。map 欠落時は synthetic offset なしで provenance を保持し、source 欠落は既存 unavailable/warning 動作を保つ。採用済み block-local recovery を変えず Q4/MT 劣化 summary を解決する。
4. diagnostic owner と別途 Q12 render 診断、location、overlap/precedence、profile を定義・採用する。共有 link 診断は render warning を割り当てず、下記の限定 URL 前提が rejected-URL 一種類のみを割り当てる。Render が [完全 page template 定義](../en/render.md#complete-page-template-definition)を所有するが、定義は実行 template witness を供給しない。残る Doc11/math・owner-slot 表示依存、具体的 style/search bytes、pinned immutable manifest を別途解消する。warning promotion は documentation だけに影響し、proof/extraction acceptance には影響しない。
5. その後に限り、採用済み interface と完全入力に対して Doc14/15 実装を dispatch し、上記 wire shape と canonical byte の positive/refusal/incompatibility witness を備える。Doc23 atomic publication、Doc24 executable determinism、optional DocIndex schema/compatibility は個別 gate のままで、この補完では一つも解消しない。

## 採用済み G4 URL 方針診断の前提
限定 [Q5 出力方針](./render.md#採用済み-htmlurl-出力方針) と [共有 URL 診断](../../mizar-diagnostics/ja/documentation_urls.md) を採用する。実 Doc8 destination、供給 Doc10 分類との binding、限定 safe output と W0415 検出・発行を採用する。全体 rendering、template 実装 witness、具体的 style/search bytes と pinned manifest、残る Q12/source/readiness 診断、symbolic math、他の G4/G5 は gate 内に残る。
