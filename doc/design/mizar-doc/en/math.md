# Doc11 Math-Model Definition Proposal
Canonical language: English; [Japanese companion](../ja/math.md).
Status: non-normative proposal. All Doc11-local Q1–Q12 below are UNSELECTED; neither alternative authorizes implementation or normative adoption. These identifiers are independent of approved [Doc4 decisions](./doc_build.md#owner-q-decisions), unselected [Doc8 Q9–Q18](./commonmark.md#unselected-owner-q-decisions) and [Doc9 Q1–Q10](./links.md#unselected-owner-q-decisions); none changes here.

## Authority And Fixed Boundary
Spec [21.3](../../../spec/en/21.source_code_annotation_and_atp.md#213-latex-expression-annotations), [24.3](../../../spec/en/24.documentation_generation.md#243-mathematical-formula-rendering) and [24.4](../../../spec/en/24.documentation_generation.md#244-html-output) fix annotation priority, default translations, numbering and client-side KaTeX. Architecture13 [Step3](../../architecture/en/13.documentation_and_extraction.md#step-3-resolve-links-and-render-math), [determinism](../../architecture/en/13.documentation_and_extraction.md#outputs-are-deterministic) and internal05 [artifact inputs](../../internal/en/05.documentation_extraction.md#artifact-inputs) bound consumer ownership. This definition depends on bounded approved [Doc4 inputs](./doc_build.md#index-inputs-and-later-completion), not Doc8 parsing/adoption.
Annotations on functor, predicate, mode and attribute definitions supply preferred notation at every symbol occurrence in theorem statements, type signatures and formula displays. An unannotated symbol retains its verbatim name in monospace; surrounding formula structure uses all eleven exact default translation rows in spec24.3. An annotation overrides automatic translation for that occurrence, not unrelated formula structure. Item pages also show mathematical requires/ensures clauses under spec24.4; comment tags are not inferred formal contracts.
Spec24.3 fixes inline `$formula$`, own-line `$$formula$$` centred displays, automatic display-equation numbers in theorem statements, `(chapter.section.item)` with a sequential display-equation index within the item's documentation page, hyperlinked numbers and the documented `$$\text{see }(24.3.1)$$` reference form. Recognition, delimiter eligibility, Markdown interaction and malformed-delimiter warnings remain Doc8 choices; this proposal consumes already classified occurrences only.
The generator never validates LaTeX syntax during the build. Invalid LaTeX passes unchanged to the rendering engine and may yield an output rendering error. Static HTML uses client-side KaTeX, with local library files under `assets/katex/` and no server-side processing. A proposed repertoire is not a generator allowlist or a new language restriction.

## Candidate Inputs And Formula Strategy
The following paragraphs describe the combined candidate ① of Q1–Q12 for owner review only. Doc4 retains complete package/version/lock/module/edition identity, selected publication hash, exports/origins and stored projections when present. Reader integrity/schema/binding refusals remain refusals. Raw signatures, source ranges or proof evidence do not establish structured renderable formulas, complete annotation metadata or resolved symbol occurrences.
Candidate ① requires an Artifact-owner-defined, publication-bound presentation projection for symbol annotations, parameter/binder identities, resolved occurrences and the structure of signatures, statements and formal contracts. It must distinguish a genuinely absent annotation from unavailable metadata and bind each referenced symbol to its defining publication, including dependencies. Missing, incomplete, available-empty and conflicting records stay distinct; no source re-analysis, signature parsing, name-based overload resolution or fabricated empty projection is permitted. This proposes no artifact field/schema or producer implementation; those require separate approval.
The parser-neutral comment handoff retains raw LaTeX payload, inline/display classification, source-ordered occurrence identity, full attached-target provenance and mapped source segments. The payload excludes recognized delimiter tokens but retains internal spelling, whitespace and line endings; no TeX trim, entity decoding or macro expansion occurs here. How the future parser obtains that payload remains Doc8's unselected contract, including raw versus interpreted text. An empty recognized payload is distinct from no occurrence, and supplies no additional Doc11 build-time syntax warning.
Candidate ① inserts each stored annotation as an opaque TeX fragment for the corresponding resolved occurrence, without scanning its characters as variable placeholders or recursively expanding symbol names inside it. This is a concrete literal-insertion alternative, not an adopted argument-substitution model: `n!` on Factorial and `\gcd(a,b)` on Gcd leave renamed actual arguments, nested calls and binder capture unresolved under Q2. The spec's example theorem must remain satisfiable; if literal insertion cannot satisfy intended annotation use, adoption awaits owner clarification rather than silently inventing template syntax or changing the example.
For complete unannotated structure, candidate ① traverses the producer's ordered expression/binder children and applies precisely the spec24.3 table: arithmetic, division, exponentiation, modulo, comparisons, membership, inclusion and universal/existential quantification. TeX braces preserve operand grouping; explicit mathematical parentheses preserve tree grouping where required. Preserve operand order and binder identity; perform no algebraic simplification, variable renaming or logical normalization. Use verbatim monospace symbol names at unannotated leaves, with TeX escaping solely to preserve their visible spelling. Exact grouping and identifier-encoding rules remain Q3/Q4, so no new operator translation is implicitly selected.
Structures beyond the table, unsupported projection variants and unavailable dependent notation are readiness gaps, never invented formulas or evidence of invalid mathematics. Candidate ① retains any authoritative display text as escaped plain text marked unavailable for mathematical rendering, with a proposed presentation diagnostic. Without such text it exposes unavailability without inventing a statement. An explicitly empty annotation is passed as an empty payload, never silently replaced by the symbol name; incomplete annotation metadata cannot be treated as a known absent annotation. Q5 gates the degradation policy and its publication scope.

## Candidate KaTeX And Numbering Handoff
The proposed generator repertoire is exactly the table's TeX constructs plus grouping, parentheses and the monospace/text escaping needed to preserve names and references. Authored annotations/comment payloads remain unrestricted strings passed through; actual supported commands and unsupported/invalid-command behaviour belong to the selected KaTeX runtime, not a second generator TeX parser. No build-time KaTeX execution, TeX compilation, syntax preflight, command rejection or repair is introduced.
Candidate ① bundles a single immutable KaTeX release with its matching JS/CSS/fonts, an explicit option/macro manifest and asset digests. Q6 requires the exact release, repertoire, option values, resource limits and provenance to be proposed before adoption; none is pinned or installed here. Candidate ① disables trusted HTML/URL commands and cross-formula mutable macro state, isolates each occurrence and requests an escaped visible rendering-error marker retaining the original payload when client rendering fails. The exact KaTeX options, safe DOM transport and fallback markup remain joint math/render-owner gates under Q6/Q7, not a claimed security implementation or a narrowed LaTeX input grammar.
Candidate ① gives every theorem-statement display occurrence a stable page-local source/structure ordinal, including repeated identical formulas; inline formulas do not consume the counter. Comment displays and non-theorem displays remain displays without automatic numbers in this candidate. Chapter/section values must come from an explicit owner-supplied allocation bound to the page/publication, never from FQN splitting or example constants. Missing allocations block numbering readiness rather than emitting a fabricated number. Q8/Q9 retain scope/allocation alternatives while preserving the required theorem numbering and format.
Candidate ① recognizes formula-number references only from a future parser's explicit math-reference classification, not a TeX substring scan. A publication-bound number-to-display registry yields the numbered target; duplicate numbers or missing targets remain unresolved, never first-match links. Q10 gates that classification, ambiguity/degradation policy and reference namespace; Doc8 still owns recognition, and Doc9/Doc13–15 must define page/anchor allocation and href encoding before emission. No Doc9 page/anchor alternative is adopted here.

## Determinism And Adoption
Candidate ① keeps Doc4 full-identity/module/FQN ordering and semantic child/source order separately. Identical bound inputs, lock/toolchain/schema context, options, engine assets and allocation registries yield identical math payloads, numbers and generated bytes, independent of worker/enumeration order; duplicates retain distinct stable occurrences. No clock, network lookup, random id or ambient macro state supplies output. Render-time failure is not a build diagnostic, and absent assets/configuration are deployment/readiness failures rather than invalid-LaTeX findings.
Presentation drafts follow existing stage/file/range diagnostic ordering with stable publication/target/occurrence ties and preserved mapped segments. Missing maps use available authoritative provenance without fabricated contiguous spans. Internal05's [diagnostic owner](../../internal/en/05.documentation_extraction.md#diagnostics) must define meanings, locations, ordering and profile behaviour before implementation; W0400–W0404 remain attachment warnings. Only an explicit documentation profile may promote documentation warnings; phase0–15 verification, proof status and extraction acceptance never change.
Doc11 remains a proposal. Doc12 needs coherent owner adoption, approved complete input producers, exact formula/annotation and KaTeX definitions, numbering/reference interfaces and shared diagnostics; it also retains its independent Doc8 dependency. No code, schema, diagnostic allocation, normative adoption, Doc8/Doc9 decision, coverage/owner credit or broader Doc4/5/crate completion is claimed.
