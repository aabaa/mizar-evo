# Crate Plan: mizar-doc
Canonical language: English; [Japanese companion](../ja/00.crate_plan.md).
## Responsibility
Phase-16 documentation/extraction consumes stable artifacts; it never re-runs semantics, checks evidence or mutates publication inputs.
## Specification Items
Spec §§23.5/24; architecture [13](../../architecture/en/13.documentation_and_extraction.md) and internal [05](../../internal/en/05.documentation_extraction.md) define consumer ownership for published-input loading and planning.
## Relevant Tests
Existing genuine registration fixtures feed published-input, export-index and native-source families in mizar-test; the Doc lint guard covers workspace policy. Original fixtures/expectations remain unchanged.
## Design And Source Inventory
The paired [reader](./artifact_reader.md), [build-input owner](./doc_build.md) and [comments owner](./comments.md) own these APIs. Cargo, `src/lib.rs`, `src/artifact_reader.rs`, `src/doc_build.rs`, `src/comments.rs` and `tests/lint_policy.rs` form the initial crate; the [TODO](./todo.md) retains the remaining module inventory.
## Known Gaps And Drift
Published-input loading, raw export indexing and optional hash-checked native Disk text/maps use existing Artifact/Session APIs. Planning binds selected publications to a current snapshot and retains unresolved index inputs; native lexical input uses existing Lexer preprocessing. Package Doc production, executable projections, runtime readiness and phase-15 integration remain separate.
## Coverage Audit Impact
Register the artifact-reader owner in the chapter-24 audit and SCA-002; general rendering/extraction coverage remains open.
