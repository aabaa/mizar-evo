# Doc10 Producer And Allocation Prerequisites Proposal
Canonical language: English; [Japanese companion](../ja/link_prerequisites.md).
Status: non-normative proposal only. [Spec24.2](../../../spec/en/24.documentation_generation.md#242-cross-referencing-and-hyperlinks) fixes Doc9 and the Doc13 href interface; this proposal neither reopens them nor supplies implementation readiness. [Shared link diagnostics](../../mizar-diagnostics/en/documentation_links.md) own diagnostic details.

## Authenticated Import And Dependency Inputs
Proposed producer responsibility belongs at the Session/Artifact publication boundary that retains resolved import selection; the Doc consumer never selects packages/versions or reconstructs imports. The producer supplies each source module's full identity and publication hash, its semantic-order import vector of bound module/publication identities, and explicit coverage: unavailable, incomplete or complete (including complete-empty). Storage sorting and dependency interface hashes cannot establish that vector. [Doc4 inputs](./doc_build.md#index-inputs-and-later-completion) remain unchanged.
The producer also supplies an explicit finite documentation-closure inventory rooted at the selected package publication: package tuples, selected publication hashes, index locations and each index's module/export coverage. Completeness names the covered namespace and every required dependency edge; an omitted reference is not evidence of absence. Cycles are permitted only inside this finite inventory and do not authorize discovery. There is no source or network fallback.
Before use, the index consumer authenticates each referenced index through the existing validating reader and checks schema compatibility, publication/package binding and full module/export identities against validated publications. Each import endpoint must bind to that authenticated inventory. A path, FQN, canonical ordering or interface hash alone is insufficient. Unsupported schema, integrity, stale/currentness or binding failures keep their lower-reader refusal; missing coverage stays unavailable/incomplete.
The handoff retains unavailable versus incomplete versus explicitly complete-empty for every queried namespace. A unique current-module match remains definitive without imports; otherwise unqualified success requires complete ordered imports and required target inputs. FQN searches use only the bound closure. Duplicate routes retain provenance while collapsing identical full targets; distinct targets never merge. No serialized field, schema revision or public API is selected here.

## Artifact-Owned Direct-By Producer
The Artifact owner must project direct syntactic theorem-to-theorem `by` citations from the original authoritative compilation/publication process, bound to the citing publication and the same complete export identities as the index. Existing [artifact evidence](../../../spec/en/23.package_management_and_build_system.md#2351-mizirjson-artifact-format), exports and `used_axioms` alone do not supply this graph; the Doc consumer cannot recover it from source, names or proof evidence.
Each proposed citation record retains citing and cited full module/publication/export identity and an occurrence identity: citing theorem, preserved `by` occurrence ordinal and cited-target ordinal within that occurrence, both in original encounter order. Retain authenticated source provenance/maps when available, without manufacturing ranges. Repeated and self-citations remain records; cross-package endpoints must authenticate against the supplied closure. Ordinals distinguish syntax occurrences, not proof/evidence dependencies.
Coverage explicitly enumerates which theorem bodies/proofs were examined within the selected finite closure and whether that scope is complete, incomplete or unavailable. Complete-empty requires authoritative complete coverage with no direct edges, never merely an empty record vector. An unmapped endpoint makes the affected coverage incomplete; keep its occurrence provenance rather than silently dropping it. Missing/unexamined theorems or packages cannot support an exhaustive UsedBy claim.
The consumer reverses only mapped direct edges and applies spec24.2's display deduplication/order while retaining occurrence order separately. Completeness is relative to the explicitly declared documentation closure, never all possible external dependents. Producer projection, authentication, schema compatibility and coverage validation require separate owner work; this proposal introduces no artifact field or proof-acceptance change.

## Validated Page, Anchor And Section Allocations
The render allocation owner supplies a table bound to the selected output root and full module/publication identities, plus item identities, exact authoritative labels/FQN ids and optional aliases. Before resolving hrefs, the Doc consumer requires evidence that the complete supplied destination set has no page-path collisions and no distinct targets sharing one full id on a page. Unavailable labels block item-anchor readiness; duplicate full ids block that page. No identity winner, suffix, slug or guessed path repairs a collision.
Validation checks that paths are relative to the declared root, destinations cover the queried targets, exact FQN fragments agree with the bound exports, and optional aliases satisfy spec24.2's full/section/alias collision rules. Suppress an unsafe optional alias without changing the full anchor. Directory spelling, filesystem case policy, dedicated-item/source routes and output publication remain Doc13/Doc23 decisions; this proposal does not adopt their candidates.
The generated-specification producer supplies an explicit version-bound section inventory with logical section ids and page destinations; the allocation validator checks version binding, uniqueness and destination/fragment existence. A known complete index with no matching section is unresolved; unavailable/partial index inputs cannot establish a complete search. Absent/unknown sections never become module anchors. No section grammar beyond the adopted interface is added.
Validation hands off logical paths/fragments, never guessed or pre-normalized hrefs. Apply only the adopted [Doc13 href interface](./render.md#candidate-destinations-and-page-content): percent-encode UTF-8 per path segment/full fragment while preserving exact DOM ids. Allocation completeness and href encoding are separate obligations; valid encoding cannot authenticate a missing destination.

## Ordered Readiness Gates And Decisions
Resolve these prerequisite families in order; adoption of this proposal alone cannot discharge any producer or validation gate:
1. Separately adopt the necessary interface definitions, then supply/authenticate ordered imports and finite dependency indexes, with positive, complete-empty, incomplete and refusal witnesses.
2. Supply the Artifact-owned direct-by projection and scope/endpoint validation, witnessing repeated/self/cross-package edges, missing coverage and complete-empty coverage without evidence fallback.
3. Supply and validate page/full-anchor/alias/section allocations against those identities, witnessing collisions, missing labels, version mismatch and the adopted non-ASCII/percent/hash href encoding.
4. Separately adopt and allocate the [exact shared diagnostics](../../mizar-diagnostics/en/documentation_links.md), including location support and profile handling; witness coincident/discontiguous/unmapped occurrences and scope-only incompleteness.
5. Only a separately dispatched Doc10 readiness/implementation unit may integrate those authenticated inputs and adopted diagnostics. Doc13 rendering, schema/publication work and coverage/owner/milestone credit remain outside this definition.
Screened proposal decisions: publication-bound producer placement, explicit coverage inventories, citation occurrence ordinals and validation handoffs are selected internal/provenance choices. No new language-specification choice is needed or left unselected here. Numeric diagnostics and adoption metadata remain explicitly UNSELECTED in their owner; no code/schema allocation is made.
