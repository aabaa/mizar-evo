# Doc10 Adopted Producer And Allocation Prerequisite Interfaces
Canonical language: English; [Japanese companion](../ja/link_prerequisites.md).
Status: adopted prerequisite interfaces; [gate-1 import/closure inputs](#authenticated-ordered-imports-handoff) are supplied separately. [gate-2 direct-by inputs](#authenticated-direct-by-handoff) are supplied separately; validated allocations, diagnostics and resolver integration remain gated. [Spec24.2](../../../spec/en/24.documentation_generation.md#242-cross-referencing-and-hyperlinks) fixes Doc9 and the Doc13 href interface; this adoption does not reopen them. [Shared link diagnostics](../../mizar-diagnostics/en/documentation_links.md) remain a separate, unadopted and unallocated proposal.

## Authenticated Import And Dependency Inputs
Producer responsibility belongs at the Session/Artifact publication boundary that retains resolved import selection; the Doc consumer never selects packages/versions or reconstructs imports. The producer supplies each source module's full identity and publication hash, its semantic-order import vector of bound module/publication identities, and explicit coverage: unavailable, incomplete or complete (including complete-empty). Storage sorting and dependency interface hashes cannot establish that vector. [Doc4 inputs](./doc_build.md#index-inputs-and-later-completion) remain unchanged.
The producer also supplies an explicit finite documentation-closure inventory rooted at the selected package publication: package tuples, selected publication hashes, index locations and each index's module/export coverage. Completeness names the covered namespace and every required dependency edge; an omitted reference is not evidence of absence. Cycles are permitted only inside this finite inventory and do not authorize discovery. There is no source or network fallback.
Before use, the index consumer authenticates each referenced index through the existing validating reader and checks schema compatibility, publication/package binding and full module/export identities against validated publications. Each import endpoint must bind to that authenticated inventory. A path, FQN, canonical ordering or interface hash alone is insufficient. Unsupported schema, integrity, stale/currentness or binding failures keep their lower-reader refusal; missing coverage stays unavailable/incomplete.
The handoff retains unavailable versus incomplete versus explicitly complete-empty for every queried namespace. A unique current-module match remains definitive without imports; otherwise unqualified success requires complete ordered imports and required target inputs. FQN searches use only the bound closure. Duplicate routes retain provenance while collapsing identical full targets; distinct targets never merge. No serialized field or schema revision is selected here.

### Authenticated Ordered Imports Handoff
`authenticate_doc_imports` is a separate in-memory gate-1 handoff; raw request `import_order` and `dependency_indexes` retain their existing unauthenticated meaning. It revalidates the root plan against the current registry/request/workspace and reads only the explicitly supplied finite `(package, publication_hash, artifact_root)` inventory through the existing export/summary readers. These roots locate validated publication indexes, not a new serialized DocIndex format.
`AuthenticatedDocImports` privately retains the selected publications, complete full-identity export/summary inventories and genuine `PublishedImportView` producers. Source module/publication/hash and original resolver provenance must agree with the validated publication. Imported targets bind to the inventory's full identities and publication hashes; ambiguous publication binding cannot choose a winner.
`DocImportCoverage` is an extensible `#[non_exhaustive]` unavailable/incomplete/complete state. Per-module coverage and finite-closure coverage remain separate. Missing producers, summaries or endpoints cannot become complete-empty; complete-empty requires a genuine complete producer and checked finite dependency scope.
No link lookup, direct-by/UsedBy, allocation, diagnostic or render integration follows from this API; [later readiness gates](#ordered-readiness-gates-and-decisions) remain open.

## Artifact-Owned Direct-By Producer
The Artifact owner must project direct syntactic theorem-to-theorem `by` citations from the original authoritative compilation/publication process, bound to the citing publication and the same complete export identities as the index. Existing [artifact evidence](../../../spec/en/23.package_management_and_build_system.md#2351-mizirjson-artifact-format), exports and `used_axioms` alone do not supply this graph; the Doc consumer cannot recover it from source, names or proof evidence.
Each citation record retains citing and cited full module/publication/export identity and an occurrence identity: citing theorem, preserved `by` occurrence ordinal and cited-target ordinal within that occurrence, both in original encounter order. Retain authenticated source provenance/maps when available, without manufacturing ranges. Repeated and self-citations remain records; cross-package endpoints must authenticate against the supplied closure. Ordinals distinguish syntax occurrences, not proof/evidence dependencies.
Coverage explicitly enumerates which theorem bodies/proofs were examined within the selected finite closure and whether that scope is complete, incomplete or unavailable. Complete-empty requires authoritative complete coverage with no direct edges, never merely an empty record vector. An unmapped endpoint makes the affected coverage incomplete; keep its occurrence provenance rather than silently dropping it. Missing/unexamined theorems or packages cannot support an exhaustive UsedBy claim.
The consumer reverses only mapped direct edges and applies spec24.2's display deduplication/order while retaining occurrence order separately. Completeness is relative to the explicitly declared documentation closure, never all possible external dependents. Producer projection, authentication, schema compatibility and coverage validation require separate owner work; interface adoption introduces no artifact field or proof-acceptance change.

### Authenticated Direct-By Handoff
`authenticate_doc_direct_by` consumes a current `AuthenticatedDocImports` and original [Artifact projections](../../mizar-artifact/en/verified_artifact.md#in-memory-direct-by-projection), without reading source or discovering dependencies. `AuthenticatedDocDirectBy` retains those immutable producers and their original occurrences/examinations; it supplies no reversal, presentation or link resolution.
Validation binds each source module/publication/hash to the selected manifest and its captured SourceId to any available authenticated import producer, and each examined/citing/mapped cited theorem to its exact stored export identity. Duplicate or foreign source producers and contradictory known endpoint bindings refuse. A missing cited module keeps its occurrence incomplete. Complete module coverage also requires examination of every local public theorem export; reexports add no local body. Missing producers remain unavailable, and omitted scope or unmapped owners/targets cannot become complete-empty.
Per-module and aggregate citation coverage reuse `DocImportCoverage`, independently of `closure_coverage()` on the finite import handoff. Callers must retain both states; complete citation examination of supplied modules cannot establish that missing dependency inputs were covered. The projection has no serialized schema, so existing validating-reader refusals remain at gate 1. Driver's genuine capture retains original compilation syntax and available semantic mappings; a structurally supplied callback alone is not a genuine producer witness.

## Validated Page, Anchor And Section Allocations
The render allocation owner supplies a table bound to the selected output root and full module/publication identities, plus item identities, exact authoritative labels/FQN ids and optional aliases. Before resolving hrefs, the Doc consumer requires evidence that the complete supplied destination set has no page-path collisions and no distinct targets sharing one full id on a page. Unavailable labels block item-anchor readiness; duplicate full ids block that page. No identity winner, suffix, slug or guessed path repairs a collision.
Validation checks that paths are relative to the declared root, destinations cover the queried targets, exact FQN fragments agree with the bound exports, and optional aliases satisfy spec24.2's full/section/alias collision rules. Suppress an unsafe optional alias without changing the full anchor. Directory spelling, filesystem case policy, dedicated-item/source routes and output publication remain Doc13/Doc23 decisions; this interface adoption does not adopt their candidates.
The generated-specification producer supplies an explicit version-bound section inventory with logical section ids and page destinations; the allocation validator checks version binding, uniqueness and destination/fragment existence. A known complete index with no matching section is unresolved; unavailable/partial index inputs cannot establish a complete search. Absent/unknown sections never become module anchors. No section grammar beyond the adopted interface is added.
Validation hands off logical paths/fragments, never guessed or pre-normalized hrefs. Apply only the adopted [Doc13 href interface](./render.md#candidate-destinations-and-page-content): percent-encode UTF-8 per path segment/full fragment while preserving exact DOM ids. Allocation completeness and href encoding are separate obligations; valid encoding cannot authenticate a missing destination.

## Ordered Readiness Gates And Decisions
The prerequisite interface definitions above are adopted. Resolve the remaining families in order; interface adoption alone cannot discharge any producer, authentication, coverage, allocation, diagnostic or implementation gate:
1. The [authenticated import/closure handoff](#authenticated-ordered-imports-handoff) supplies ordered imports and finite dependency indexes with explicit coverage and refusal validation. This discharges only this input gate; no later gate is discharged.
2. The [authenticated direct-by handoff](#authenticated-direct-by-handoff) supplies Artifact-owned projection and finite scope/endpoint validation, preserving repeated/self/cross-package occurrences and unavailable/incomplete/complete-empty coverage without evidence fallback. This discharges only this producer gate; all following gates remain open.
3. Supply and validate page/full-anchor/alias/section allocations against those identities, witnessing collisions, missing labels, version mismatch and the adopted non-ASCII/percent/hash href encoding.
4. Separately adopt and allocate the [exact shared diagnostics](../../mizar-diagnostics/en/documentation_links.md), including location support and profile handling; witness coincident/discontiguous/unmapped occurrences and scope-only incompleteness.
5. Only a separately dispatched Doc10 readiness/implementation unit may integrate those authenticated inputs and adopted diagnostics. Doc13 rendering, schema/publication work and coverage/owner/milestone credit remain outside this definition.
Adopted internal/provenance decisions: publication-bound producer placement, explicit coverage inventories, citation occurrence ordinals and validation handoffs are retained from the completed proposal. No new language-specification choice is needed or left unselected here. Numeric diagnostics and diagnostic adoption metadata remain explicitly UNSELECTED in their owner; no code/schema allocation is made. Doc9’s historical ② alternatives remain inactive.
