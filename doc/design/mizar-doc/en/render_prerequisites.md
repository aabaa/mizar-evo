# Doc13 Render Prerequisite Completion Proposal
Canonical language: English; [Japanese companion](../ja/render_prerequisites.md).
Status: [Doc13 candidate ①](./render.md) remains a non-normative render/wire proposal except for the adopted Q3 href and bounded in-memory G1 identity, G2 destination and G3 coordinate/source-view handoffs and the bounded G4 opaque client and URL-policy diagnostic prerequisites and supplied-search reader below. No registered schema or complete page producer is authorized. The definitions below select internal presentation/serialization proposals; other owners' semantics and readiness remain gated.

## Adopted G1 Identity Binding
`project_frontend_identity` in Artifact captures an immutable original-source identity product; Driver retains it through `PublishedSourceMetadata::identity()`. Source/snapshot lineage stays with Driver. The producer cross-checks native `src/<components>.miz` components against Session's existing validated module identifier grammar and exact canonical module identity; no FQN or arbitrary artifact string supplies components. Invalid/non-lossless paths, including non-ASCII native identifiers, refuse.
The compatibility binding is verified-artifact `1.2` with `resolver-symbol-kind-v1`: `predicate`, `functor`, `mode`, `attribute`, `structure`, `selector`, `registration`, `theorem`, `lemma`, `algorithm`, `scheme`, `template`, `synonym`, `antonym`, `redefinition`, `builtin`. Unknown spellings or versions refuse this product; generic Artifact readers retain their opaque kind policy. Stored Public/Reexported exports are preserved; this does not extend Driver's semantic export production.
`authenticate_doc_identities` revalidates the selected current plan and explicit finite publication inventory, then requires exactly one complete product per module and exact original artifact/publication/source binding. The immutable result keeps module Ord and FQN/origin export order, including complete-empty modules, duplicate FQNs, versions, reexports, optional lock identity and exact display strings. Missing/duplicate/foreign/stale/mismatched products refuse as a whole. These are internal owner handoffs, not adoption of the proposed tuples, JSON, rendering or coherent Doc13 interfaces; Remaining readiness obligations stay gated.
Native Driver lock/config commitments use their owner-framed representation. Doc4's [authenticated native route](./doc_build.md#package-planning) retains genuine Driver capture/publication evidence through Doc10/G1 revalidation; the ordinary raw route still refuses those commitments. Genuine original publications also remain usable in explicit dependency inventories.

## Adopted G2 Destination Allocation
`allocate_doc_destinations` consumes authenticated G1 identities and Doc10 inputs with exact complete module/publication/export coverage. It produces Q1 version/module/dedicated-item paths and returns an immutable paired handoff. `allocations()` retains Doc9 module-page destinations; `dedicated_item` supplies the same exact export's dedicated page, FQN fragment and validated optional alias. Missing/ambiguous labels and colliding full ids refuse the entire product.
The caller declares a complete auxiliary page/section namespace bound to the generated version root. Generated and auxiliary paths are checked together against reserved `index.html`, `search.json`, `cross-references.json` and the `assets/` subtree, including implicit directories and ASCII-case spelling conflicts. No winner or suffix repairs collisions. Section coverage remains independent under the existing Doc10 validator; the legacy supplied-table interface keeps its policy.
This adopts only the bounded G2 allocation prerequisite. It emits no files and supplies no renderer, wire/schema, source routing, later-gate or publication readiness.

## Adopted G3 Source Coordinates
`authenticate_doc_sources` revalidates the selected current plan and explicit finite publication inventory, then retains the original Artifact-validated projection. Its source binding uses full module identity, publication hash, exact packaged relative source path and supplementary Session `hash_text(original)`. A normalized source hash alone cannot identify original byte coordinates. Legacy/null projections remain unavailable; contradictory publication/path/source/frame or map bindings refuse.
The immutable handoff composes ordered Q3→loaded→original and original citation lexical→loaded→original segments against that same projection. Session owns map intersections; Doc validates consumer bounds and UTF-8 boundaries. Independently mapped segments survive partial coverage without bridging container, removed-comment or missing-map gaps; coverage remains complete/incomplete/unavailable. Artifact occurrence spans retain their loaded AST frame: `citation_ranges` recovers authored lexical endpoints before composing them, while `lexical_ranges` accepts explicitly lexical segments. Citation ordinals, repeated/self occurrences and endpoint/examination coverage remain unchanged.
This adopts only the bounded G3 coordinate prerequisite. Reference encounter-order/classification stays with Doc8/9, source-view/line routing with the [bounded Q3 definition](./render.md#q3-source-view-and-line-routing-definition), and degraded summaries with Q4/MT; adopted block-local recovery is preserved. Coherent Doc13, rendering and later gates remain separate.

## Identity And Allocation Handoffs
Consume the authenticated publications and complete export inventory from [Doc4](./doc_build.md#index-inputs-and-later-completion), with the producer/validation obligations of [Doc10 prerequisites](./link_prerequisites.md). Export visibility includes Public and Reexported; retain each full identity once, never merge distinct duplicate FQNs. Every projection must retain its binding to the validated original module/export and publication.
For this proposed JSON only, define module key `M = [package_id, package_version, lock_identity, module_components, edition, publication_hash]` and item key `I = [package_id, package_version, lock_identity, module_components, edition, origin_id, publication_hash]`. Strings retain exact owner spelling; only absent lock identity is null. Version is the stored required string under Doc4, never synthesized. Hashes use the owning Hash's lowercase hexadecimal encoding, not an interface/source hash. Module components are an ordered array of authoritative strings. Existing ModuleSummaryIdentity stores one module-path string: the adopted G1 handoff supplies its authenticated lossless structured-path binding; coherent wire adoption remains separate; splitting an FQN or guessing separators is forbidden. These tuples do not revise Artifact storage.
Key order compares existing full ModuleSummaryIdentity Ord through that binding, then exact FQN and origin for items, publication hash last. Never sort encoded JSON text or parsed versions. `fqn`, `kind` and `signature` project VerifiedExport's exact fully_qualified_name, export_kind and rendered_signature strings. Kind is an opaque owner string, not a new enum; the adopted G1 handoff above owns the actual producer vocabulary and its version binding. Unknown spellings cannot be inferred from names or statements. Empty available display strings stay empty; unavailable metadata is not an empty string.
The render allocation handoff supplies each `M`'s module page and each `I`'s module-entry and dedicated-item destinations, exact FQN id, authoritative label and validated optional aliases. A logical destination `D = [path_components, fragment]` uses root-relative authoritative path components and an exact fragment string (null only when no fragment is required). Validate the entire Q1/Q2 destination set, including `cross-references.json`, against [page/anchor/section rules](./link_prerequisites.md#validated-page-anchor-and-section-allocations); no identity winner or suffix repairs collisions. The binding records both destinations for one item without changing Doc9's module-page reference destination.
Construct search hrefs relative to the version output root, and page links relative to their actual containing page, using only adopted Q3 per-segment percent-UTF8 and full-fragment encoding. DOM ids retain exact FQNs with attribute escaping. For example, logical `p/é%#.html` and fragment `m.é%#` yield `p/%C3%A9%25%23.html#m.%C3%A9%25%23`. This is distinct from Q1 filesystem spelling. Version-bound section destinations require the authenticated section inventory; source links require packaged original source/maps under the [bounded Q3 source-view/line definition](./render.md#q3-source-view-and-line-routing-definition). Its isolated handoff supplies source-view/line routing only.

## Adopted G4 Supplied Search Reader
Only the reader of supplied version-1 search data and [Q9/DOM behavior](./render.md#owner-slots-and-dom-hooks) is adopted; the following producer/serialization proposal remains gated. Supplied records use the exact envelope, item and identity shapes below, the G1 kind vocabulary and owner lowercase hexadecimal publication hashes. All records validate before any result is consumed; supplied order and distinct duplicate FQNs survive without inferring authenticated completeness or producer ordering.
Reject duplicate decoded object keys, unknown fields, wrong shapes/types, invalid UTF-8/JSON, unsupported versions/kinds and unsafe hrefs. Legal JSON whitespace/key order is accepted; no coercion or partial records. Hrefs must be Q3-canonical relative paths with the full encoded FQN fragment; forbid empty/dot/traversal components, decoded path separators/backslashes/controls, root/foreign URLs and malformed escapes. Local index fetches reject foreign origins and redirects; rebase results from the index directory preserving stored escapes/fragments. Each control's failure is isolated and visibly unavailable, distinct from compatible complete-empty data or zero matches.
The [local asset handoff](./render.md#adopted-local-style-and-search-assets) supplies the executable consumer. This adopts no index producer, summary projection, complete renderer, registered schema, publication, diagnostic/readiness definition or later-gate/coverage credit.

## Proposed Search Encoding And Compatibility
Retain Q7's envelope key order `format_version, package_version, items` and record key order `identity, fqn, kind, summary, signature, href`. Format version is candidate JSON integer `1`; identity uses `I`, package_version the selected stored string, kind/signature the projections above, href the dedicated page with full FQN fragment. Items follow the identity order above and include every selected export, including undocumented/reexported items. Dependencies enter only through explicit documented exports. Complete-empty exports serialize as `items:[]`.
Summary is Q4's exact projected string, including `""`, or null only for known absence of a comment. Unavailable inputs block search readiness; they never become null or an omitted record. Adopted Doc8 raw-block conversion/map recovery continues the default build with warnings; its degraded summary uses the [joint Q4/MT definition](./render.md#joint-q4mt-summary-definition), not a new Q8 producer refusal. The isolated shared projection supplies module fragments and search text; complete search production/serialization remains separate.
Search and auxiliary JSON use Q11 compact UTF-8 without BOM, declared key order, no insignificant whitespace and one final LF. Escape quote and backslash, and every U+0000–001F as lowercase `\u00hh`; emit other Unicode literally without normalization or escaping `/`. Reject duplicate/unknown keys, wrong shapes/types, invalid UTF-8 and unsupported format versions as incompatible; do not coerce or consume partial records. Ordinals/offsets below are canonical unpadded decimal u64 strings, avoiding browser number truncation. Null has only the explicitly assigned meanings; it is never a wildcard identity.
Version 1 has exactly these fields and shapes; any wire shape, value interpretation, kind vocabulary binding or ordering change requires a separately reviewed compatibility/version decision. This proposal reserves no schema identifier. Q9's client matching/order is unchanged; load/parse incompatibility displays unavailable rather than an empty match set. Q11's renderer/template/toolchain and pinned-asset identities remain reproducibility inputs outside these wire records.

## Proposed Cross-Reference And UsedBy Serialization
At the selected version root, candidate `cross-references.json` has keys `format_version, package_version, references, citations, used_by, coverage` in that order, with the same version/byte/compatibility rules. It is separate from search and the opt-in machine-readable DocIndex. It represents authenticated Doc9 resolution/coverage results; it neither resolves references nor manufactures a direct-by producer.
Reference records have keys `subject, form, reference, state, targets, routes, destinations, provenance` in that order. Subject is `[M, target]`, where target is `["module"]` or `["item", origin_id, fqn]` bound to that module; form is `code|explicit|see`; reference is `[raw, interpreted]`, with null interpreted only when unavailable. State is `resolved|unresolved|ambiguous|incomplete`, retaining Doc9's outcome rather than recomputing it. Ordinary URL links are not semantic edges. Retain every authoritative occurrence, including unresolved and coincident ones; a block whose conversion failed supplies no invented occurrences.
Target keys are `["item", I]` or `["section", inventory_publication_hash, specification_version, section_id]`; section keys require the version-bound inventory's authenticated publication binding. Targets contains only the owner-authenticated reference class: item candidates in item identity order, or section candidates by exact version, id, publication string order. Module targets and mixed-class arrays are invalid; unavailable classification retains the owner's unresolved handoff, never guessed targets. Known candidates are distinct. Resolved has one target, unresolved none, ambiguous multiple; incomplete may retain known candidates without implying uniqueness. Routes use `[target_key, kind, position, endpoint_M]`, with `current|import|closure` and null position except an authoritative import ordinal. Apply [shared link route ordering](../../mizar-diagnostics/en/documentation_links.md#structured-identity-and-details); no cyclic route discovery; section targets have no module-query routes. Destinations contains one `[target_key, D]` per validated known candidate in targets order; duplicate target/destination rows are invalid; missing allocations retain incompleteness, never guessed hrefs or active ambiguous links.
Reference provenance has keys `block, occurrence, logical_range, mapping, segments` in that order. Block/occurrence are preserved zero-based source-order ordinals; logical_range is `[start,end]` in Doc8's extracted-block byte coordinates. Mapping is `complete|incomplete|unavailable`; segments retain original encounter order as `[source_binding, start, end]`, where source_binding is `[M, packaged_relative_path, source_content_hash]` authenticated by the source/map producer, and offsets are original UTF-8 byte coordinates, half-open. Never bridge discontiguous segments. Unavailable mapping uses an empty segment array, not fabricated zero ranges; independently mapped segments survive an incomplete map. Missing source-order ordinals or coordinate bindings remain producer gates; serialization cannot infer them from output enumeration.
Order references by subject's module/item order (module subject before items), block ordinal, occurrence ordinal, then form in the stated order. The producer must bind ordinals to original logical encounter order, including repeated/same-range occurrences; do not deduplicate references. Mapped offsets are provenance, not sorting substitutes. Logical reference ranges remain required; an unavailable conversion view is handled by Doc8 recovery, not a fabricated reference record.
Citation records have keys `citing, cited, by_ordinal, target_ordinal, provenance` in that order, with item keys for endpoints and the [Artifact-owned original ordinals](./link_prerequisites.md#artifact-owned-direct-by-producer). Cited may be null only for an unmapped endpoint, forcing incomplete coverage; preserve its occurrence. Citation provenance uses `mapping, segments` as above; by/target ordinals identify syntax even without maps. Sort by citing identity, numeric by ordinal and target ordinal; retain repeated/self/cross-package citations. Neither `@see`, Markdown links nor used_axioms supplies these records.
Coverage has keys `closure_state, closure, citation_state, examined` in that order. States are `unavailable|incomplete|complete`; closure is the explicit finite array of `M` in module/publication order. Examined is `[I, parts]` for producer-enumerated theorems, in item order, with actually examined `body|proof` parts in that order without duplicates. These project [the existing coverage obligations](./link_prerequisites.md#artifact-owned-direct-by-producer); an empty vector alone never establishes complete coverage. Keep closure and examination states independent; missing/unmapped endpoints cannot yield complete citation_state.
Used_by contains one record per producer-classified selected theorem in target item order, keys `target, state, citing`. State is unavailable if either coverage state is unavailable, otherwise incomplete if either is incomplete, otherwise complete. Citing is the distinct reverse-mapped direct citing item keys in Doc9 display order; occurrence records remain separate and lossless. Complete-empty lists require complete authenticated closure and examined coverage with no incoming direct edges. Incomplete lists retain known edges but are displayed explicitly unavailable, never as exhaustive. Completeness is relative to that closure, not all external dependents.

## Ordered Readiness Gates
Each gate requires independently inspectable owner evidence; prose definition or screening is not a passing witness:
1. The bounded [G1 identity handoff](#adopted-g1-identity-binding) adopts kind/version compatibility and authenticated lossless module components against complete exports. Coherent adoption of the required Doc13 ① render/wire interfaces remains separate, preserving adopted Doc8/9 and Q3 hrefs; this prerequisite alone does not make Doc13 ready.
2. Supply/authenticate Doc10 import/closure/direct-by inputs and render page/id/alias/section allocations. Demonstrate complete-empty, incomplete and refusal states, repeated/self/cross-package citations, reserved/file-directory/case collisions, absent labels and non-ASCII hrefs. Lower-reader integrity/schema/currentness failures remain errors.
3. The bounded [source-coordinate handoff](#adopted-g3-source-coordinates) supplies authenticated original byte segments. Original-order reference encounter/classification remains Doc8/9 work; the separate [Q3 source-view/line definition](./render.md#q3-source-view-and-line-routing-definition) fixes internal routing/presentation, and its isolated authenticated original-text access, allocation and rendering handoff is adopted. Missing maps preserve provenance without synthetic offsets; missing source keeps its existing unavailable/warning behavior. The [joint Q4/MT definition](./render.md#joint-q4mt-summary-definition) fixes degraded summary selection without changing adopted block-local recovery; its isolated shared selector, module fragments and search text projection are adopted. Complete page/index production remains outstanding. The isolated comment/tag/See [safe-flow handoff](./render.md#adopted-comment-and-tag-safe-flow-handoff) composes genuine Doc8 views and supplied Doc9 classifications; UsedBy fragments and templates remain separate.
4. Separately define/adopt Q12 render diagnostics, locations, overlap/precedence and profiles with the diagnostic owner; shared link diagnostics do not allocate render warnings; the bounded URL prerequisite below allocates only its rejected-URL meaning. Render owns the [complete-page template definition](./render.md#complete-page-template-definition); this definition supplies no executable template witness. The bounded supplied-search reader/local assets above do not resolve remaining Doc11/math and owner-slot presentation dependencies. Warning promotion affects documentation only, never proof or extraction acceptance.
5. Only then dispatch Doc14/15 implementation against adopted interfaces and complete inputs, with positive/refusal/incompatibility witnesses for the wire shapes and canonical bytes above. Doc23 atomic publication, Doc24 executable determinism and optional DocIndex schema/compatibility remain separately gated; this completion discharges none of them.
