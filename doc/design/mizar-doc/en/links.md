## Authority And Fixed Boundary
Current handoff: spec24.2 owns the adopted link semantics, including Q9 Artifact-owned, publication-bound direct-by records; neither exports nor `used_axioms` is a citation fallback. [Doc13 Q3](./render.md#candidate-destinations-and-page-content) supplies only the adopted href encoding interface, not filesystem or source routing.
Spec [24.1–2](../../../spec/en/24.documentation_generation.md#242-cross-referencing-and-hyperlinks) fixes label-based references, lookup precedence, ambiguity warnings, UsedBy and exported-label anchors. Architecture13 [shared identity](../../architecture/en/13.documentation_and_extraction.md#documentation-and-extraction-share-symbol-identity) and [Step3](../../architecture/en/13.documentation_and_extraction.md#step-3-resolve-links-and-render-math), internal05 [index](../../internal/en/05.documentation_extraction.md#documentation-index) and [diagnostics](../../internal/en/05.documentation_extraction.md#diagnostics) bound consumer ownership. This proposal depends on bounded approved [Doc4 inputs](./doc_build.md#index-inputs-and-later-completion), not Doc8 adoption or parsing.
Doc4 supplies full package/version/lock/module/edition identity, selected publication hash, stored export origin/FQN and optional label candidates. Its canonical ordering is storage order, never semantic import precedence. None, available-empty and ambiguous candidates stay distinct; reader integrity/schema/binding refusals remain refusals. No source fallback, synthesized label, package/version selection, proof acceptance or serialized index schema follows from these inputs.
The fixed surface includes exact-label/FQN inline code, explicit `[text](ref)` and `@see ref`; explicit and @see references accept label/FQN, specification section and external URL forms. Expressions, theorem fragments and overloaded notation in code remain code. Unqualified lookup first checks the current module's exported labels, then imported modules in semantic import order; ambiguity warns and leaves text unlinked. FQNs do not invoke overload resolution.
Every documented item has its exported-label-derived full FQN anchor (for example `#algebra.ring.AddAssoc`); a page-unique label may also have `#AddAssoc`. Sections use `#sec-20-5-1`. Definition/theorem/registration labels and the algorithm identifier supply the respective labels as specified; absent authoritative metadata cannot be replaced by splitting an FQN or parsing a signature.

## Candidate Resolution Model
The following is the combined candidate ① of Q1–Q10, for owner review only. No Rust API, parser grammar or artifact field is adopted. Other combinations require coherent definitions before adoption.
A parser-neutral occurrence retains its form (code, explicit or @see), exact raw spelling, optional interpreted destination, mapped source segments, attached module/item identity and publication provenance. Doc8 owns recognition/decoding and field extents; this contract can describe future occurrences without selecting its Q9–Q18. Candidate ① compares the supplied interpreted reference exactly, with no further trim, case folding, Unicode normalization or expression parsing; raw text remains available for diagnostics. It never turns a whole code expression into several reference attempts.
Candidate ① routes a recognized specification-section reference through an explicitly supplied generated-specification index, and an external URL through unchanged. Other eligible references query authoritative exported labels/FQNs. Unsupported or missing destination classification remains an unresolved handoff, not an invented symbol spelling. No network lookup is performed. Page/URL safety and HTML escaping remain rendering responsibilities; this proposal neither adds a URL scheme allowlist nor changes the spec's passthrough rule.
A target retains full original module identity, publication hash, export origin, FQN, actual label and visibility; reexports preserve their stored identity rather than inventing origin equality. Candidate ① deduplicates only identical complete target identities reached by multiple lookup routes; distinct records with the same label/FQN remain distinct. Apply the selected documentation visibility policy without promoting stored metadata to verification authority. Current-module candidates precede all imported candidates: one ends unqualified lookup successfully, multiple end it as ambiguous. Only with no current-module candidate traverse all imports in their semantic order, retaining every candidate and its route. Two distinct matching targets are ambiguous even when encountered at different import positions; enumeration order cannot choose a winner.
FQN lookup in candidate ① searches the explicitly bound package/dependency documentation closure, retaining full identities even where FQNs collide across versions or packages. A unique target is linkable only when the queried namespace and target page/anchor are known complete. Zero matches in a complete search means unresolved; multiple distinct matches mean ambiguous. Missing metadata means incomplete, never a negative lookup or complete empty graph. A unique current-module hit needs no later import search; without it, unavailable import order/completeness prevents a claim of successful unqualified resolution.
Candidate ① import inputs retain each source module's authoritative ordered module identities and a distinction between unavailable, explicitly complete-empty and incomplete vectors. Dependency references retain package tuple, publication hash and index location; an index consumer must authenticate the referenced index's schema, publication and full target identities against validated inputs before use. A path alone or canonical sort never authenticates an import edge or chooses a package version. Cycles do not trigger recursive source discovery: lookup uses only the supplied finite closure. No suitable completeness/validation producer is approved here.

## Candidate Pages, Anchors And UsedBy Inputs
Candidate ① obtains module-page destinations from a separate allocation table keyed by full module/publication identity. Its paths distinguish colliding packages/versions; paths are relative to the selected output root. The table must refuse path collisions before href construction; this proposal does not choose a directory spelling or output traversal policy. The full anchor id is the exact authoritative FQN, with no notation-based slugging, suffix or renaming. Two distinct items needing the same full id on one page block that page's link readiness pending owner resolution. An unavailable authoritative label also blocks item-anchor readiness.
Candidate ① emits a short alias only for one distinct documented target bearing that label on the page and only if it collides with no full id, section id or other alias. Full ids retain priority; suppressing an optional alias never changes a full anchor. Rendering escapes DOM attributes and encodes href components at the output boundary while retaining the logical anchor identity; the exact fragment-encoding contract remains Q6. Section lookup needs a bound specification version, section id and page destination; absent/unknown sections stay unresolved rather than becoming local module anchors.
Spec24.2 requires all direct `by` citations by theorems to theorem T. Architecture13 mentions `used_axioms` and citation metadata, but spec [23.5.1](../../../spec/en/23.package_management_and_build_system.md#2351-mizirjson-artifact-format) describes `used_axioms` as accepted-evidence facts for particular statuses; export identity/ranges alone do not supply all syntactic citations. Neither raw exports nor transitive accepted-evidence dependencies establish the required direct-citation graph. This mismatch is an input-definition gate, not permission to change language/proof intent or claim UsedBy complete.
Candidate ① requires publication-bound authoritative direct-citation records identifying citing theorem, cited theorem, `by` occurrence provenance and completeness scope, mapped to the same complete export identities. The future producer must state which theorem bodies/proofs were covered; a missing producer or an unmapped endpoint is unavailable/incomplete, not zero citations. Consumer recomputation from source, names or proof evidence is excluded. Doc4 inputs and existing artifact schemas remain unchanged; producer/schema work needs its own approval and task.
Reverse only direct mapped theorem-to-theorem citation edges for UsedBy. Candidate ① retains occurrence provenance but displays each citing theorem once per target, including self-citation if authoritatively recorded; cross-package edges require bound endpoints. `@see`, Markdown links, transitive dependencies and used_axioms-only entries are not direct-by evidence. Sort displayed citing identities by existing full module identity order, exact FQN then origin, with publication hash as the final distinction; repeated occurrence order is retained separately. Candidate ① exposes incomplete citation coverage rather than an exhaustive empty UsedBy list; UI and incomplete-input warning policy remain Q10.

## Adoption And Review Witnesses
Candidate ① orders presentation drafts by existing diagnostic stage/file/range rules and stable target/publication identity tie-breakers; source occurrences retain mapped segments through attachment/loading transformations. Missing maps use existing provenance locations, never fabricated offsets. The Documentation diagnostic owner must define unresolved, ambiguous and incomplete-input meanings, locations, order and profile behavior before implementation; no shared diagnostic code is allocated here, and W0400–W0404 remain attachment warnings. Warning promotion can fail documentation only, never verification or extraction acceptance.
Review witnesses include an exact code label versus an expression; explicit/@see label, FQN, section and URL; a local hit with unavailable imports; complete-empty versus missing imports; duplicate routes versus distinct matching imports; colliding package/version FQNs; a wrong-hash dependency index; full/short/section anchor collisions; absent section registry; direct repeated/self/cross-package `by` records versus used_axioms-only data; and absent versus complete-empty citation coverage. Their candidate outcomes follow the paragraphs and Q alternatives above, not executable fixtures or adopted test intent.
Current Doc10 gates remain: authenticated complete ordered import/dependency-closure inputs and Artifact-owned publication-bound direct-by producers; validated page/anchor/section allocations; exact shared diagnostic descriptors and detail/location/deduplication/order rules. Doc9 and Doc8 adoption do not supply these inputs or diagnostic definitions. No link resolution, schema/diagnostic allocation, math/HTML rendering, extraction/publication, coverage/owner credit or broader Doc4/5/crate completion is claimed.
