## Adopted Opaque Math Transport
For the bounded [runtime](./math.md#adopted-opaque-client-runtime), `render::opaque_math_fragments` borrows ParsedComments and emits one fragment per real Doc8 occurrence in block/occurrence source order. It joins only MathRange interior segments without rewriting payload; original attachments, target/publication, outer range and discontiguous maps remain with the caller under those same ordinals. Unavailable input or malformed segment bounds refuse; available-empty remains empty. This is neither a page renderer nor a serialized provenance schema.
Each inline `span` or display `div` carries attributes in fixed order: class, data-mizar-block, data-mizar-occurrence, data-mizar-display, data-mizar-tex. Unpadded decimal ordinals and lowercase hexadecimal UTF-8 payload bytes avoid HTML parsing/entity/newline transformations, including NUL. A role=status child and code child provide a visible pending fallback. Escape HTML metacharacters and spell non-HTML-preservable controls as visible `\u{hex}` there; the hex attribute remains exact. Client fallback uses textContent with the decoded original payload. No payload enters executable source, innerHTML, URLs or attributes other than hex.
The local asset handoff exposes fixed relative `assets/katex/` paths and immutable bytes, validates the complete exact manifest/configuration set before integration, and refuses missing/extra/changed entries. The standalone client derives its local base from its own script URL, including nested pages; it verifies runtime/CSS/fonts/configuration against pinned digests before loading them, rejects redirects/foreign origins and retains safe fallback on failure. Verified asset bytes alone supply executable/CSS/font blob URLs. Site staging/publication and complete HTML templates remain gated.

## Candidate Destinations And Page Content
The following paragraphs retain combined candidate ① for owner review, subject to the adopted Q3 href interface above. Allocate each selected package to its explicitly configured output root; retain full package/version/lock/module/edition, publication hash and export origin/FQN in the allocation table. Reject colliding roots rather than selecting packages or versions. Doc4 requires stored versions; this route does not add an unversioned planner or synthesize a version.
Q1 proposes a version root `doc_dir/v<component(version)>/`. Inside it, a one-component module `algebra` uses `algebra/index.html`; a nested module `algebra.groups.basic` uses `algebra/groups/basic.html`. A dedicated item page uses `<module-components>/items/<component(exported-label)>.html`. Components come from authoritative structured paths/labels, never splitting guessed FQNs. Keep ASCII letters, digits, `_`, `-` and `.`; encode every other UTF-8 byte as `~hh` with lowercase hex, including literal `~`; encode all dots in `.`/`..` and a trailing dot. Empty components block allocation. This is a candidate filesystem spelling, separate from URL encoding.
Q2 checks the entire destination set, including reserved `index.html`, `search.json` and `assets/`, for file/directory and ASCII-case-folded path collisions before emission; a collision blocks that package's site/search readiness. Thus `algebra` plus `algebra.index` cannot silently share `algebra/index.html`. Distinct full identities never merge or gain arbitrary suffixes. Exact full FQN ids remain mandatory on module listing entries and dedicated pages; approved Doc9 aliases are checked against all full/section/other alias ids. Doc9 reference destinations remain module-page-plus-anchor; module listings additionally link to dedicated item pages. Both destinations designate the same full identity.
Q3 adopted href interface constructs relative hrefs from allocated paths, percent-encoding UTF-8 bytes outside ASCII letters/digits and `-._~` per path segment and encoding the full logical fragment likewise; separators alone remain `/`. DOM ids retain exact FQN spelling, escaped as attributes, without normalization or notation slugs. Adopted Doc9 requires version-bound specification destinations. The remaining Q3 source-routing candidate requires packaged source text/maps bound to the artifact range plus an explicitly configured source destination/line convention; no local absolute path, guessed line or consumer source fetch. Missing source is visibly unavailable and warns by existing policy; exact source-view routing remains an adoption prerequisite under Q3.
Q4 selects the first ordinary CommonMark paragraph across the target's separately attached blocks in source order, excluding recognized tag paragraphs, as the summary. Flatten text/code to visible text, link labels and image alternative text to their text, math to its unchanged supplied payload, soft/hard breaks to spaces and raw HTML tokens to their literal spelling; collapse ASCII whitespace to one space and trim it, without Unicode normalization or truncation. An available comment without such a paragraph yields `""`; known absence yields `null`; unavailable producer metadata is not either state. Approved Doc8 Q18 conversion/map failure instead retains the raw affected block with a warning and continues the default build; its degraded one-line summary/search representation remains a joint Q4/MT adoption gate, never a fabricated first paragraph. Preserve all complete comments and every tag occurrence in source order on item pages, including unknown/malformed/duplicate tags; tables and See also are views, never replacement or deduplication. Formal contracts remain distinct from explanatory tags.
Q5 treats raw CommonMark HTML as visible escaped text, including inline tags; it remains a parsed construct and is not silently removed or executed. All source/summary/code/LaTeX text is context-escaped; Mizar highlighting uses lexical information only. Ordinary URLs remain ordinary URL references, not semantic lookups: the [bounded adopted output policy](#adopted-html-and-url-output-policy) defines safe destinations and visible fallback with a separately owned warning. Never fetch remote images/assets during generation. Image destination policy follows the same gate. This output policy neither changes approved Markdown recognition nor silently reclassifies MT failures.
Q6 hands already classified opaque math occurrences and resolved symbolic inputs to the future math owner. The bounded opaque transport/runtime above adopts safe DOM transport, pinned assets/options and error/reproducibility behavior; symbolic inputs and equation numbering/references remain unresolved Doc11 dependencies. No annotation substitution is selected here. Static assets must eventually be local, immutable and version-bound; no runtime CDN, mutable asset download or cross-formula state is authorized by this proposal.

## Candidate Search And Auxiliary Indexes
Q7 proposes UTF-8 JSON with top-level keys in this order: `format_version` (candidate integer `1`), `package_version` (stored string), `items` (array). Each item has keys `identity`, `fqn`, `kind`, `summary`, `signature`, `href` in that order. `identity` is the tuple `[package_id, package_version, lock_identity, module_path, edition, origin_id, publication_hash]`, with owner-canonical strings, null only for an absent lock identity, and module_path an ordered string-component array. Exact owning encodings, kind spellings and format compatibility must be enumerated before adoption; this is a proposed search wire format, not an Artifact/DocIndex schema allocation.
Include each selected package's exported/reexported item once per complete stored identity, including undocumented items and distinct duplicate FQNs; dependencies enter only through explicit documented exports, not closure crawling. `summary` is Q4's string or known-absent null, `signature` the authoritative stored display string without TeX/HTML conversion, and `href` the allocated dedicated item page plus full FQN fragment. Empty available strings remain empty. Missing required identity/kind/signature, incomplete exports, missing summary inputs or unresolved allocation block the package's search emission under Q8; approved block-local conversion/map recovery is excluded from this readiness refusal and awaits the Q4/MT degraded-summary definition; never omit a record, invent a signature or use null for unavailable input.
Q9's client search treats each ASCII-whitespace-separated query token as a substring that must occur in at least one of FQN/kind/non-null summary/signature, folding ASCII A–Z only and preserving all other code points. Empty query lists all items; matches retain index order, with no locale-dependent ranking, stemming or Unicode normalization. Results use text DOM nodes and validated hrefs, not HTML injection. Failure to load/parse a compatible local index displays search unavailable without fabricating an empty result set; this browser state is not a new build diagnostic.
Architecture Step4 also requires a cross-reference index, and internal05 names UsedBy output. Q10 proposes one separate cross-reference JSON containing identity-bound resolved edges, direct-by reverse edges, approved destinations, occurrence provenance and explicit completeness states; missing citation data is not an empty graph. Concrete field names/compatibility and ordering within source occurrences remain a joint Doc9/render adoption prerequisite, not an invented producer here. The optional machine-readable DocIndex stays opt-in and separate from search; its schema/compatibility belongs to a later coherent index definition under Doc4/Doc13, with publication by Doc23. Neither index establishes proof or extraction authority.

## Candidate Determinism And Failure Boundaries
Q11 fixes the reproducible set to relative paths and exact bytes of pages, search/cross-reference indexes, enabled optional index and bundled assets. Equal bound publications, sources/maps, lock context, dependency-index hashes, options, renderer/schema/toolchain and asset versions yield equal outputs regardless of enumeration or worker scheduling. Order modules by existing full ModuleSummaryIdentity Ord, items by exact FQN then origin, publication hash last; keep semantic import order and source/tag/occurrence order separately. Search uses the same identity order, never a locale collation or FQN-only deduplication.
Candidate ① serializes HTML with fixed templates/attribute order, UTF-8 without BOM, LF template line endings and one final LF. JSON is compact, follows declared object-key order, uses standard JSON escapes for quote/backslash/control characters, emits other Unicode literally and ends in one LF; auxiliary objects require an explicit canonical key order before adoption. Retained source payload line endings/spelling remain data and are escaped, not normalized by template LF rules. Assets are copied byte-for-byte from a pinned manifest. Exclude timestamps, random ids, absolute workspace/temp paths, hostnames, locale and browser-produced DOM from generated bytes; browser math behavior is still gated by Doc11, not certified here.
Q8 proposes blocking only the affected package's complete site/search generation for missing mandatory producer-supplied page/search projections; no partial site claims complete exported coverage. Approved Doc8 conversion/map failures keep raw-block warning/degradation and do not abort the default build; Q8 cannot reclassify them as missing producer inputs. Approved unresolved links remain safe unlinked text with warnings, incomplete UsedBy is explicitly unavailable, and missing source retains its existing warning rather than invented content. Lower-reader integrity/schema/currentness refusals stay errors, never presentation success. Upstream MT meanings and math failure handling remain their owners' unresolved gates; remaining output-policy failures need separately adopted render diagnostics.
Q12 proposes Documentation diagnostics with existing stage/file/range order and full target/publication plus stable occurrence tie-breakers, retaining mapped segments and generated file references when available; never fabricate offsets. The bounded [URL diagnostic](../../mizar-diagnostics/en/documentation_urls.md) is adopted; remaining render descriptors, locations, overlap/failure precedence and profile behavior require diagnostic-owner definition/adoption; no further codes are reserved, and W0400–W0404 remain attachment-only. Profiles may fail documentation quality only, never proof validity or extraction acceptance. Doc23 owns staging/atomic replacement and write-failure cleanup: readers must not see partial pages/indexes; this proposal grants no publication implementation or new transaction scope.

## Adopted HTML And URL Output Policy
This bounded Q5 adoption governs output only; CommonMark recognition, raw/interpreted destination storage and Doc10 classification/resolution remain unchanged. Raw HTML tokens, including inline tags, render as visible context-escaped literal spelling without a warning. No remote asset/image fetch occurs during generation.
For an ordinary URL-class link or image, apply this predicate to the exact CommonMark-interpreted destination, never its raw spelling: reject any ASCII C0 control (U+0000–001F), DEL or backslash anywhere; ignore leading/trailing U+0020 only for checking. In the remaining string, if a colon precedes every slash, question mark and hash (absent delimiters count as later), require an ASCII scheme matching `[A-Za-z][A-Za-z0-9+.-]*` and ASCII-case-insensitively equal to `http`, `https` or `mailto`. Otherwise accept it as relative/fragment, including empty and network-path destinations. Do not entity-decode or percent-decode again, normalize, repair or rewrite the stored destination. Accepted href/src values preserve the interpreted spelling with attribute-context escaping.
Thus `HTTPS://host`, `mailto:a@b`, `../a`, `#x`, `//host/a`, empty and `javascript%3Aalert(1)` pass; `javascript:alert(1)`, `data:x`, `1http:x`, `:x`, ` javaScript:x `, embedded controls and backslashes fail. Entity decoding belongs to CommonMark: `jav&#x61;script:x` is rejected when its interpreted value is `javascript:x`.
Rejected links retain all visible label content without an active href; rejected images retain their visible alternative text without src or an image load. Autolinks retain their visible label. This does not replace a semantic Doc10 reference with a URL or change its lookup. The [URL diagnostic owner](../../mizar-diagnostics/en/documentation_urls.md) defines the single warning; detection/emission and full rendering remain gated.
