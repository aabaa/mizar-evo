# Source overload selection
Canonical language: English; [Japanese pointer](../ja/source_overload.md).

## Boundary
`SourceOverloadInput` carries existing overload-engine input records with explicit
viability, comparison and view evidence. Source extraction authenticates the
ordinary/template use, candidate declaration identities, signatures, arguments,
anchors and source order before the unchanged engine consumes those records.
The initial profile is unary builtin set/object signatures and direct type
templates; unsupported source shapes fail closed. Task277 owns direct template
roles: this producer consumes native parameter/loci/actual nodes without
extending the separate fixed-profile 277A handoff. Task279 owns refinement
after ordinary-root selection.

## Transaction
`SourceOverloadHandoff` retains the original TypedAst and collection, expansion,
viability, specificity and selection outputs. TypedAst installation and final
ResolvedTypedAst assembly preserve the same handoff and require the matching
pipeline outputs. Missing comparisons never supply an ordering; expected or
result types never choose a root. Source qua views require their written basis.
The MT10-AS ordinary-root smoke consumes this final projection. It adds no
proof, accepted evidence, registration activation or semantic coverage credit.
