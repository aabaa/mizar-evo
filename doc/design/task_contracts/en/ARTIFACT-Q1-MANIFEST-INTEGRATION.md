## Integration Contract
Expose the existing commented family/version and store hash-exclusion paths from the codec owner; use them with existing validating JSON codec and generic atomic store APIs. Exclusions remain exactly the inherited local paths prefixed by `artifact`; comments are never excluded. No new envelope representation, profile enum, alternate transaction or sidecar.
Keep manifest schema1.0 and its exact fields. Select the commented reader only when `artifact_hash` declares `mizar-artifact/commented-verified-artifact` version1.0. All three main hash references must have the selected family/version and their existing classes. Unknown families, unsupported versions, mixed domains and malformed payloads fail closed; never retry another profile.
Referenced-file validation uses the selected outer family/version, exclusions and artifact/interface/implementation hashes. For commented1.0, require the existing codec's exact normal1.2 inner artifact; compare manifest source path/hash and full module identity with that inner artifact, not its version or inner semantic hashes with outer hashes. Reuse existing witness coverage, summary checks, file reachability, freshness/base guards and atomic manifest replacement. Unavailable and complete available-empty projections remain distinct valid envelopes. Legacy absence remains unavailable; no failed payload is downgraded.
Publication/hash validation proves selected byte/identity binding, not genuine producer lineage or current-request authority. Driver must later supply its freshness-validated retained draft through existing publication eligibility; Doc must later bind selected validated publication before consumption.
