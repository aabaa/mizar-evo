## Producer Contract
Add a real-MizarParserSeam-only Frontend `run_loaded_with_comment_metadata(source, captured_text)` entry point, preserving run_loaded's source identity and no-loading behavior. Return its ordinary output plus an optional immutable CommentMetadata; absence is a refused metadata input, never available-empty or a partial projection. Existing APIs/storage bytes stay unchanged.
Validate captured original UTF8 text against normalized source, hash, line map, origin and exact loading segments before metadata construction. Disk/OpenBuffer only; generated input is refused. Snapshot/package-version/publication currentness and sealed output lineage remain downstream obligations; this API supplies no such proof.
Construct metadata only inside that real pipeline path, not from caller-supplied AST/output. Expose read-only portable package/module/path/edition/origin/source-hash identity, original/loaded/lexical texts, loading segments and preprocess segments using existing ID-free segment types. Runtime SourceId, absolute diagnostic paths, map handles and AST IDs are excluded. Original/loaded/lexical byte frames are explicit; retained text preserves physical lines and inter-comment gaps without source rereading.
Preserve all ordinary/doc raw comment lexemes in loaded-source order, including markers, whitespace, Unicode and empty doc bodies. Preserve ordered whitespace trivia outside comments and syntactic candidate boundaries, wrappers, attached annotations and standalone annotations from the real AST; retain recovery state without inventing verified attachment. Include nested definition/registration/algorithm candidates supported by existing syntax. Use source positions, not allocation order, and validate UTF8 bounds, parent/child containment and exact comment slices/maps. Exact/composite/synthetic distinctions remain in reused map segments.
Write scope: this contract pair; Frontend preprocess/orchestration source and existing frontend test files; paired preprocessing API/plan pointers. Lower-owner source APIs and semantic tests remain unchanged. No coverage-audit ownership/status changes.

## Test Matrix And Exit
Six cases (cap six; Rust boundary tests in existing Frontend files, no new language behavior):
1. Real Disk capture with interleaved ordinary/multiline/doc comments, empty :::, Unicode and whitespace: exact lexemes/source order/gaps; marker-stripped raw_body unchanged.
2. BOM/CRLF and OpenBuffer versions: original/loaded/lexical frames and portable segments compose to exact or explicitly composite/degraded positions; no SourceId/path leakage.
3. Real parsed named items, visibility/export wrappers, attached and standalone annotations, nested definition/registration/algorithm candidates and recovery: actual ordered boundaries/relationships, no inferred semantic target.
4. No comments versus empty doc line: successful complete empty collection versus one present lexeme; comment-only edits change source metadata while preserving lexical reuse when text permits.
5. Mismatched captured text/hash/maps/origin, foreign or invalid UTF8 ranges and generated input: no metadata payload; ordinary pipeline diagnostics/acceptance stay unchanged.
6. Equivalent captures under fresh SourceIds/local diagnostic paths and repeat runs: equal portable metadata; existing frontend storage round trips and pipeline behavior remain compatible.
