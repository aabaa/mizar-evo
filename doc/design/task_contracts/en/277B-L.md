## Frozen checker API and structural invariant

The standalone module is
`crates/mizar-checker/src/source_template_type_parameter_association.rs`, with
paired durable ownership in
`doc/design/mizar-checker/{en,ja}/source_template_type_parameter_association.md`.
It is distinct from completed 277A `source_template` ownership.

The exact public surface is:

- `SourceTemplateTypeParameterAssociationId` with `new` and `index`;
- immutable `SourceTemplateTypeParameterAssociation`;
- `SourceTemplateTypeParameterAssociationTable` with `get`, `iter`, `len`, and `is_empty`;
- `SourceTemplateTypeParameterAssociationHandoff`;
- non-exhaustive `SourceTemplateTypeParameterAssociationError`; and
- `SourceTemplateTypeParameterAssociationProducer::build(collection: &TemplateTypeParameterSourceCollection, typed_ast: &TypedAst) -> Result<SourceTemplateTypeParameterAssociationHandoff, SourceTemplateTypeParameterAssociationError>`.

There is no caller DTO. The handoff owns source, module, association table, and
`debug_text`. Each row retains the R1 binding ID; it maps `TypedNodeId`s for
`definition_block`, `parameter`, `binder`, `type_head`, and `identifier`, and
keeps R1 parameter/type-head ranges and source ordinals. The table is immutable
and dense in the existing R1 generator-link order.

The exhaustive getter surface is
`SourceTemplateTypeParameterAssociationId::new(index: usize) -> Self` and
`index(self) -> usize`; row `binding() -> TemplateTypeParameterBindingId`,
`definition_block()`, `parameter()`, `binder()`, `type_head()`, and
`identifier()` each returning `TypedNodeId`, `parameter_range()` and
`type_head_range()` each returning `SourceRange`, and
`parameter_source_ordinal()` / `type_head_source_ordinal()` each returning
`usize`. Table `get(id) -> Option<&SourceTemplateTypeParameterAssociation>`,
`iter() -> impl Iterator<Item = (SourceTemplateTypeParameterAssociationId,
&SourceTemplateTypeParameterAssociation)>`, `len() -> usize`, and
`is_empty() -> bool`; handoff `source_id() -> SourceId`, `module_id() ->
&ModuleId`, `associations() -> &SourceTemplateTypeParameterAssociationTable`,
and `debug_text() -> String` are the only other getters.
The non-exhaustive error has exactly `EnvironmentMismatch` and
`InvalidAssociation { association: SourceTemplateTypeParameterAssociationId }`.

`build` validates in this order:

1. source/module disagreement returns `EnvironmentMismatch`;
2. each R1 link performs binding lookup and scans `typed_ast.nodes()` for
   `TypedNode.resolved_node == Some(the R1 ResolvedNodeId)`; zero or multiple
   matches for any of the five resolver IDs fail closed;
3. recovery is rejected and exact node kinds are required;
4. Range anchors, then R1 parameter/type-head range equality, are required;
5. the binder range is contained by the parameter range, both parameter and
   type-head ranges are contained by the definition range, and the identifier
   range is contained by the type-head range;
6. direct edges are `definition -> parameter`, `parameter -> binder`, and `type_head -> identifier`;
7. every other failure is the invalid-association variant above.

There is no reorder/duplicate variant: R1 owns order and ambiguity. The
producer does not mutate `TypedAst`, infer names, cast a resolver ID to a dense
typed index, or publish semantics. Range/spelling similarity cannot substitute
for the exact `resolved_node` match, and no new Typed/Resolved link slot is
authorized.
