## Freeze した checker API と structural invariant

standalone module は
`crates/mizar-checker/src/source_template_type_parameter_association.rs`、paired durable
owner は `doc/design/mizar-checker/{en,ja}/source_template_type_parameter_association.md`。
completed 277A `source_template` ownershipとは別である。

exact public surface:

- `SourceTemplateTypeParameterAssociationId` (`new` / `index`)
- immutable `SourceTemplateTypeParameterAssociation`
- `get` / `iter` / `len` / `is_empty` を持つ `SourceTemplateTypeParameterAssociationTable`
- `SourceTemplateTypeParameterAssociationHandoff`
- non-exhaustive `SourceTemplateTypeParameterAssociationError`
- `SourceTemplateTypeParameterAssociationProducer::build(collection: &TemplateTypeParameterSourceCollection, typed_ast: &TypedAst) -> Result<SourceTemplateTypeParameterAssociationHandoff, SourceTemplateTypeParameterAssociationError>`

caller DTO はない。handoff はsource、module、association table、`debug_text` をownする。
row はR1 binding ID、`definition_block`、`parameter`、`binder`、`type_head`、`identifier`
のmapped `TypedNodeId`、R1 parameter/type-head rangeとsource ordinalを保持する。tableは
immutable、existing R1 generator-link orderにdenseである。

exhaustive getter surface は `SourceTemplateTypeParameterAssociationId::new(index: usize) ->
Self` と `index(self) -> usize`; row の `binding() ->
TemplateTypeParameterBindingId`、`definition_block()`、`parameter()`、`binder()`、
`type_head()`、`identifier()` は各 `TypedNodeId`、`parameter_range()` / `type_head_range()`
は各 `SourceRange`、`parameter_source_ordinal()` / `type_head_source_ordinal()` は各
`usize`。table は `get(id) -> Option<&SourceTemplateTypeParameterAssociation>`、
`iter() -> impl Iterator<Item = (SourceTemplateTypeParameterAssociationId,
&SourceTemplateTypeParameterAssociation)>`、`len() -> usize`、`is_empty() -> bool`。
handoff は `source_id() -> SourceId`、`module_id() -> &ModuleId`、`associations() ->
&SourceTemplateTypeParameterAssociationTable`、`debug_text() -> String`だけ。
non-exhaustive error はexactに `EnvironmentMismatch` と
`InvalidAssociation { association: SourceTemplateTypeParameterAssociationId }` を持つ。

`build` のvalidation順序:

1. source/module disagreementは `EnvironmentMismatch`;
2. 各R1 linkはbinding lookup後、`typed_ast.nodes()`をscanし、
   `TypedNode.resolved_node == Some(R1 ResolvedNodeId)`のnodeだけをmatchする。5 resolver
   IDのいずれもmatchが0件または複数ならfail-close;
3. recoveryをrejectし、exact node kindを要求する;
4. Range anchor、次にR1 parameter/type-head range equalityを要求する;
5. binder rangeはparameter range内、parameter/type-head rangeはdefinition range内、
   identifier rangeはtype-head range内であることを要求する;
6. direct edgeは `definition -> parameter`、`parameter -> binder`、`type_head -> identifier`;
7. その他のfailureは上記invalid-association variant。

R1がorder/ambiguityを所有するのでreorder/duplicate variantはない。producerは`TypedAst`を
mutateせず、nameをinferせず、resolver IDをdense typed indexへcastせず、semanticをpublish
しない。range/spelling similarityはexact `resolved_node` matchの代用にならず、新しい
Typed/Resolved link slotも追加しない。
