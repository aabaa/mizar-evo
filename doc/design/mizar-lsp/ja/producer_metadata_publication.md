## 公開物と所有権

必要な公開物は、依存先向けの [ModuleSummary](../../mizar-artifact/en/module_summary.md#scope) と、import 元における解決済み可視面のローカル公開 view の二つです。前者は public 宣言、lexical 効果、reexport を公開し、ローカル private 宣言、活性区間、namespace alias binding の代わりにはなりません。後者はそれらの事実を選択した source と依存入力へ結び付け、Q3-A が in-memory carrier を選択します。これは論理上の要件であり、新しい Rust 型やシリアライズ field ではありません。
Lexer は正確な記述 spelling 片、構文 arity、default/explicit operator metadata、活性イベントを所有します。Resolver は宣言との対応、意味上の relation target、visibility、import/alias/conflict 解決、reexport を所有します。Artifact は codec、検証 reader、正規順序、interface hash を所有します。既存 Driver/build owner が真正な phase output を取得・関連付け、既存 artifact/manifest 境界で公開し、LSP が読みます。LSP による AST/IR 走査、compiler replay、target の推測、架空 producer 登録で不足を埋めません。
対応する各事実には producer の canonical module/origin、記述または修飾 access spelling、role/kind、source provenance、visibility が必要です。ローカルな事実には保持した original source 上の owner 定義 scope と activation boundary も必要です。Notation は正確な片/arity と利用可能な fixity/associativity/precedence、alias は自身の宣言 provenance と正確な target/relation、namespace binding はローカル spelling と canonical target を必要とします。公開済み symbol/label signature と status はそのまま保持し、lexical 候補を解決済み symbol、alias 同値性、受理済み theorem に昇格させません。未対応の事実は unavailable とし、keyword と補完順位は Task25 が所有します。

## Notation 公開案

承認済み Q1/Q2-A に従い、拒否 guard の削除だけでなく真正な同一 frontend 対応を拡張します。宣言と operator/alias イベントを既存 source map で写像し、一意で未回復の owner 宣言と完全な source inventory に結び付けます。resolver 表示文字列から再構成せず、lexer の正確な spelling 片と arity を保持します。複数片が origin を共有でき、origin key だけでは重複除去しません。独立 operator 宣言は symbol/spelling を追加しません。
ローカル view は位置依存イベントを保持します。import metadata が module body を初期化し、ローカル spelling/operator 変更は宣言完了境界でのみ有効になります。default metadata より最新の活性 explicit spelling-level イベントを優先し、後続の同 spelling overload は別候補のまま、勝者を推測しません。private 宣言は resolver scope に従ってローカルに可視ですが、export row に漏らしません。出力 summary は依存 interface であり、過去のローカル位置への回答に使う履歴ではありません。
**Q1 — export する operator 効果:** 承認済み A は最終的な public 公開適格 spelling-level metadata を既存 exported shape に載せ、import operator 入力と過去のローカルイベントは local view に保持します。対応する exported functor/arity と owner が認証した operator event を必須にします。private 効果が最終 metadata を決める場合や、ローカル exported owner がなく imported spelling だけを変更する場合は、export policy の承認まで出力 lexical product を公開しません。代案 B は shape への平坦化に代えて、forwarded spelling への効果も含む versioned exported operator-event projection を定義します。既存 codec と限定的な初期 producer のため A を推奨します。B は対応範囲が広い一方、scope/visibility/conflict 意味と schema 作業の明示が必要です。どちらも言語の activation/overload 規則を変更しません。
**Q2 — alias 同一性と admission:** 承認済み A は解決済み public synonym/antonym に resolver 所有の宣言 origin を与え、元 target module/origin と relation kind を別に保持し、lexical shape は alias 自身の exported row を key とします。その宣言の複数 spelling は origin を共有します。producer は imported original を含め既存意味に従って kind、順序付き loci/arity 対応、target を認証し、浅い lexical fallback では代用しません。代案 B は元 origin の追加 spelling として alias を export し、relation/provenance carrier を別途定義します。alias の visibility、宣言 range、antonym inversion を独立に保持できる A を推奨します。B は alias row を不要にしますが、foreign target に現行 envelope binding をそのまま使えません。この提案は既存の対応 relation profile を拡張しません。未対応の predicate/functor/mode/attribute/algorithm target や chain は公開前に各 resolver/checker owner の作業が必要です。どちらも antonym を target と同一視せず、overload applicability を決めません。

## Import と alias の公開案

producer は import pre-scan 成功だけでなく、完全な source import/export inventory と意味検証済み resolver output を使います。[alias binding](../../mizar-resolve/en/imports.md#alias-binding) を維持し、`as` はローカル namespace spelling だけを変え canonical module/artifact identity を変えません。alias なしでは既存 namespace 規則を使います。重複 source 宣言/provenance を保持しつつ canonical closure の graph edge は重複除去します。未解決・回復済み・競合 alias を明示し、import 順で衝突を解消しません。依存先の public surface だけにアクセスできます。ローカル shadowing/ambiguity は resolver outcome が供給し、補完が選びません。
import/forward された各事実に canonical target module/origin、owner 解決済み access path、import 元 source binding、import/export provenance、消費した各 dependency summary の module/interface reference を保持します。import prelude に現れるだけでは namespace alias は exported 宣言になりません。通常 import は内容を自動 reexport しません。module path と label access は対応 resolver の事実を使い、rendered text、filename、lexical symbol id から生成しません。
**Q3 — 消費可能な carrier:** 承認済み A は選択 publication に付随する不変な owner-produced view を公開し、上記論理事実、local scope/event、dependency reference を既存 snapshot association に保持します。available な完全空 scope と unavailable/unsupported scope を区別し、resolved/ambiguous/unresolved outcome を LSP の解決なしで渡します。process-local identifier のシリアライズは定義しません。代案 B はこの view 用の別 versioned artifact projection を追加します。ModuleSummary に local scope/alias data があると仮定しない A を推奨しますが、真正 producer の引き渡しと lifecycle 検証が必要です。B は永続 replay に対応する一方、承認済み schema/encoding/storage owner が必要です。どちらかの carrier が実装・関連付けされるまで Task25 は事実の利用可能性を仮定できません。保留中の OpenBuffer provenance/storage や Session SourceId encoding は決めません。
**Q4 — reexport 合成:** 承認済み A は canonical target summary と明示 forwarding edge を保持します。resolver が非循環 public forwarding closure を検証して可視 view を作り、実際に消費した全 summary interface を記録します。facade の `reexports` は forwarding 関係を記録し、foreign lexical shape を facade identity でコピーしません。代案 B は承認済み stable forwarding-origin mapping と対応 payload codec により各 facade に forwarded row を実体化します。現行 envelope 検査を変えず provenance を残す A を推奨します。B は読出しを単純化しますが新しい identity/hash 規則が必要です。欠落 target、private forwarding、未対応 item-level forwarding、未解決 cycle を成功した空 closure にしません。local `as` alias は canonical reexport target を改名しません。

## 検証と公開境界

Acceptance chain: 一つの整合 run から真正 frontend/source と resolver result を保持し、対象の完全な declaration/import/export inventory と正確な対応を検証し、各依存先を requested module/index/manifest binding に照らし owner reader で読み、認証済み事実だけを合成し、summary と Q3 view を検証・正規化してから、既存 publication owner で対応 reference を公開します。caller 提供 identity や codec round trip だけでは source/build authenticity を保証しません。source candidate、provider 成功、未 commit summary は publication ではありません。
[typed lexical envelope](../../mizar-resolve/en/module_summary_reuse.md#typed-lexical-payload-binding) を再利用し、kind/schema/key がちょうど一つの public exported row を選び、canonical module/origin payload identity が一致することを要求します。現行 reader は FQN key 代用と、foreign payload identity を facade envelope にコピーした場合を含む不一致 envelope を拒否します。Q2/Q4 が表現可能な row を供給できなければ unavailable のままです。既存 shape 検証と lexer 正規 summary 構築を使い、合法な重複 shape を保持します。Artifact contribution 順序と lexer 順序/fingerprint は異なる owner 契約で、hash を相互代用しません。
canonical artifact writer と [interface hash](../../mizar-artifact/en/module_summary.md#interface-hash) は exported notation/parse effect と影響する dependency interface を含みます。body/comment/range だけの変更は既存除外を保ち、意味上の exported spelling/operator/reexport 変更は対応 interface input に反映します。既存 source/lexical/artifact hash domain を相互代用せず再利用します。local view は正確な source/publication/dependency reference に結び付け、新 hash encoding を定義しません。
**Q5 — 不完全/回復済み入力:** 承認済み A は必要な inventory、mapping、semantic relation、dependency、互換 encoding に欠落/曖昧/未対応があれば、対象 product 全体を公開せず、部分 vector を完全としません。真正な完全空 product は有効です。代案 B は family/scope 単位の completeness と承認済み unavailable marker を公開し、回復 buffer の有効 family を残します。最小の失敗処理として A を推奨します。B は IDE 可用性を高めますが、正確な分割/marker と family 間依存規則が必要です。対象は新 product だけで、既存 diagnostics や独立 metadata reader を変更せず、新 public diagnostic code も選びません。completeness は宣言した product scope に限り、proof/native payload や module 全体の acceptance credit を意味しません。
読出しは metadata reader の [freshness 規則](../en/metadata.md#snapshot-association-and-freshness) を通じ既存 snapshot association/currentness を再利用し、snapshot owner が権威を持ちます。一回の読出しで一つの original source/dependency set を保持し、新 local alias と旧 summary を混ぜません。stale な公開事実は明示 stale として original 座標を保持し、欠落事実は unavailable であり成功した空 surface ではありません。構文 recovery や等しい build id は current semantic metadata を作りません。SourceId/provenance encoding、source loading、scheduling policy を追加しません。
