# コード補完
canonical English: [英語仕様](../en/completion.md)。
所有者: [lsp計画](00.crate_plan.md)。

## 責任と入力

[lsp計画](00.crate_plan.md)の Task25 に従い、現在の開いている
バッファと、一つの保持された[公開データ](../en/metadata.md#published-inputs)から
`textDocument/completion` に応答する。通常経路は構文候補を返し、メタデータホスト
経路は利用可能な所有者生成の記号、表記、ラベル、名前空間アクセスパスを追加する。
要求時にビルド、名前解決、AST/IR 走査、証明探索を実行しない。

## 文脈と候補

生テキストの UTF-16 位置を検証し、CRLF を一改行として扱い、サロゲートの分割を
拒否する。既存の字句前処理で現在の接頭部分を読み、コメントや文字列内では補完しない。
最後のセミコロン以後の有効トークン中に `by` があれば、コンマ区切りを含め引用を選ぶ。
それ以外は直前のトークンで選ぶ。`be`、`being`、`->`、`qua` は型（`object`、`set`）、
`holds`、`that`、`not`、`and`、`or`、`implies`、`iff`、`:` は論理式（`ex`、`for`、`not`）、
`=`、`:=`、`equals` は項（`the`）を選ぶ。他の未完成式位置では項と論理式の種類の和を候補とできる。不確かな宣言位置には
構文上根拠のあるキーワードだけを返す。型の適用可能性や名前解決の成功を保証しない。

記述された接頭辞で絞り込む。ドット付きアクセスには公開された次の名前空間要素または
末端名を示し、最後のドット以降だけを挿入する。型には mode/structure/attribute、
項には functor/constructor/selector、論理式には predicate/attribute を用いる。
別名は公開された表記の種類と関係を保ち、意味を推測しない。引用候補は公開された定理・
定義ラベルであり ATP の前提候補ではない。未公開の private や証明内ラベルは利用不可である。ローカル宣言は認証された宣言完了境界で有効に
なる。import の公開範囲と別名パスは resolver ビューから取得する。欠けた生成物は利用不可
のままとする。独立した operator イベントは有効化後の表記情報を更新するが記号は増やさない。
異なるオーバーロードと表記片、正確なアリティ、供給されたシグネチャと状態を保持する。

## 鮮度と決定的な応答

既存の[スナップショット鮮度](../en/snapshot.md#freshness-and-replacement)を用いる。
構文には現在のバッファを用いる。意味候補の有効化位置には保持された元ソースの同じカーソル
位置を用い、その位置が無効なら意味候補を省く。stale 候補には `stale_artifact`、元 URI と
バージョンを明記し、位置が元ソースを指すことを示す。`textEdit`、追加編集、現在のバッファの
範囲は返さない。無効・利用不可のメタデータで独立した構文候補を消したり pending を作らない。

接頭辞の完全一致を優先し、次にローカル、import、キーワードの順、続いて表記と正規の同一性で
順位付けする。オーバーロードの同順位も決定的に処理し、同一候補だけを重複排除する。
対応する `sortText` と通常のプレーンテキスト挿入を返す。繰り返し要求や入力順序の変更でも
順序と項目を一定に保つ。閉じた文書と終了状態では既存のライフサイクル規則に従って候補を返さない。

## テスト設計

群別マトリクスは契約が所有する。表記と import には実際の frontend/resolver ビューを、
ホスト鮮度には実際に選択されたスナップショットを使う。native 公開の適格性は変えない。
フレーム付き stdio で capability と構文フォールバックを確認する。§23.6 または SCA-003 の
監査完了クレジットは追加しない。
