## Producer profile and ownership

Parser owns whether a correction is justified and its exact token boundary; Frontend preserves that typed evidence through [diagnostic merging](../../mizar-frontend/en/orchestration.md#diagnostic-merge-order). Diagnostics owns shared payload construction, shape validation, canonical identity and aggregation. Driver's [real frontend service](../../mizar-driver/en/frontend_adapter.md#disk-frontend-service) binds original loaded sources and transfers genuine phase output, never derives edits from messages. The publication host owns immutable retention, store installation and approved deferred registrations; LSP only consumes them. These are responsibilities, not new public types or an external schema.
**Q1 — first genuine producer:** proposed A supports only the parser's existing missing-export-semicolon-before-next-item site: a syntactically complete export path/list followed by a recognized next item, with a parser-authenticated insertion boundary. [Export grammar](../../../spec/en/12.modules_and_namespaces.md#124-export-statements) requires `;`; `ModuleParser::diagnose_missing_semicolon` already emits `MissingSemicolon`, adopted as E0041, and `module/tests/parser_diagnoses.rs::parser_diagnoses_missing_export_semicolon_before_next_item` preserves that intent. Attach a proposed advisory `MaybeIncorrect`/`LocalTextEdit` insertion of `;`, never delete or replace the next token. The edit is an empty native range at the mapped boundary with explicit expected text `""`; retain the next-token diagnostic span separately. Other sites, EOF, malformed paths and ambiguous recovery receive no fix from this profile. Alternative B commissions a successful-build advisory diagnostic profile with its owning phase, existing approved diagnostic meaning and exact correction evidence; no such concrete profile is claimed here. Recommend A as a bounded attachment proposal using existing syntax intent, subject to Q3: it cannot reach the current full-snapshot consumers. B preserves their publication route but needs a separate concrete producer definition before implementation. Neither is approved, and a recovery message alone proves no safe insertion site.
For A, propose one `DiagnosticContext` handle on the same E0041 draft, subject `Diagnostic` with the containing code and exact stable detail key; bind `required_snapshot` to the producing snapshot. Its content explains the missing terminator and the authenticated insertion boundary, not a type/proof trace or a claim that the corrected module will verify. A parser-local typed correction must survive Frontend conversion to original source coordinates; extending that handoff is future producer work, not permission to reconstruct a correction in LSP or infer it from E0041 alone.

## Backing content and identity

**Q2 — bounded backing profile:** proposed A uses retained `CacheRecord` backing with a producer-owned encoding key `mizar-frontend/export-semicolon-context/v1`. Proposed exact content is artifact-owner canonical JSON UTF-8 of the object with keys `category` = `syntax.missing_semicolon`, `site` = `export-before-item`, `expected` = `;`, and `insertion_offset` = the original loaded-source byte offset (nonnegative integer). No source id, URI, localized wording or arbitrary trace enters these bytes; source identity belongs to the authenticated diagnostic/publication association. Return the same bytes as `StructuredText` payload text; use that same canonical object as the bounded summary descriptor, with the distinct approved `content`/`summary` hash roles. Producer validation checks the complete object, exact handle/source association, payload text/format/truncation and both role encodings; a localized preview is independent. Alternative B stores a versioned artifact-backed context through an approved artifact writer/reader and uses its store hash. Recommend A for a small context that needs no artifact from an erroneous module; B offers durable replay but requires artifact schema/publication ownership before use. A is retained query backing, not a persistent cache format or a new hash domain. No parser/storage codec is implicitly extended by approval of this document.
Under A, apply the already-approved [backing domains](code_action_validators.md#hash-domains-and-inputs): `CacheRecord.content_hash` hashes exact content bytes; `summary_hash` hashes exact descriptor bytes, each framed with its role and encoding. The cache key is a deterministic producer-local context key, never a file path or proof identity; the store registration is for the exact canonical handle. No `required_artifact_hash` is invented for this non-artifact profile. If a later producer consumes artifacts/missing facts, it must supply every manifest-reachable dependency and the owner-authenticated obligation/entry selector under the existing validators; A grants no such support.
Assign explicit stable producer keys for the insertion fix, context handle and any Q4 command before aggregation, using deterministic producer-local occurrence identity rather than publication ordinals or human text. Repeated sites and reordered diagnostics must retain the Diagnostics canonical fix/handle deduplication rules; changed edit, source, subject or backing preconditions cannot reuse an old association as authority. Identical ids on different diagnostics are resolved within their own records. Equal bytes or one attached handle never establish a fix-to-handle relation.

## Publication and host handoff

**Q3 — host eligibility and handoff:** Driver publishes a coherent full snapshot only for `BuildSessionOutcome::Succeeded` with completed outputs and committed manifests; the E0041 frontend path instead finishes recoverable/fatal without the required output. [Diagnostic overlays](diagnostics.md#unsaved-text-overlays) are separate, and existing action/explain/deferred-registration hosts select only the full `lsp_snapshot`. Attaching Q1-A payloads therefore cannot reach those consumers. Proposed A preserves that route and parks E0041 host activation; a separate concrete successful-build producer definition under Q1-B is required. Alternative B requires a separate owner-approved definition of a ranged diagnostic-publication/host-input adapter for source-error sessions, with genuine original-source retention and backing authentication, while preserving success-only semantic/artifact publication and all existing consumer validation. Recommend B only if the owner chooses the concrete E0041 profile for Task39; it adds a prerequisite definition outside this producer-only unit, not permission to implement or widen consumers here. A avoids that boundary change but cannot activate Q1-A. Approval must select a compatible producer/route pair; no currently eligible native payload route is claimed, and no error is downgraded or failed module published as successful.
Once an eligible route is separately approved and implemented, retain immutable producer output with its exact diagnostic aggregation/publication: original-source binding, canonical fixes/handles, bounded store payloads and explicit fix-to-backing associations. Join producer draft identities through actual canonical aggregation records, never ordinal/title/code-span guesses. A full-snapshot host populates the **existing approved Q3-A** `register_deferred_fix` carrier with the exact publication/diagnostic/canonical fix and every consumed backing dependency. Any separately proposed ranged adapter must define equivalent authenticated admission in its own contract; it cannot pretend to be an existing full publication. No new serialized phase product or alternative Task38 carrier is selected here.
For the existing full route, the [snapshot owner](snapshot.md#source-association) supplies the original capture, text/maps, URI/version/incarnation and non-reused process-local publication identity. Retain the matching store with that publication for the existing [retained-read lifetime](snapshot.md#currentness-and-retention); never attach an old store to a new equal-id build. Publish a complete supported association before exposing its action; unavailable backing cannot be repaired by host-generated content or LSP compiler replay. Dropping a publication follows existing retention, with no new eviction budget or global mutable store policy. No serialized SourceId or parked OpenBuffer provenance/storage choice is defined.
**Q4 — native action surface:** conditional on an eligible Q3 route, proposed A delivers the Q1 local edit and bounded `mizar/explain` query, plus a separate `MachineApplicable`/`CommandOnly` explain suggestion on that diagnostic with a fixed producer-owned opaque reference. The host allowlists that exact reference only for reading this handle; it populates content/summary/store/producer validation in the approved registration and reconstructs `mizar.executeDiagnosticCommand` under existing capability, locator, revalidation, cancellation and error rules. There are no edits, text-hash declarations or artifact dependencies on this read-only command. Alternative B initially delivers only the local edit and explanation query, leaving the command filtered for a separately dispatched producer adapter. Recommend A to exercise the already-approved bounded command consumer with genuine data; B reduces the first producer unit but leaves native command evidence deferred. Neither option enables show-VC/reverify, arbitrary operations, automatic edit application or new public diagnostic codes. Local edits retain their existing current-source validation independently of explanation availability.

## Failure and freshness

**Q5 — incomplete producer inputs:** proposed A withholds each unsupported payload independently: without typed correction evidence, omit the fix; without complete valid backing, omit the handle or let its registered store return the existing unavailable outcome; without exact command binding, omit/filter the command. Preserve the diagnostic and any independently valid local fix. Never publish a partial object as authenticated complete content. Alternative B makes this profile's fix/handle/command bundle all-or-none while still preserving the diagnostic. Recommend A to keep diagnostic interpretation and local assistance independent of optional explanation storage; B simplifies bundle admission but loses otherwise valid assistance. This is payload availability only, not a change to error recovery, diagnostic severity/identity allocation, phase status or proof acceptance. Existing missing-payload preview fallback and cancellation remain authoritative; no numeric budget or new response state is selected.
Current host reads must deliver producer content and correctly mapped current action edits. After an edit (including version-only/equal-normalized-text changes), close/reopen or publication replacement, the old action locator cannot resolve or execute as current. While the same publication remains selected after editor invalidation, its retained explanation read keeps original content, URI/version and original-source coordinates with `stale_artifact`. An obsolete requested snapshot or replacement of the selected publication during the query gets `stale_handle`; replacement selects the new publication, never exposes the old payload through the new one. It never remaps old offsets into changed editor text. Native tests must exercise these together on the same genuinely produced payload; diagnostic-only host selection plus a separate typed range fixture is insufficient. Equal build/source hashes do not revive authority; async command reads recheck currentness/cancellation under Task38's existing rules.

## Conditional validation and handoff

| Case | Input and required outcome after approval and implementation |
|---|---|
| 1 | Real source triggers the approved site/profile: producer supplies the exact advisory insertion and matching bounded diagnostic context; unsupported/ambiguous recovery supplies no guessed edit. |
| 2 | Repeated sites, multiple records/fixes, reordered aggregation and shared/changed ids: deterministic canonical payloads and exact producer-to-published binding; no sibling or foreign backing authority. |
| 3 | A genuine original OpenBuffer capture with Unicode in allowed regions, BOM/CRLF normalization and nontrivial preceding lines: only after the selected Q1/Q3 route prerequisites exist, native host returns the actual fix, bounded content and, under Q4-A, resolved/executed explain command; loaded offsets and independent raw UTF-16 expectations agree. |
| 4 | On that same produced payload, edit/version-only change/close-reopen/equal-id replacement: refuse stale actions/commands; same-selected-publication reads retain original content and URI/version/coordinates as stale; obsolete requests or in-flight publication replacement return stale_handle, never old content under a new publication or live remapping. |
| 5 | Missing/wrong encoding, content/summary hash, source/handle/publication association or required artifact dependency: refuse affected payload/authority under Q5; preserve diagnostic, no proof credit; cancellation and missing-host outcomes remain unchanged. |
| 6 | Keep `diagnostics.rs::code_actions`, `explain_tests.rs` typed location checks and `deferred_action_tests.rs` validator fixtures distinct from a real source→phase→Diagnostics→Driver publication→host route; count only the latter for native payload evidence, no non-range or nonterminal-session substitution. |

Owner approval must record Q1–Q5 choices and any semantic clarification before implementation. Q1-A with Q3-B additionally requires the separate ranged-publication/host-adapter definition and its implementation; Q3-A instead requires a concrete successful-build producer definition. Neither dependency is satisfied by this proposal. Separate producer unit(s) then implement the approved typed phase evidence/shared diagnostic attachment and retained backing/handoff, including genuine positive/refusal tests; Q4 determines whether the bounded-command adapter is included. A producer unit cannot claim Task39 completion merely by filling records in a fixture. Muse redispatches Task39 only after all selected producer and route prerequisites pass; Task39 owns the combined positive delivery/stale-location evidence on the actual host route. Executable/global host integration remains with its existing owner; this proposal does not require implementing Tasks25/40/41 or change their parked questions. SCA-003 audit status and §23.6 deferrals remain unchanged; no semantic/native delivery credit is granted by this proposal.
