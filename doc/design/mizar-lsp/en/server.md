# Server lifecycle
Canonical language: English; [Japanese companion](../ja/server.md).
Authority: architecture 12/internal 03 and [LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/).

Existing serde_json decodes minimal JSON-RPC; LSP owns framing/lifecycle/buffers, with no new protocol dependency.
`Server: Default` owns one connection. `handle_message(Value)` returns an
optional response; `document(uri)` borrows its `(i32 version, text)` buffer;
`serve(BufRead, Write)` runs framed traffic and returns the exit code.

Initialize once with object params containing processId (i32/null), rootUri
(string/null) and object capabilities. Unknown capabilities/options are ignored.
Reply with UTF-16 position encoding and openClose/full text sync only. Before
initialization, requests get -32002 and notifications are ignored except exit.
Duplicate initialize and requests after shutdown get -32600; notifications
after shutdown are ignored except exit. Shutdown/exit accept absent/null params;
shutdown replies null without exiting; exit returns 0 after shutdown and 1 otherwise. Unknown
requests get -32601. Invalid envelopes/IDs get -32600, invalid request params
-32602; integer IDs fit i32, string IDs are retained, and valid notifications
never receive responses. Unmatched responses and $/cancelRequest notifications
are ignored; $/ requests get -32601. Request-only methods sent as notifications
are ignored; notification-only methods sent as requests get -32600.
`initialization_params(&self) -> Option<&serde_json::Value>` borrows the complete accepted initialize params, retained in the existing initialization state instead of a boolean. Before successful initialization return None; commit only after all existing validation, preserve the first accepted value through duplicate/failed/post-shutdown/post-exit traffic, and retain exact JSON values for rootUri, capabilities, options and unknown fields. Raw retention changes no protocol response, validation, buffer acceptance or unknown-option interpretation, and performs no URI conversion, filesystem access, settings selection or compiler/currentness/publication operation.

Open requires a new nonempty URI key, string languageId/text and i32 version.
Change requires an open key and a strictly newer i32 version; validate all
events before mutation, apply full texts in order, reject range/rangeLength,
and let an empty event list retain text while advancing version. Close removes
the key. Invalid, duplicate, unknown or stale notifications leave buffers intact.
Buffers retain exact client text; they are not compiler snapshots or artifacts.

Framing requires ASCII HTTP-field CRLF headers, one Content-Length and UTF-8 JSON bytes.
Bound headers to 8 KiB and bodies to 16 MiB before allocation. Content-Type is
optional; accept application/vscode-jsonrpc with utf-8 or legacy utf8 charset.
Complete frames with unsupported type/charset or invalid JSON get -32700/null
and processing continues. Invalid framing, truncation, early EOF and I/O failure
return io errors. Responses use byte lengths and flush without log text.

## Native initialize workspace inputs

`Server::native_workspace_inputs(&self) -> Result<Option<(WorkspaceRoot, Vec<WorkspacePackage>, Lockfile)>, String>` performs explicit caller-invoked metadata acquisition from the first accepted initialize rootUri. Before initialization or for null return Ok(None); never select cwd, parents, rootPath, workspaceFolders or settings as fallback. Protocol validation/responses, retained params and document buffers stay unchanged, including after terminal traffic.
Decode a present string with Session's existing file_path_from_document_uri. Require a decoded absolute path and ordinary directory using standard Path components before the metadata query, then canonicalize and require UTF-8 for the returned WorkspaceRoot. Unsupported URI/path, unavailable or nonordinary root is String Err. Reuse Build read_native_workspace_inputs for the actual parsed member manifests and mandatory lock, returning only the complete existing tuple; propagate acquisition/parser errors without partial success or synthesized metadata.
Each explicit call reacquires metadata; store no root/context and do not read source bodies or allocate IDs. These point-in-time mutable records establish no atomic provenance, effective settings, selected toolchain/dependencies, snapshot, compiler work or current publication. Full native host binding remains separate.
Tests use actual accepted initialize values and real root/nested-member metadata, compare existing parsed coordinates, preserve raw params/documents and unchanged responses, and distinguish null/uninitialized, malformed/non-file URI, missing/file/symlink roots and native-reader failure without fallback. Metadata edits/deletion after a prior call must be observed; do not repeat the existing decoder/parser/protocol matrices.

## Native frontend diagnostic notifications

`Server::submit_native_frontend_diagnostics<A: SessionIdAllocator, L: SourceLayoutProvider>(&self, driver: &mut CompilerDriver, session: BuildSession, allocator: &A, snapshots: &SnapshotRegistry<A>, input: DriverSubmitInput<L>) -> Result<(BuildSubmission, Option<Vec<serde_json::Value>>), DriverSubmitError>` first calls existing submit_captured_with_import_discovery_and_native_diagnostic_index and preserves its normal errors/submission, even when notification eligibility fails. Driver owns captured discovery and supplied-overlay handling; notification, originating and writer callers share this producer. No alternate index/batches/origins/maps are accepted. The profile is explicit all-OpenBuffer lightweight Frontend output, not full build publication.
Require an initialized non-shutdown/non-exited Server, a genuine Some index with no obsolete drafts, and the live native Driver guard before and after conversion. Read the Driver's own stored session/capture native_sources, never registry.get or caller replacement data. Require nonempty all-Open original tuples, unique SourceIds and URI keys, and exact current Server URI/version/raw text equality. Expected/actual versions and loaded maps retain their existing native/mapper validation; no new document-version policy or source reload.
For every original tuple require exactly one actual submission task with kind Frontend, phase list [Frontend] and the same package/module work unit, and exactly one original PhaseResult for that task. Only Complete/Recoverable/Fatal are supported; if that SourceId has no primary diagnostic span in the index, require Complete before calling it clean. Missing graph/run/task/result, ambiguous binding, Blocking/Cancelled or diagnostic-free non-Complete work yields None for the entire set. A nonempty index for one source never establishes evaluation of another source.
Every index record must be Current for that actual snapshot, Frontend phase and a primary span belonging to exactly one captured source; otherwise return None for the entire notification set. Convert through existing lsp_range_from_open_buffer with original loaded LineMap/LoadingMap and original SourceOriginInput, retaining Diagnostics record order per URI. No custom sorting, deduplication or identity allocation. Disk/Generated/mixed origins, Resolver/other phases, unsupported locations/freshness/maps/severity, missing/closed/stale documents or any guard failure yield None, with no partial notifications.
Return one owned JSON-RPC 2.0 textDocument/publishDiagnostics notification per captured URI, ordered by URI, with params.uri, captured i32 document version and diagnostics; clean files have an empty array. Each diagnostic carries the converted range, original code display string/message and Error=1/Warning=2/Info=3 severity; no optional related-information/data/tags or compiler status is invented. Reuse [LSP 3.17 notification](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/language/publishDiagnostics.md) and [Diagnostic](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/types/diagnostic.md) shapes. Existing Diagnostics keeps code/message/identity/aggregation authority.
Tests compose actual accepted initialize/open/change/close messages, existing native indexed association and protected capture, real SourceLoad/Frontend and original index. Compare complete discovered submissions, original diagnostic fields and independently expected raw UTF-16 ranges, including clean clearing and multiple real Open sources; reuse existing real-dispatch NoKey controls. For imports use original editor text with conflicting/unavailable disk bodies, actual lexical dependency ordering, ImportsOnly rather than complete semantic coverage, supplied-overlay preservation and failed-discovery controls; exercise notification/originating/writer delivery and original-incarnation suppression. Distinguish newer same-text versions, changed normalized-equivalent raw text, exact URI aliases with no LoadingMap, stale Driver eligibility and unsupported real origin/phase profiles using viable controls; preserve existing protocol/stdio/producer/mapper tests. With otherwise-current exact tuples, actual denied SourceLoad publication must not turn unexecuted Frontend into clean clearing; denied Frontend for a clean source must withhold the whole set even when another source supplies real diagnostics.
Returned messages establish current raw-tuple equality during this call only, not document lifecycle identity across close/reopen, IR retention, full settings/toolchain/dependency/file freshness, VerifiedArtifact or PublishedLspSnapshot. They are not sent here: later wire handoff must revalidate; executable host/settings/build scheduling/cancellation and complete current diagnostics remain separate. This notification operation does not mutate lifecycle/document state; [open lifetime handles](#open-document-lifetimes) are owned by Server lifecycle.

## Native frontend diagnostic wire

`Server::submit_native_frontend_diagnostics_to_writer<A: SessionIdAllocator, L: SourceLayoutProvider>(&self, driver: &mut CompilerDriver, session: BuildSession, allocator: &A, snapshots: &SnapshotRegistry<A>, input: DriverSubmitInput<L>, output: &mut impl Write) -> Result<(BuildSubmission, io::Result<usize>), DriverSubmitError>` calls the existing notification producer exactly once. Preserve its ordinary submission and structured Driver error; an outer error writes nothing. None eligibility returns the actual submission with inner Ok(0). Accept no alternate messages, diagnostics or capture data.
The same immutable Server borrow spans production and immediate writing, preserving the producer's initialized/terminal state and exact original URI/version/raw-text checks without duplicating them. Before each frame header, after serialization, require validate_current_native_diagnostics for that same stored session and registry. A failed guard stops further frames with inner Ok(number already fully flushed); zero means no frame was sent. Do not reconstruct original raw capture through registry.get, replace the producer's values, or rerun a phase.
Encode each original notification as UTF-8 JSON, write Content-Length in bytes with CRLF/CRLF, write the full body and flush, then increment the count. Keep order and all original fields. Inline the existing framing operations; two production uses do not justify a helper. Return the first serialization/header/body/flush error as inner Err while retaining the actual submission; stop immediately and never retry or roll back partial bytes. A callback may invalidate shared publisher/registry state during Write: already begun bytes cannot be revoked, but the next frame must pass a fresh guard. This is handoff-time checking, not atomic currentness or PublishedLspSnapshot.
Tests use three distinct real native consumer families for valid framed error/clean messages and independent byte/range/version facts, supported-control versus withheld/error handoffs, and I/O/partial-delivery/currentness failures. Any private setup helper or Write adapter needs three actual family call sites. Existing notification, protocol, stdio and producer tests stay verbatim. The conditional lightweight Diagnostics consumer is unchanged; automatic host/serve/main activation, full runtime/settings/toolchain/dependencies, scheduler cancellation, IR retention and complete current-build diagnostics remain deferred.

## Open document lifetimes

`Server::document_lifetime(&self, uri: &str) -> Option<std::sync::Weak<()>>` returns a process-local handle for the exact currently open URI on a live connection; return None for absent/closed documents or after shutdown/exit. Store one standard Arc<()> as the third element of each existing private document tuple, created only after accepted didOpen validation; return its downgrade without changing state. Preserve document(uri)'s existing version/text result.
The same open retains the same allocation through accepted didChange, including empty changes; ignored/invalid/duplicate/stale messages do not replace it. didClose removes that entry and reopening creates a fresh allocation even with identical URI/version/text; other documents and Server instances have distinct allocations. Compare a retained handle only with a newly queried handle using Weak::ptr_eq. Neither payload equality, pointer values, strong/weak counts nor upgrade success proves currentness; do not expose a serialized/numeric/hash identity or mint caller-provided handles.
A handle binds only this Server's open incarnation, not its current version/text, a compiler capture, snapshot, diagnostic eligibility, runtime or artifact. Existing notification/wire behavior and all protocol/stdio behavior remain unchanged; [Originating capture/lifetime association](#originating-native-open-buffer-capture) uses the separate explicit route. Three genuine-message families cover repeat/change and multiple documents; identical-tuple close/reopen and Server isolation; ignored/invalid traffic and shutdown/exit with retained raw state. Use existing message helpers and an independent pre-Rust relation trace, without copying complete protocol/native matrices or adding a test adapter/type/helper.

## Originating native open-buffer capture

`NativeOpenBufferCapture` is an LSP-owned envelope with only private original BuildSession and `(String URI, Weak<()>)` entries; no public constructor, fields, Clone, accessor or conversion. Its three operations below create and consume the actual relation, without copying loaded sources, maps or diagnostics or adding Server state.
`Server::capture_native_open_buffers<A: SessionIdAllocator>(&self, draft: BuildRequestDraft, allocator: &A, snapshots: &SnapshotRegistry<A>, index: &ModuleIndex, sources: Vec<(DiskSourceLoader, PackageId, String)>) -> Result<NativeOpenBufferCapture, String>` requires an initialized live Server and a nonempty list of distinct exact URI keys. Read each current document entry once under the same immutable borrow; reject absent/closed documents or negative i32 versions without changing protocol acceptance. Derive OpenBuffer origin from that entry's exact URI/raw text and checked nonnegative i64 version (both expected and actual); take its original Arc downgrade in that same operation. Call existing index.native_open_buffer_input with draft.workspace_root and the explicit package/loader. Validate every requested coordinate before calling draft.capture_sources exactly once; propagate association String errors and render capture errors with Debug into String, with no partial success or synthesized source/context. Store only the resulting original session and original URI/Weak relations; never accept an old capture or caller lifetime/origin. The caller retains actual index/plan, context, allocator/registry and publisher responsibilities.
`submit_originating_native_frontend_diagnostics` has the existing notification signature with NativeOpenBufferCapture replacing BuildSession. Compare every stored handle by Weak::ptr_eq with this Server's fresh document_lifetime for the exact URI. Still invoke the existing notification producer once with the original session, preserving its actual submission/structured Driver error; if any lifetime differs or is unavailable, suppress the complete notification set. Existing current raw version/text, native capture/index/range and Driver guards remain mandatory and unchanged; handle upgrade/count/payload equality grants no authority.
`submit_originating_native_frontend_diagnostics_to_writer` similarly replaces the existing wire session parameter with the envelope. With the same immutable Server borrow, eligible lifetimes delegate once to the original wire operation; ineligible lifetimes call the original notification operation once solely to preserve its submission/error, discard messages and return inner Ok(0) without touching the writer. Preserve existing per-frame Driver guard, exact bytes/order/flush, partial-count and I/O behavior; no retry, rollback or duplicated framing pipeline. Same open changes retain incarnation but still need the original raw tuple checks; identical-tuple reopen and another Server never inherit the capture's relation.
Tests use genuine accepted messages and explicit native coordinates through actual capture/SourceLoad/Frontend, with independent origin/version/raw UTF-16 facts and complete ordinary submission comparison. Distinguish same-incarnation success from otherwise-identical reopen/cross-Server suppression, show the old raw-tuple API still succeeds in those viable controls, and keep stale version/raw/closed/terminal, invalid source acquisition, Driver guard/error and writer failure behavior. Reuse existing native test setup and writer; any new setup helper requires three actual families. Keep all old tests and production functions verbatim; no fabricated envelope, capture, diagnostic, cache Hit or acceptance result.
This boundary authenticates only the originating open incarnation of the actual explicit capture. Full configuration/toolchain/dependency/file freshness, coherent LspSnapshot, runtime/host scheduling/cancellation, IR retention and atomic currentness through external Write remain separate; notification/wire returns do not complete ENTRY, SCA-003 or the roadmap gates.
