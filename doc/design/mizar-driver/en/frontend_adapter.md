# Source Services

> Canonical language: English. [Japanese companion](../ja/frontend_adapter.md).

## Disk SourceLoad service

`PhaseRegistryBuilder::register_source_load()` registers the real disk-only service named `SourceLoad`, owned by `mizar-frontend`, covering only `PipelinePhase::SourceLoad`. The zero-argument registration method fixes the single-phase descriptor/catalog identity without exposing a second public service type. Frontend is registered separately under [Disk Frontend service](#disk-frontend-service); SourceLoad does not run later phases.
`SourceLoadInputs<'a>` borrows the captured `BuildSnapshot`, `BuildPlan`, `ModuleIndex`, and caller `SessionIdAllocator`. `PhaseExecutionResources<'a>` and `PhaseExecutionContext<'a>` carry optional source inputs; real submission wires them into the scheduler dispatcher. This transport remains dormant under the default graph while later services are missing; A5 validates execution directly through the registry, without a new graph/profile. No allocator or payload is captured in the registered service.

## Binding and execution

Require a module work unit and exactly one matching disk SourceVersion, workspace package plan, package index entry, and workspace module entry. Match package/module/path/edition, package root/source root/manifest, and snapshot/workspace root across owners; reject duplicate or conflicting entries. The module source-relative path must agree with its package-relative path and source root. Reject unsafe workspace-relative plan roots rather than resolving them outside the captured workspace.
Canonical package roots must remain inside the canonical captured workspace; use the bound canonical root for loading. Unavailable roots still reach the loader for its real diagnostics, but successful publication requires proven root containment.
Derive a Disk SourceInput from the captured typed normalized path and source metadata. Resolve the package root from the captured workspace and workspace package plan; let the session loader own filesystem canonicalization and source acceptance.
The dispatch input hash must equal the SourceUnitCacheKey for the captured version; SourceLoad consumes no output parents or dependency hashes. Missing owner dispatch identities remain blocked; this service does not invent planner output handles.
Require a current supplied publisher and an empty, unsealed diagnostic sink scoped to SourceLoad and the same snapshot. Missing/mismatched resources, invalid bindings/identities, publication failure, or source changes after capture return Blocking without output. A successful load whose hash differs from the captured version is rejected as an obsolete dispatch result under architecture 22, not classified as a loader failure or assigned a new E0600 cause. A matching cancellation token returns Cancelled; a foreign token returns Blocking.
Call `FrontendSourceLoader<DiskSourceLoader>::load_source_unit` with the caller allocator. Validate loaded metadata, Disk origin and normalized text hash against the captured version. Use the disk codec to rebind the actual loaded payload/maps to the captured SourceId, then publish it through the supplied publisher. The service never registers/revives publisher snapshots or grants work-unit permission.
Use the [frontend-owned publication representation](../../mizar-frontend/en/source.md#sourceunit-publication). Decoder closures capture current request metadata, SourceId and the bound SourceUnit for [canonical storage comparison](../../mizar-frontend/en/source.md#current-source-storage-comparison); they decode bytes without reloading or reparsing a file.
Return Complete with the actual sealed output only after successful publication. The [scheduled prefix](./driver.md#scheduled-sourceloadfrontend-prefix) can run before missing later services; it does not complete the full build.

## Diagnostics and cache boundary

Real loader errors emit validated shared drafts with the request's package/path location, SourceLoad phase/category, current snapshot, and no fabricated range, then return Fatal without output. Map InvalidUtf8 to E0601, UnreadableSourceFile to E0602, and SourcePathOutsidePackageRoot to E0603. For E0601–E0603, use the allocated semantic name as the stable detail key. Other variants map to E0600, with stable detail keys `source.` plus the variant name in snake_case; unknown future variants remain an unsupported integration gap and return Blocking without a fabricated diagnostic. Message text is display-only. Failure to construct/emit a draft returns Blocking.
`cache_key` returns NoKey: normalized source hashes cannot prove that cached raw loading maps match the current file. Every execution loads the real source. The codec supports storage placement, not cache-hit scheduling or cross-snapshot reuse credit.

Exercise real invalid UTF-8, deleted/unreadable files, symlink escape where supported, and allocator failure through the shared diagnostic sink. Preserve absent later-service blocking and existing registry tests.
The real Frontend service below consumes frontend-owned preprocessing, lexing, parsing, recovery and aggregate storage. Cache compatibility, LSP conversion, artifact publication and later semantic/proof phases stay with their existing owners.

## Dependency lexical provider

The provider consumes `mizar-resolve`; `mizar-artifact` is a production dependency for the canonical identity and lexical payload APIs used by supplied source leaves. The exact dependency-boundary lint admits these owner seams only; artifact publication authority stays outside the driver.

implementation of the actual frontend `LexicalSummaryProvider` contract. Roots
are borrowed `(PackageId, PathBuf)` bindings supplied by the caller; no registry
installation path is guessed and no root is retained in a new public resource.
The caller supplies a build-validated module index and stubs from the source
version represented by the request SourceId; the request carries no source hash.
Require exactly one captured source for that SourceId, matching request and
indexed module editions, and matching indexed package/module metadata.
Map stubs with the resolver's provisional frontend mapper and resolve paths
through its existing index-backed import resolver. This is not AST import validation.
For each resolved dependency target, require matching module/reference artifact
path and hash plus a unique explicit root. Read through the build-owned indexed
summary reader, then the resolver's canonical lexical-summary consumer.
Successful entries retain the summary's full artifact module identity, with the
original stub ordinal/span. Each successful `ResolvedImportEntry.import.module_id`
must equal the A15 `ModuleLexicalSummary.module_id` exactly. Duplicate imports remain in provenance; frontend
canonicalization owns their active-environment deduplication.
A file-read rejection retains a resolved entry but no summary, so the frontend
owns its existing `MissingSummary` recovery. Its diagnostic-only module ID is
`format!("{:?}:{:?}", package_id, module_path)` over the indexed string parts;
it asserts only known package/path identity and never reaches the lexer.
Unresolved paths remain absent for existing `UnresolvedImport` recovery.
Malformed request/index/root bindings, unsupported source-backed targets, or a
rejected lexical payload return `ProviderUnavailable`, without partial output.
No empty source summary is fabricated. Existing frontend environment assembly owns conflict recovery. The real service below owns shared diagnostic conversion and IR publication; complete source export producers and current-build lock/cache/proof acceptance remain outside this provider.

## Disk Frontend service

`register_frontend(artifact_roots: Vec<(PackageId, PathBuf)>)` registers a real Frontend-only service with explicit owned dependency roots; no paths are guessed and no execution-resource type is added. It borrows captured SourceLoadInputs and uses the frontend-owned [publication representation](../../mizar-frontend/en/orchestration.md#frontendoutput-publication). Later services remain unavailable; registration does not complete the whole driver graph.
Require the same current snapshot/workspace and unique matching disk source/version, workspace package/index/module metadata as SourceLoad. Require one own current SourceLoad/SourceUnit/schema-1 sealed parent for the same work unit, plus only the [supplied leaf parents](#supplied-workspace-leaf-summaries) allowed below, validate publisher/storage, recover its typed SourceUnit and verify identity, package/module/path/edition/hash plus canonical disk metadata. Do not reload the source or allocate another SourceId.
Before execution, each indexed DependencySummary must agree with exactly one dependency_summaries entry for its module and exactly one captured snapshot artifact ref with the same `(artifact string, content_hash)` pair. Every dependency_summaries entry must have its matching indexed module and captured ref. Missing, duplicate exact-pair or mismatched refs block; same relative spelling with different hashes is allowed, and unrelated snapshot refs confer no authorization. Callers capture exact module-summary path spellings; the service invents no package namespace.
The dispatch input hash equals SourceUnitCacheKey for the captured version. Dependency hashes equal the sorted multiset of all DependencySummary content hashes in the captured module index. Parent hashes come from the sealed bundle. `cache_key` returns NoKey; query identities grant no cache reuse and do not establish dependency file availability.
Require an empty unsealed Frontend sink in the same snapshot and a current supplied publisher. Scheduler dispatch creates this sink for Frontend. Matching cancellation returns Cancelled; foreign cancellation, invalid resources/binding/identities or provider/span/conversion/publication failure returns Blocking without output. Never create missing resources or revive publisher snapshots.
Use the real dependency lexical provider and MizarParserSeam through `run_loaded`. Convert the complete diagnostic vector before mutating the sink. Some AST with diagnostics returns Recoverable; absent AST with diagnostics returns Fatal; neither publishes output. Absent AST without diagnostics, a present AST without its key, or undiagnosed recovery nodes are integration failures and return Blocking without inventing E0052. Only Some AST with no diagnostics/recovery publishes Complete.
For conversion, apply the frontend-owned exact code/class mapping from specification 22.2.3; never inspect message text. Shared phase is Frontend (the actual coordinator), category ParseError, stable_detail_key is the descriptor semantic name; `frontend.class` is the local class name in snake_case; `frontend.code` is its typed enum path in snake_case joined by dots (Syntax uses `syntax.` plus the exact key). These structured strings retain local distinctions for identity. Preserve source order before existing shared aggregation.
Class compatibility is lexical-precondition for source preconditions except unterminated comments (comment-structure), import-prescan for import/raw-import scans, lexical-environment for environment codes, scope-skeleton for scope codes, tokenization for raw-scan/lexer codes, and syntax or annotation-syntax for known parser keys. SourceLoad entries, unknown code/class variants or parser strings, and incompatible code/class pairs fail the entire conversion. Validate every primary range and secondary anchor projection against the owning loaded source identity/text, including ordered bounds, length and UTF-8 endpoints. Use lossless shared anchors with unspecified intent, retain message and generated reasons exactly, and preserve secondary order/multiplicity. Recovery None produces no note; Some text produces one Note even when empty. No source binding is inferred merely from successful storage decoding.
Tests exercise actual clean/imported and failed pipelines, blob roundtrip, current parent/lineage and hash separation, every mapping, unknown/malformed inputs, anchor/intent preservation, empty notes and atomic conversion failure. Use actual emitting producers where available, with typed retained fixtures for reserved/pass-through categories; do not claim producer availability from those fixtures. Full-build and later-phase acceptance remain deferred.

## Diagnostic-only import continuation design

The resolver’s [source-bound import producer](../../mizar-resolve/en/imports.md#parsed-import-candidates) owns parsed/prescan/source correspondence and path resolution for the supplied-parent, diagnostic-only and clean-importer routes. Driver admission, sealed currentness, publication and diagnostic conversion remain unchanged.

The restricted route follows [specification 22.3.5](../../../spec/en/22.error_handling_and_diagnostics.md#diagnostic-only-continuation-after-lexical-import-failure). Frontend owns the original live aggregate and diagnostic conversion; IR owns sealed storage/lineage; driver owns currentness, cancellation and restricted invocation; resolver owns AST candidate validation and typed path failures. It is not a normal successful Frontend phase output or a workspace summary provider.
The restricted route keeps the live `FrontendOutput<SurfaceAst>` inside `FrontendService::execute` after `run_loaded`; it never publishes the failed output or decodes it later. The existing SourceLoad parent, captured source version/index, dispatch identity and current publisher bind this output to the same loaded source. After complete frontend diagnostic conversion, admit only a nonempty exact E0022/code-class vector, present AST and producer key, no recovery/error nodes or flags, and a structurally complete top-level import prelude from `ImportPathCandidate::from_surface_ast`. Require nonempty candidates; crosscheck their complete ordered count, prefix/components, alias spelling/span and branch base/member spans against the live preprocessing stubs. Direct candidate and stub spans must agree; for branches the AST declaration span contains the prescan member span. Validate all retained ranges and each represented import token text, including framing, against the same loaded source. The stubs crosscheck completeness, never independently authorize semantic paths. Reject any omission, extra candidate, spelling or span mismatch. Resolve only path/alias facts through `ImportPathResolver` with `ModuleIndexInput` over the captured index. No graph or summary input is inferred.
Convert the entire typed path-failure vector privately within the driver Frontend service; only E0220–E0224 classes map to Resolver-phase drafts, and any unallocated class rejects the semantic batch. Validate source bindings, ranges, UTF-8 boundaries, anchors, class/code mapping and stable details before emitting to a separate Resolver sink. Failed semantic conversion discards only that batch, preserving the validated Frontend batch. Invocation cancellation is checked before work and its token is immutable during the call; recheck publisher/parent currentness before analysis and before returning either batch. Later scheduler cancellation and lane guards suppress cancelled or superseded reporting. Return `Recoverable` with empty output refs, carrying the Frontend batch and optional Resolver batch in existing `PhaseResult.diagnostics`. The registry still attaches its query observation; `NoKey` grants no cache reuse or success credit. The scheduler still fails this task and skips normal dependents. No new output type, registry resource, durable failed-output handle or Recoverable-to-Complete mapping is needed.
The live Frontend service performs source-bound E0220–E0224 conversion on this restricted route. The [scheduled prefix](./driver.md#scheduled-sourceloadfrontend-prefix) exposes this route through `CompilerDriver::submit` while preserving the failed session and blocking normal dependents. E0225 and complete workspace summaries remain deferred.

Import draft detail keys are `import.source_module` (String list `[package, path]`), `import.ordinal` (Integer), `import.path` (resolver spelling String), and `import.branch_member` (Source range, only for branches). E0223 additionally carries `import.alias` (String) and `import.target` (String list `[package, path]`). Use the registry semantic name as stable detail key, Resolver phase and ResolveError category. Primary and secondary ranges follow specification 22.3.5 with unspecified anchor intent; this schema gives distinct candidate identity to shared aggregation.
