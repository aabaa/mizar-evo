## Existing producers and missing consumer

[Proof original-graph checking](../../mizar-proof/en/status.md#source-theorem-reflexivity-original-graph) returns actual Core/VC graphs and Kernel result/policy decision. [Genuine status](../../mizar-proof/en/status.md#source-theorem-reflexivity-status-projection), [trusted used_axioms](../../mizar-proof/en/status.md#source-theorem-reflexivity-status-with-used-axioms), and [source FILE production](../../mizar-proof/en/status.md#source-theorem-witness-file-candidate) are separate existing facades, not a combined Driver receipt. They preserve explicit BuiltinDischarge origin, DischargedBuiltin class and the incomplete dependency slice/mandatory MISS.
M1.3 already supports matching [FILE staging](../../mizar-proof/en/witness_store.md#explicit-source-theorem-file-staging), [built-in main profile](../../mizar-artifact/en/verified_artifact.md#explicit-built-in-enclosing-profile), committed readers and [witness publication](../../mizar-proof/en/witness_store.md#publication-references). Their existence does not register a native service or prove its currentness.
The old Driver91 wrapper is [retired](frontend_adapter.md#native-theorem-reflexivity-core-vc-caller). The [registered candidate-check service](frontend_adapter.md#scheduled-source-theorem-candidate-check) consumes the separate ATP candidate route. `candidate.rs` requires KernelVerified for candidate FILE production; `artifact.rs` uses AtpFormulaSubstitution origin and requires KernelVerified in its accepted projection. Removing those guards or relabeling DischargedBuiltin would cross their frozen boundary.
The missing edge is producer-owned genuine reflexivity evidence/status carried through a real, freshly authorized KernelCheck service. M1.4 integration and M1.5 full emission remain open; no coverage or milestone credit is granted.

The raw [Core/VC handoff](frontend_adapter.md#native-theorem-kernel-handoff-core-vc-caller) supplies source-admission/lineage constraints, not acceptance. A new caller must use genuine Proof reflexivity production; raw handoff/default discharge success cannot replace it.
Before publication, validate unique exact phase/kind parent roles, snapshot/module/input/dependency identities, physical retention and publisher authorization; repeat live guards after lower work. Bind status to actual goal/context/polarity/evidence/policy/trusted used_axioms. Select BuiltinDischarge origin before checking, never infer it from success. Preserve upstream refusal/error ordering; distinguish unsupported input, rejected/open proof and resource/internal failure without new public diagnostics.
Publish only after actual Kernel and existing policy acceptance. Original Pending/Active/Open graphs stay original; accepted bounded proof does not complete its slice, enable reuse/cache hits, discharge other obligations or make a session verified. Task Complete means transport success only. Cancellation, stale lane, source changes admitted as a superseding snapshot/lane association, collected parents or superseded publisher prevent new publication under existing point checks; frozen capture does not recheck disk edits/removal. Retained past payload/read tokens grant no live authority.
Drafts, structurally readable FILEs and hashes are not committed witnesses. Future FILE/main/manifest consumers must use M1.3's matching class/identity/policy/evidence/staged-reference and reachability checks. Preserve selected-witness-hash absence, generic/state built-in gaps, mandatory MISS and existing caller-expected-snapshot/retained-token limits; no new cross-edit or transferable receipt guarantee.

## Owner Q-decisions

**Q1 — registration and graph route.** A: an explicit opt-in genuine-reflexivity KernelCheck profile with genuine Core/VC/source-check prerequisites and no fictitious AtpSolve/BackendRun or normal candidate parent. B: extend candidate-check with an explicit tagged built-in alternative and disjoint parent/input validation. **Recommend A:** preserve the normal ATP route and make profile confusion fail closed. B reduces registrations but expands its accepted-input boundary. Either needs reviewed exact descriptor, output kind, graph prerequisites and default-input rules; old service counts must not silently authorize it.

**Q2 — joining Kernel result and status.** A: a bounded Proof-owned composition returns actual original graphs, Kernel result/decision and corresponding status/full slice/trusted used_axioms from the same genuine evaluation, using existing owned values. B: Driver calls existing separate facades and validates their complete original-graph/identity/policy/evidence association. **Recommend A:** same-result guarantees stay with the semantic producer, avoiding duplicated Driver selection/status logic. The combined surface does not exist: a reviewed Proof prerequisite must define its exact API/errors without a new public semantic model. B avoids that entry point but needs an explicit replay/equality contract; hashes alone are insufficient. Neither admits caller-authored acceptance or moves Kernel checking into Driver.

**Q3 — first implementation scope.** A: end M1.4's first slice at fresh sealed Kernel/status output; separately contract the genuine FILE/Artifact service consumer using M1.3 producers. B: include both Kernel/status and witness/Artifact service adaptation in one implementation contract. **Recommend A:** isolate the missing boundary and require its genuine source E2E before emission integration. A does not satisfy the committed-artifact M1 target; B needs a larger staging/commit/readback matrix. Neither weakens normal KernelVerified guards or claims full Artifact17 emission.

**Q4 — refusal and ATP fallback.** A: return this route's existing unsupported/open/rejected/error outcome without automatic ATP fallback. B: explicitly route refusal to the separate normal ATP profile, with real candidate/check prerequisites and preserved origin/status. **Recommend A:** bound the backend-free service and refusal causality. B needs separately approved scheduling/failure composition before implementation. Both use effective policy unchanged; disabled built-ins cannot be retried under weaker policy, and backend success never supplies acceptance.

**Q5 — status exposure.** A: internal typed sealed service data only, retaining existing task/event meanings; CLI/LSP/public status schema changes are deferred. B: also expose distinct built-in proof status in a versioned public Driver result/event surface. **Recommend A:** establish the producer handoff without a new presentation compatibility contract. B needs event/schema, consumer and stale-publication rules in its implementation contract. Neither treats task/session completion as proof acceptance or retained data as current publication.
