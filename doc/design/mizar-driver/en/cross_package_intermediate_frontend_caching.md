## Exact admission delta

Q1-A adds exactly three distinct captured clean AST-bearing native Disk modules I=app/main→M=app/mid→A=core/base: I/M share one workspace package, A belongs to a distinct second package, and A is import-free. Names illustrate the existing producer; eligibility is this topology, not literal spelling. Each edge has exactly its stated distinct target, with repeated imports retaining ordinal/span/alias/branch provenance. Both packages must be uniquely bound to the accepted plan/index and complete captured overlay. Extra unrelated workspace modules do not join the closure.
Preserve existing zero-/direct-leaf and same-package intermediate routes. Cross-package direct-leaf M remains independently eligible under its existing route. General package placement, branches/depth, cycles/self-imports, artifact dependencies, reexports, Open/Generated, diagnostics/recovery, missing AST or unavailable lexical contributions refuse this optimization without trimming members; ordinary execution retains its existing results and errors.
At each edge consume only complete A13 direct local public exports, including genuine complete-empty summaries. A's symbols may affect M's tokens but never become implicitly I-visible. Keep direct physical lineage A←A SourceLoad, M←M SourceLoad+A Frontend, I←I SourceLoad+M Frontend; PackageResolve remains a scheduling prerequisite. Retaining/authenticating ancestors adds no I payload parents or semantic export authority.

## Per-package authentication and independent expectations

Q2-A adapts the approved [bottom-up algorithm](intermediate_workspace_frontend_caching.md#ancestor-authentication-and-independent-cold-expectations), never treating CurrentPackage authorization as evidence that all modules share a package. Authenticate both graph edges against exact accepted graph/results, parsed/prescanned resolved imports, complete overlay and protected captured source entries. Reject missing/surplus/duplicate/swapped/foreign/stale/collected associations before sorting, even when local paths, source bytes or export fingerprints coincide.
For each I/M/A select its own unique workspace PackagePlan and PackageIndexEntry; validate package/module, matching version/edition, safe member/root/source-root/manifest paths, captured Disk SourceVersion/SourceUnit identity/hash/path/edition and exact SourceLoad key/storage/maps. The app metadata cannot substitute for core's metadata. Each consumed A/M ModuleSummaryIdentity uses its target's package version and edition with full canonical module identity and owner-ordered ExportedSymbolShape bytes; workspace summary lockfile_identity stays None. No release, lock attestation or new edition-compatibility rule follows.
Preserve each module's complete Frontend keys, source/raw storage, semantic bytes, side tables and named inputs. Package-specific effective verifier/build settings remain associated with their own package in Build's independent aggregates, authenticated by existing [config content](frontend_adapter.md#native-config-content-association) checks; use the existing [shared lock content](frontend_adapter.md#native-lock-content-association) binding for the workspace. Do not invent per-package lock digests, replace core settings with app defaults or infer policy from configuration. Existing policy/toolchain/schema/runtime inputs remain mandatory.
Independently run full A analysis from its captured source with no summaries, derive A's local A13 summary, run M with exactly that summary, derive M's local summary, then run I with exactly M's summary, each under its own captured package context. Expected keys/tokens/storage/maps/sides/named inputs must not come from Store or retained A/M/I Frontend outputs. Compare every accepted A/M payload completely against its independent result before using it as cache evidence. Validate genuine I output against independent I expectations for both lookup reconstruction and persistence.
Use the actual bound parser/provider in independent and scheduled runs; retain bootstrap descriptor/provider association and participating running-image residency checks. Copied metadata/equal hashes do not prove association. Missing mapping or evidence refuses optimization. Analysis may repeat on misses; scheduler skipping on CacheHit does not establish avoided parsing.

Valid core version/edition/config changes with I/M source bytes fixed must miss or refuse according to existing compatibility rules; shared-lock changes follow existing whole-workspace footprints. SourceId/task/worker/capture/completion order, output slots, Store roots and retention are not new semantic inputs. Unmapped consumed inputs or required public compatibility changes return to owner; do not silently use empty/zero substitutes or activate v2 on incomplete mapping.

Retain the entire closure through independent analysis, lookup/decode, scheduler acceptance/consumption and final validation. Release partial acquisitions and all owners on success/miss/refusal, Store/decode/scheduler error, cancellation and supersession. No new public seam, schema or transitive-retention API is proposed.
