## Existing coverage and definition gap

The [supplied-summary authenticator](frontend_adapter.md#supplied-workspace-leaf-summaries) already visits plural physical Frontend parents and returns target-associated summaries for ordinary execution. Cache admission is narrower: `registry.rs::native_frontend_cache_parents` accepts at most one leaf; `frontend_adapter/source.rs::prepare_native_disk_frontend_cache_payload` requires exactly one summary/leaf source and checks every resolved import against that target. Its private `mizar-driver/native-disk-frontend-dependencies/v1` projection already contains ordered import entries, target-sorted summary entries and phase/work-unit-sorted physical-parent entries. Lists alone do not prove multiple-target admission safe: the missing definition is exact target/summary/Frontend/SourceLoad correspondence and complete lifecycle/testing across all entries.
Driver owns capture/runtime/provider association and orchestration. Build retains graph/index/config/lock and readiness; Frontend owns preprocessing, lexical environments, keys, parsing and storage; Resolver/Artifact retain resolution, A13 exports and summary identity; Cache owns canonical keys, compatibility and Store validation; IR owns reconstruction, physical lineage and retention; Proof owns effective policy, acceptance and reuse. Reuse these owners and existing private paths; no new public context, lower-owner seam or parallel summary representation is approved.

## Proposed authenticated closure

Under Q1-A, extend the existing zero-/one-leaf routes to any finite set of distinct direct captured workspace targets, each a clean AST-bearing import-free Disk leaf without reexports; the importer is likewise clean, AST-bearing Disk without reexports. This is a depth-one closure, not a transitive traversal. Complete-empty public exports remain valid only when genuinely authenticated. Missing or unsupported contributions, intermediate/transitive/artifact dependencies, self/cycles, reexports, Open/Generated sources, recovery or diagnostics withhold this optimization. Same-spelling conflicts and qualification/aliases follow existing owner semantics; a diagnostic-bearing conflict cannot become a cache success.
Derive distinct targets from authenticated importer prescan, parsed imports and real resolution. Require a bijection between those targets, supplied immutable summaries, accepted leaf Frontends and their captured target-owned source/metadata associations. The importer has exactly its own SourceLoad plus one Frontend physical parent per distinct target; each leaf Frontend has exactly its own current SourceLoad lineage. Validate every target's native capture, snapshot/plan/index/task, package version/edition/root/path/source keys/maps, AST, A13 local exports and summary identity through the existing zero-import leaf validation. Reject missing, surplus, duplicate, swapped, stale or foreign associations, including a correct summary paired with another leaf's source. Equal content/fingerprint values cannot collapse distinct targets or authenticate identity. Source summaries retain existing `lockfile_identity: None`; captured lock/config inputs confer no release authenticity.
Repeated imports of the same target share one physical leaf parent but retain every ordered ordinal/span/alias/branch provenance entry. Never deduplicate by lexical spelling or fingerprint. The actual bound parser/provider must consume exactly the validated summary set used for expectations and execution; copied descriptors, caller contexts and matching hashes do not authenticate selection. Retain actual bootstrap descriptor/provider association and executing-image residency for all participating code; unavailable association refuses caching.

## Readiness, retention and persistence

Q4-A reuses the [dependency-ready callback](driver.md#dependency-ready-native-disk-frontend-binding) on the actual importer, after accepted PackageResolve, own SourceLoad and every required leaf Frontend, whether Completed or CacheHit with a real output. Bind exact graph task/result/overlay correspondence; arrival order, Store presence and cached strings cannot supply readiness. No leaf is pre-run and no synthetic completion is created. Only scheduler-accepted hits expose reconstructed importer output. A failed/cancelled/unavailable parent follows ordinary scheduling and cannot prepare a partial closure.
Acquire scoped IR owners for own SourceLoad, every leaf Frontend and its SourceLoad before consuming them; retain all through full expectations, lookup/decode, scheduler consumption and final validation, including the rehydrated importer. Partial acquisition failure releases every owner already acquired. Recheck physical validity, lane/request/snapshot/cancellation/supersession/publisher authority before and after lower work and scheduler handoffs. Release on success, miss, refusal, decode/Store failure, scheduler error, cancellation and supersession. Readers/snapshot leases confer no current-use/publication right, no atomic lifetime across Store I/O is promised, and frozen capture promises no later disk freshness.
Q5-A pairs dependency-ready lookup with guarded PersistentPrefix writes from genuine clean importer output and accepted dependency results under the identical whole closure. Validate every parent/summary association and complete expected output before insertion; one inadmissible leaf withholds importer caching rather than dropping that leaf. Independently eligible leaf writes may stand; guard loss suppresses further writes without rolling back earlier valid writes. Preserve best-effort Store failures, package routing, invalid-input/real-producer error precedence, pure registered NoKey and existing direct/retained/zero-/one-leaf contracts. Unsupported contexts withhold optimization without new diagnostics or manufactured semantic success.

## Owner Q-decisions

**Q1 — cardinality.** A: all finite exact depth-one sets of direct import-free workspace leaves, retaining duplicate import provenance. B: admit exactly two distinct targets first and require another definition before further cardinalities. **Recommend A:** the same per-target bijection and all-parent validation apply without a new arbitrary cardinality policy; this grants no transitive/intermediate/artifact admission or resource bound.
**Q2 — projection.** A: retain existing private v1 list encoding and complete owner keys if the coverage mapping is complete and zero-/one-leaf bytes remain unchanged. B: define a new versioned private projection before multiple-target admission. **Recommend A conditionally:** existing lists can represent all rows; no schema/compatibility change is authorized by assumption. Missing coverage or encoding ambiguity requires owner resolution before implementation, never a partial key.
**Q3 — expectations.** A: genuine full importer analysis using the authenticated complete summary set before lookup. B: first define an independent parsing-avoiding expectation producer. **Recommend A:** extends the approved bounded oracle without inventing a new Frontend authority. B needs its own owner seam/footprint proposal and explicit parsing-avoidance criteria.
**Q4 — timing and lifetime.** A: existing importer-readiness callback with scoped ownership of every physical dependency through scheduler use. B: a separate all-leaf preparation stage with new staging/retention rules. **Recommend A:** preserves Build graph execution and avoids speculative producers; neither option bypasses currentness or exact accepted-result correspondence.
**Q5 — rollout.** A: guarded multi-leaf writes and reads together. B: read-only admission first, genuine writes later. **Recommend A:** enables real automatic cold/warm evidence and whole-closure fallback. B requires a separately identified genuine record producer before positive lookup credit. Neither alters Store compatibility, zero-/one-leaf behavior or proof/publication policy.

## Conditional verification and handoff

After owner approval, the implementation freeze defines at most six case families:
1. Under Q1-A, two- and three-distinct-target runs with real leaves, distinguishable exports, repeated import of one leaf and genuinely complete-empty exports (Q1-B instead requires third-target fallback): automatic cold writes, warm/fresh captures, resident/blob and current SourceId rebinding equal independent clean full keys/bytes/maps/sides/parent commitments/diagnostics/outcomes. Use independent workspace/capture registry/empty Store and opposite worker/completion/capture controls; expected values never come from the cache under test.
2. Edit each leaf independently while importer bytes stay unchanged, including a lexical edit directly observed in importer token content; add/remove/replace a target and change duplicate/alias/branch provenance. Each viable changed input invalidates or refuses; unchanged local IDs and scheduling permutations preserve canonical identity. Reuse existing notation/operator/parser/edition/config/lock/policy/runtime invalidation controls, extending where multiple associations create a new obligation.
3. Start from otherwise viable real records and independently attack missing/surplus/duplicate/swapped/foreign/stale/collected Frontend/SourceLoad pairs, target/summary/provider mismatch and coherently rewritten-hash payload corruption; refuse before unchecked publication even when different targets have equal export fingerprints.
4. Deterministically stagger leaves, mix accepted Completed/CacheHit parents, fail/cancel one parent and cancel/supersede/replace publisher during preparation. Verify no premature lookup, exact all-parent retention through scheduler consumption, partial-acquisition cleanup and release on every terminal path.
5. An otherwise viable multi-leaf closure with exactly one cache-inadmissible leaf yields no importer hit/write and equals independent clean ordinary execution; never drop that member. Conflicting same-spelling multi-leaf imports retain ordinary errors; qualification/alias resolution retains ordinary outcomes and caches only when otherwise eligible. Unsupported/incomplete/transitive/intermediate/artifact/cyclic/diagnostic cases and disabled/failing Store preserve viable ordinary execution and real error precedence.
6. Existing zero-/one-leaf cold/warm, direct/retained/persistent/NoKey, canonical compatibility and later-service/proof/publication/reuse deferrals remain unchanged. No broader cache or full STEP6C completion claim.
Reuse Driver `source_load/native_disk.rs` imported cold/warm and independent edit/clean tests, `supplied.rs`/`misc.rs` parent handoff, `frontend.rs` real conflict cases, private source-adapter refusal tests and affected Build/Frontend/Resolver/Cache/IR owner groups. Positive evidence uses actual bootstrap, genuine producers, scheduler events and Store records. Subsequent freeze specifies exact implementation write paths, APIs/encodings, per-case outcomes, focused checks and short E2E; changed cache/lifecycle obligations run then, with full regression only on cadence triggers. New language/semantic/compatibility choices return to the owner. This definition changes no code/tests/spec/coverage/audit status.
