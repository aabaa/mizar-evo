## Existing producers and missing seams

The real [supplied workspace-leaf route](frontend_adapter.md#supplied-workspace-leaf-summaries) authenticates a current sealed leaf Frontend and its own SourceLoad lineage, builds A13 local exports and a canonical lexical contribution, and supplies that summary to the actual provider. The [scheduled prefix](driver.md#scheduled-sourceloadfrontend-prefix) can hand off genuine leaves through a complete import overlay. Intermediate and artifact-summary producers exist, but do not establish cache eligibility. Do not fabricate a complete artifact ModuleSummary from a source lexical summary.
Existing [encoding](frontend_adapter.md#native-leaf-frontend-record-encoding), [retained lookup](frontend_adapter.md#retained-native-leaf-frontend-lookup) and [cold expectations](frontend_adapter.md#cold-native-leaf-frontend-expectations) admit zero imports only. Missing are the imported input closure/key projection, independent importer expectations using authenticated leaf summaries, actual provider/runtime binding and scheduler lookup/retention at dependency readiness. These are definition gaps; imported admission and tests remain implementation prerequisites.
Driver owns run/capture/provider association and orchestration. Build retains plan/index/config/lock and scheduling authority; Frontend owns preprocessing, key bundles, lexical environments, parsing and output storage; Resolver/Artifact retain target resolution, A13 correspondence and summary identities. Cache owns canonical keys, compatibility and Store validation; IR owns payload reconstruction, lineage, physical validity and retention; Proof owns effective policy and acceptance/reuse. No public context or lower-owner API is introduced here.

## Proposed bounded closure

Under Q1-A, admit only a diagnostic-free AST-bearing Disk importer with one distinct direct captured workspace target, itself a clean import-free leaf without reexports. Repeated imports of that target retain ordinal/span/alias provenance under existing rules; they do not create duplicate physical parents. Private-only exports may yield a genuinely complete-empty contribution. Missing/unsupported contributions, other targets, intermediate/transitive imports, artifact dependencies, cycles/self-imports, reexports, Open/Generated sources, recovery and diagnostics withhold optimization. Ordinary services retain their existing broader behavior.
Authenticate protected native capture, snapshot/plan/index/task and target-owned package version/edition/root/path/source metadata under the existing leaf rules. Require exactly the current own SourceLoad and resolved leaf Frontend parents, selected by kind/work-unit, with no missing/surplus/duplicate parent; validate the leaf's own current physical SourceLoad lineage, source keys/maps, AST and A13 export correspondence. Authenticate importer prescan and parsed imports against its source and resolution; every supplied summary must come from that exact validated leaf and every distinct target must be represented. Index/overlay identities, equal fingerprints and generic sealed publications alone are insufficient. Retain existing source-summary identity, including lockfile_identity None; captured lock/config identities remain separate and confer no release authenticity.
The actual Frontend service/provider must consume that exact immutable validated summary set. Bind its selected parser/provider implementation, registered/actual descriptors and owner codecs to the genuine bootstrap association. Extend the existing executing-image residency closure to all newly participating Resolver/Artifact/export/lexical-provider code; copied descriptors, TypeId, caller roots or equal digests cannot authenticate selection. Unsupported linkage or unavailable association refuses caching. Preserve actual installed Proof policy, per-package configuration/Store routing and no new compatibility equivalence.

## Complete keys and independent expectations

Q2-A requires a complete versioned imported-input projection alongside the unchanged full owner Frontend key bundle. Cover source semantic and raw-storage identities, preprocessing lexical/import-prescan hashes, each resolved summary's full module identity and lexical fingerprint, ordered import provenance, active lexical environment, notation/synonym/antonym effects, predicate/functor metadata and source-position operator views, parser lexing plan/filter/context, token key/content, parser input hash/schema/version and edition. Preserve own and leaf parent content/side-table commitments, target source/key association, actual config/lock/policy/runtime/schema inputs and complete canonical named inputs. Do not replace a multiset or ordered provenance with a set, infer token content from a token-key hash, or use a semantic proof DependencySlice for lexical completeness.
The subsequent implementation freeze must map every required component to its genuine owner value and exact versioned canonical encoding, ordering and Cache key field, including coverage through existing composite hashes. Missing operator/notation/filter evidence is unavailable, never zero. Reuse owner codecs and exact Cache compatibility; no speculative new upstream hash or schema is approved here. Volatile SourceId/session/lane/task/worker/order/retention and cache-root routing do not enter semantic keys; original ordinal/source-position information does where owned semantics require it.
Under Q3-A, run genuine full Frontend analysis from the current bound SourceUnit and the same authenticated provider summaries, independently of Store data and any retained importer Frontend. Require clean AST/key and exact source/preprocess/dependency correspondence. Produce the entire key bundle, semantic canonical bytes, complete raw Disk storage, maps, side tables and named-input/parent expectations before lookup. Compare complete incoming raw storage before decoding, retain IR expected semantic/side validation and Cache key/produced-by validation, then rebind current SourceId/maps and reconstruct current lineage through owner codecs. Never publish unchecked bytes for an equivalence test. A miss may repeat analysis; this proposal makes no parsing-avoidance claim.

## Scheduler timing, lifetime and refusal

Q4-A prepares lookup only at the actual importer's graph readiness after PackageResolve and genuine own SourceLoad and leaf Frontend dependencies have been accepted by the scheduler. The leaf may be genuinely executed or admitted through its already supported zero-import cache path. Validate exact graph/overlay/task correspondence; do not run roots, SourceLoad or leaves ahead of the scheduler, synthesize Complete results, or derive dependency readiness from Store metadata. Q3 analysis is expectation preparation, not a completed scheduler task. Ordinary execution remains eligible until Build accepts a real rehydrated skip; report prepared outputs only for the exact task finally CacheHit.
Acquire scoped IR owners for every consumed physical parent, including leaf SourceLoad lineage, before use; hold them through expectation generation, lookup/decode, scheduler consumption and final validation. Hold a rehydrated importer likewise. Check lane/request/snapshot/cancellation/publisher authorization and physical parents before use and after lower work at existing handoffs; release every acquired owner on success, miss, refusal, scheduler error, cancellation and supersession. Borrowed readers or snapshot leases do not confer currentness or publication rights. No atomic lifetime across Store I/O is promised; frozen capture does not promise later disk freshness.
Q5-A extends best-effort PersistentPrefix writes only from actual accepted Completed/CacheHit dependency results and a genuine clean importer output under the same validated closure. Revalidate output, parent correspondence, physical/current authorization and complete expected payload before insertion. Guard loss suppresses further writes; earlier valid writes need not roll back. Missing/unsupported context withholds only the affected optimization under approved Q6-A; disabled cache, lookup/decode/retention/Store failures preserve ordinary outcomes. Invalid input and real producer errors retain existing precedence; no new diagnostics or semantic success are manufactured. Registered cache queries stay pure NoKey; direct/retained and zero-import routes retain their existing contracts.

## Owner Q-decisions

**Q1 — first imported profile.** A: one distinct direct workspace import-free leaf, permitting existing duplicate import provenance. B: include multiple targets/intermediates/artifacts now. **Recommend A:** uses a genuine bounded producer without transitive authentication or external summary provenance. B requires a larger explicit closure, ownership and test proposal before implementation; neither grants semantic import/export acceptance.
**Q2 — closure representation.** A: reuse the complete owner key bundle plus a versioned canonical dependency/parent association projection with the coverage mapping above. B: add a new Frontend-owned complete lexical/parse footprint producer first. **Recommend A for this bounded profile:** minimizes public surface while refusing any unmapped input. If complete coverage cannot be established from genuine owner values, return the gap for a prerequisite decision; do not silently implement a partial A. B needs a separately frozen owner seam, not copied parallel AST/summary structures.
**Q3 — independent expectations.** A: genuine full importer Frontend analysis with authenticated current summaries before lookup. B: first build an independent expectation producer that avoids parsing. **Recommend A:** follows the approved cold-profile staging with a complete oracle. B needs a new producer/footprint proof and explicit parsing-avoidance criteria. Store records or retained importer outputs cannot supply either option's current expectations.
**Q4 — scheduler placement.** A: perform dependency-aware preparation when the actual importer becomes ready, scoped to accepted parents. B: require all parents to be precomputed in a separate preparation stage. **Recommend A:** preserves graph execution ownership and avoids speculative phase work. B needs explicit staging/retention and correspondence rules; neither bypasses Build readiness or current-use guards.
**Q5 — persistence rollout.** A: pair guarded imported writes with dependency-ready lookup in the later implementation. B: implement read-only lookup first and defer genuine writes. **Recommend A:** supplies real cold/warm records and observable fallback without test-authored positives. B needs a separately identified genuine producer before positive lookup credit. Both preserve best-effort Store semantics and existing zero-import behavior.

## Conditional validation and handoff

After approval, freeze at most six case families: (1) genuine importer/leaf cold writes, warm/fresh-capture lookup, resident/blob and SourceId rebinding against independent clean full keys/bytes/maps/sides/lineage/diagnostics/outcomes; (2) independently viable source/raw/import-prelude/target/alias/lexical/notation/operator/parser/edition/leaf-summary/config/lock/policy/runtime changes miss/refuse, while worker/order/local-ID changes preserve canonical identity; (3) stale/foreign/collected/swapped/missing/surplus parents, wrong summary/provider and coherent rewritten-hash corrupt records refuse before unchecked publication; (4) deterministic readiness, cancellation/supersession/publisher replacement and all owner-release paths; (5) disabled/failing Store and unsupported/incomplete/transitive/artifact/diagnostic profiles preserve viable ordinary execution and error precedence; (6) zero-import/retained/persistent/NoKey and later-service deferrals remain unchanged. Each refusal control starts from an otherwise viable cache record and clean run; missing data never stands for complete-empty.
Reuse Driver `source_load/supplied.rs`, `misc.rs` scheduled-overlay and `native_disk.rs` matrices plus Frontend/Cache/IR owner tests. Positive evidence must use actual bootstrap, scheduler events, genuine producers and Store records; actual CacheHit and absence of importer TaskStarted prove scheduler skipping only, not avoided expectation parsing. Owner approval of Q1–Q5 precedes a Muse implementation dispatch and contract freeze naming exact producer APIs/encoding, scheduler hook, owner write scopes, retention/error paths and focused/E2E gates. New semantic or compatibility choices return to the owner. No code, tests, spec, coverage, proof/publication/reuse or full STEP6C status changes here.
