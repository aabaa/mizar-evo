## 既存境界と提案 closure

[通常の intermediate consumer](frontend_adapter.md#workspace-intermediate-summaries) は direct lineage を検証し、消費済み祖先について current な sealed publication を信頼するが、祖先 payload を独立再検証しない。実装済み[複数 direct-leaf caching](multiple_direct_leaf_frontend_caching.md) は各 leaf/SourceLoad pair を認証する。`registry.rs::native_frontend_cache_parents` の legacy v1 経路は依存 Frontend の graph 依存を root/own SourceLoad のみに限定し、`frontend_adapter/source.rs::prepare_native_disk_frontend_cache_payload` も leaf lineage を独立強制する。Intermediate 経路は実装契約に従い限定 closure 全体を別途認証し、legacy direct-leaf 経路の admission 条件は維持する。
Q1-A の新 closure は importer I → intermediate M → import-free 祖先 A のみで、同じ captured workspace package の異なる三 module。全て clean AST-bearing native Disk で reexport/recovery/診断なし。各 edge は指定 target だけへ resolve し、重複 import の ordinal/span/alias/branch provenance を保持する。無関係 workspace module を closure に加えない。既存 zero-/one-/multiple-direct-leaf は維持。artifact 依存/index summary、cycle/self-import、追加 branch/depth、cross-package intermediate、Open/Generated、字句 contribution 不明は新最適化を見送る。不適格 member を黙って除かない。
Physical lineage は direct のまま。A は own SourceLoad、M は own SourceLoad と A Frontend、I は own SourceLoad と M Frontend を持つ。PackageResolve は scheduling 前提で payload 親を捏造しない。Cache 用に保持・認証した祖先を I の余分な出力親にしない。両 edge とも A13 direct local public contribution だけを export し、真正 complete-empty と不明を区別する。A の記号は M を介して I に暗黙可視化しない。A 編集で M token/key が変わっても M local export と I active lexical environment は等しい場合があり、後述の保守的 invalidation は可視性を変えない。
Driver は capture/provider/runtime association と orchestration、Build は graph/index/config/lock/readiness、Frontend は前処理・全 key・parse/output/storage、Resolver/Artifact は resolve/A13 identity、Cache は canonical key/Store、IR は physical lineage/reconstruction/retention、Proof は acceptance/reuse を所有。既存 private path/owner 表現を使い、public recursive graph API・summary 型・lower-owner seam を承認しない。

## 祖先認証と独立 cold expectation

Q2-A は実 scheduler 受理出力と保護された current captured SourceUnit から closure を bottom-up 認証する。各段で一意 package plan/index/version/edition/root/path/source metadata、snapshot/graph/task/overlay、source input key、canonical raw Disk storage/map、全 named input を実 SourceLoad/Frontend に対応させる。summary/export fingerprint が等しくても不足/余剰/重複/入替え/foreign/stale/collected を canonical ordering 前に拒否。workspace summary の lockfile_identity None を維持し、config/lock bytes は release attestation を与えない。
Imported summary なしで current source の A を真正 full analysis して A13 local summary を導出し、その認証済み immutable A summary だけで current M を独立 full analysis。M local summary を導出し、それだけで I を解析する。期待 key/token/payload bytes/named input/side table を Store record や retained A/M/I Frontend payload から得ない。受理依存 payload の全 owner key・semantic/raw storage・side table・named input を独立生成結果と比較してから認証済み依存として使う。通常実行の sealed-publication trust だけでは新 intermediate cache admission を与えない。
期待生成と scheduled execution の各段で、実際に bind された parser/provider が検証済み summary を消費すること。Bootstrap descriptor/provider association と参加 code の executing-image residency を認証する。コピー descriptor/context 文字列/一致 hash は association の証明にならず、根拠がなければ cache を拒否。Miss で full analysis を繰り返してよい。受理 CacheHit と importer TaskStarted 不在は scheduler skip のみを示し、parse 回避/proof reuse credit はない。

## Footprint と encoding 判断

Q3-A は既存 `frontend-dependencies` named input に intermediate 専用 private `mizar-driver/native-disk-frontend-dependencies/v2` domain を提案する。全既存 owner key と native source/raw-storage/config/lock/policy/runtime/schema input を維持。Zero-/one-/multiple-direct-leaf の v1 bytes と dispatch route は変更せず、M 自体の既存 direct-leaf caching は v1 で継続できる。Cache/IR public schema version 変更は承認しない。
V2 canonical preimage は root target と target 順 A/M/I entry を持ち、各 entry に全 `FrontendCacheKeys::canonical_bytes`、owner `PreprocessedSource::canonical_bytes`、実 `TokenStream::canonical_bytes`、順序付き resolved import provenance、消費 edge ごとの target 対応 full summary module identity/fingerprint/owner 順 `ExportedSymbolShape::canonical_bytes`、正確な direct-parent relation を含む。全消費 closure の SourceLoad/Frontend content と side-table commitment を phase/work-unit 順に含め、I Frontend 自体は含めない。SourceLoad storage/map/key 認証は必須。既存 owner encoding と Cache hashing を使い、token content を token-key hash で、identity を summary fingerprint で代用しない。
M local export summary が不変でも A の完全な認証済み lexical/parse footprint を commit し、A 編集で I は保守的に miss するが transitive lexical export を作らない。全 owner key/content により notation/synonym/antonym、predicate/functor metadata、source-position operator view、lexer/filter/parser/schema/edition を各段で保持。不明 mapping は zero/empty で埋めず拒否。Import 順は semantic provenance、module/physical 順は canonical serialization。SourceId/session/lane/task/worker/capture/completion 順、retention、cache-root routing は semantic key 外とし、physical relation は slot/output ID でなく logical phase/work-unit と commitment を使う。
実装契約は framing/order/codec/hash 配置と真正 owner API 対応を固定し、I 出力を除外し legacy v1 bytes を維持する。未対応入力や public schema/compatibility 変更の必要性は owner に戻す。承認済み限定実装は public compatibility を変更しない。

## Currentness、保持、永続化

Q4-A は既存[dependency-ready callback](driver.md#dependency-ready-native-disk-frontend-binding)を、PackageResolve、I SourceLoad、M Frontend と正確な受理済み A/M SourceLoad/Frontend ancestry が揃ってから拡張する。両 edge の graph/result/overlay 対応を検証。Completed/CacheHit は真正 current output がある場合のみ等価。Scheduler service の先行実行や Store 存在からの readiness 推測はしない。失敗/cancel/欠落祖先は部分 hit/write を作らず通常 scheduling に従う。
三つの SourceLoad と A/M Frontend を消費前に scoped IR owner で保持し、lookup 成功時は再構築 I も取得。全消費 closure を期待生成、lookup/decode、scheduler 受理/消費、最終検証まで保持。部分 acquisition 失敗で取得済みを解放し、成功/miss/refusal/Store・decode・scheduler error/cancel/supersede の全経路で全解放する。Lower work、Store I/O、handoff 前後で physical validity と request/lane/snapshot/cancellation/supersession/publisher authority を再確認。Retention/read lease は current-use/publication 権限や I/O を跨ぐ atomic lifetime を与えず、frozen capture は後の disk freshness を保証しない。
Q5-A は同一の完全認証 closure と独立 whole-payload expectation の下、真正受理済み clean I 出力から best-effort PersistentPrefix write を行う。Decode 前の全 raw storage、owner semantic/side/named-input expectation、Cache key/produced-by、current SourceId rebinding、再構築 direct lineage を検証。一祖先不適格でも I lookup/write を見送り、独立適格な A/M write は維持可能。Guard 喪失は以降の write を止め既存 valid write は巻き戻さない。Store disabled/failure、miss、非対応 profile は通常結果と invalid-input/実 producer error 優先順位を保持し、新診断や成功を捏造しない。Direct/retained/NoKey と later-service/proof/publication/reuse deferral を維持。

## Owner Q-decisions

**Q1 — profile。** A: 既存経路に上記限定同一 package I → M → A を追加。B: 現 admission を維持し intermediate cache は延期。**推奨 A:** 一般 recursion/branch/artifact/reexport/cycle を許可せず STEP6C 前提を供給する。
**Q2 — 祖先根拠。** A: 各段を bottom-up 独立 full-source 解析し全受理依存 payload と比較。B: sealed-publication trust を維持し、別の承認済み owner 契約が独立認証済み祖先 receipt の完全性を証明するまで intermediate hit を延期。**推奨 A:** 現 metadata だけでは独立祖先 payload 根拠が得られない。B は延期で、seal-only admission ではない。
**Q3 — projection。** A: 全既存 owner key と legacy v1 bytes を保ち intermediate 専用 private v2 closure encoding。B: unchanged v1 direct-leaf encoding が全 chain を曖昧なく commit する別 mapping 証明まで admission 延期。**推奨 A:** 明示 relation/祖先入力で新 topology と旧 leaf list の混同を避け、public schema を変えない。
**Q4 — lifetime。** A: 既存 Driver readiness callback と限定 closure 全体の scoped IR owner。B: 別設計の IR transitive-retention API が owner 承認されるまで延期。**推奨 A:** 消費する physical payload 五つだけを既存 direct lineage/currentness のまま保護し、新 public lifetime 保証は不要。
**Q5 — persistence。** A: dependency-ready lookup と真正 guarded PersistentPrefix write。B: read-only を先行し write 延期。**推奨 A:** 自動 cold/warm と whole-closure refusal を観測可能。B の positive hit 根拠には別途許可された真正 producer が必要で、同じ独立 expectation を要求する。

## 条件付き検証と引継ぎ

実装契約は次の六 case family を定義する。Spec/trace/audit status/semantic credit は変更しない:
1. 識別可能な export と complete-empty control の真正 chain。自動 cold write、warm/fresh-capture resident/blob hit、Completed/CacheHit 混在を、独立 workspace/capture registry/空 Store/別 SourceId の uncached full analysis と比較。逆 worker/order/capture layout で全 module key/bytes/maps/sides/direct parent commitment/診断/session・phase outcome を確認。
2. I/M bytes 固定で A 字句宣言を独立編集し M token content の変化と I へ A 記号を暗黙継承しないことを確認。M local summary/I lexical environment 不変でも I 依存は保守的に invalidate。M local export/I source と duplicate/alias/branch provenance も別編集し viable 入力は affected key を miss、edited-warm recapture を独立 clean と比較。Scheduling/local-ID 置換は canonical identity 不変。既存 notation/operator/parser/config/lock/policy/runtime control を再利用。
3. 他条件が viable な真正 record で各 ancestor/source/summary/provider/edge の不足/余剰/重複/入替え/foreign/stale/collected と hash も整合する payload corruption を独立攻撃。Summary fingerprint が等しくても unchecked publication 前に拒否。
4. A/M 完了を決定的に遅延し cache/実行親混在、祖先 fail/cancel、準備/I/O/handoff 中の cancel/supersede/publisher 交換、部分 acquisition 失敗を検査。早すぎる lookup がなく、全消費 payload を保持し全終端 cleanup を確認。
5. 他条件が viable な一祖先不適格で I hit/write がなく、その祖先を落とさず独立 clean 通常実行と一致。Artifact/reexport/cycle/deeper/branching/cross-package/診断/不完全 profile、disabled/failing Store は通常 outcome/error 優先順位を保持し、両 edge の conflict と qualification/alias 意味を維持。
6. Zero-/one-/multiple-direct-leaf、retained/persistent/NoKey と legacy canonical compatibility を維持し、広い cache/parse 回避/Proof reuse/full STEP6C 完了を主張しない。
`source_load/misc.rs::scheduled_workspace_intermediate_consumes_only_its_own_public_symbols`、`supplied.rs::supplied_workspace_intermediate_rejects_reexport_and_changed_captured_import_index`、`native_disk.rs::imported_native_disk_edits_match_independent_clean_runs_across_profiles` と真正 imported cold/warm/refusal/lifecycle control、影響する Build/Frontend/Resolver/Cache/IR owner 群を再利用する。実装契約で exact write path/API/encoding/case outcome/focused check/短い E2E を指定。変更 cache/lifecycle 義務は直ちに実行し full regression は cadence。T1 N1/N2 根拠 follow-up は本ユニット外。
