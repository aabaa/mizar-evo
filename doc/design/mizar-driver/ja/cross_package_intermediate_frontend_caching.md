# Cross-package intermediate native Disk Frontend caching 提案
Canonical language: English; [英語正本](../en/cross_package_intermediate_frontend_caching.md)。

## Status and authority

**Q1–Q5 は owner 承認待ち。** [Driver 計画](00.crate_plan.md#task-index)の本定義は、既存 STEP6A47 の app/main→app/mid→core/base producer を [STEP6C](../../mizar-build/ja/incremental_parallel_equivalence.md) の前提として提案する。cache は有効化しない。実装には owner 判断と後続 Muse dispatch/freeze が必要。full STEP6C、言語、診断、意味的 acceptance、proof/reuse、trace/audit、parsing 回避の credit は得ない。
承認済み同一 package 設計の [authority](../en/intermediate_workspace_frontend_caching.md#status-and-authority)、[owner 境界](../en/intermediate_workspace_frontend_caching.md#existing-boundary-and-proposed-closure)、[完全 footprint](../en/intermediate_workspace_frontend_caching.md#footprint-and-encoding-decision)、[独立期待値](../en/intermediate_workspace_frontend_caching.md#ancestor-authentication-and-independent-cold-expectations)を維持する。仕様の [workspace layout](../../../spec/ja/23.package_management_and_build_system.md#233-ワークスペースのレイアウト)は共有 workspace lock、[supplied summaries](frontend_adapter.md#supplied-workspace-leaf-summaries) は target 所有の package metadata を規定する。本提案は cross-package 差分のみを所有し、通常実行の sealed-publication trust は変更しない。

## Exact admission delta

Q1-A は相異なる clean AST-bearing captured native Disk module 三つ、I=app/main→M=app/mid→A=core/base のみを追加する。I/M は同一 workspace package、import-free A は別の第二 package に属する。名前は既存 producer の例であり、判定は文字列でなく topology による。各 edge は指定された一つの distinct target のみを持ち、重複 import は ordinal/span/alias/branch provenance を保つ。両 package を accepted plan/index と complete captured overlay に一意に結合する。無関係な workspace module は closure に含めない。
既存 zero-/direct-leaf、同一 package intermediate route を維持する。cross-package direct-leaf M は既存 route で独立に適格となり得る。一般の package 配置、分岐/追加深度、cycle/self-import、artifact dependency、reexport、Open/Generated、diagnostic/recovery、AST 欠如、利用不能な lexical contribution は member を除去せず optimization を拒否し、通常実行の結果とエラーを維持する。
各 edge では完全な A13 direct local public export のみを消費し、正当な complete-empty summary を含む。A は M の token に影響し得るが、I から暗黙に見えるようにはならない。direct physical lineage は A←A SourceLoad、M←M SourceLoad+A Frontend、I←I SourceLoad+M Frontend。PackageResolve は scheduling 前提に留まる。祖先認証/保持で I payload parent や意味的 export authority を追加しない。

## Per-package authentication and independent expectations

Q2-A は承認済み [bottom-up algorithm](../en/intermediate_workspace_frontend_caching.md#ancestor-authentication-and-independent-cold-expectations)を適用する。CurrentPackage authorization は同一 package の証拠ではない。両 edge を exact accepted graph/results、parsed/prescanned resolved import、complete overlay、protected captured source と照合する。local path/source byte/export fingerprint が同じでも missing/surplus/duplicate/swapped/foreign/stale/collected association は sort 前に拒否する。
I/M/A ごとに自身の一意な workspace PackagePlan/PackageIndexEntry を選び、package/module、一致する version/edition、安全な member/root/source-root/manifest path、captured Disk SourceVersion/SourceUnit identity/hash/path/edition、exact SourceLoad key/storage/map を検証する。app metadata は core の代わりにならない。消費する A/M ModuleSummaryIdentity は target 自身の version/edition、完全 canonical module identity、owner 順 ExportedSymbolShape byte を持つ。workspace summary の lockfile_identity は None を維持し、release/lock attestation や新たな edition 互換規則を与えない。
各 module の完全 Frontend key/source/raw storage/semantic byte/side table/named input を維持する。package 固有の effective verifier/build setting は Build の独立 aggregate で当該 package に関連付け、既存 [config content](frontend_adapter.md#native-config-content-association) 検査で認証する。workspace は既存 [共有 lock content](frontend_adapter.md#native-lock-content-association) binding を使う。package ごとの lock digest を発明せず、core setting を app default に置換せず、config から policy を推論しない。既存 policy/toolchain/schema/runtime input は必須。
captured source から summary なしで A を独立に full analysis し、local A13 summary を導出して M を解析し、M の local summary のみで I を解析する。各解析は自身の captured package context を使う。期待 key/token/storage/map/side/named input は Store や retained A/M/I Frontend output から得ない。accepted A/M payload 全体を独立結果と比較してから cache evidence に使う。lookup reconstruction と persistence の双方で genuine I output を独立 I 期待値と照合する。
独立解析と scheduled run は actual bound parser/provider を使い、bootstrap descriptor/provider association と participating running-image residency 検査を維持する。metadata コピーや同じ hash は association の証明にならない。mapping/evidence 不足は optimization を拒否する。miss 時に解析が重複し得る。CacheHit の scheduler skip は parsing 回避の証拠ではない。

## Footprint and compatibility

Q3-A は既存 private intermediate-only `mizar-driver/native-disk-frontend-dependencies/v2` domain と `frontend-dependencies` named input の再利用を推奨し、framing/codec/hash algorithm は変えない。target-qualified root/module entry、resolved import、full consumed summary identity、phase/work-unit-qualified physical entry は既に package を区別する。target を module path のみに潰さず、並列 package table を加えない。同じ input の v1 と同一 package v2 byte を維持する。
coverage mapping は I/M/A full owner key・preprocessed byte・実 token content→module ごとの lexical/parse input、A/M consumed full summary identity→両 package の version/edition と local export（I は M と app package を共有）、import/direct relation→両 graph edge と provenance、三 SourceLoad と A/M Frontend→完全 content/side commitment。既存 source/config/shared-lock/policy/toolchain/runtime/schema request input は owner mapping を維持する。package/root/index 対応は独立に検証し、root を場当たり的な key field として追加しない。
A lexical edit は M export/I lexical environment が不変でも M と保守的に I を invalidate する。I/M source byte を固定した正当な core version/edition/config 変更は既存互換規則に従い miss または拒否する。共有 lock 変更は既存 whole-workspace footprint に従う。SourceId/task/worker/capture/completion order/output slot/Store root/retention は新たな semantic input にしない。未対応 consumed input/public compatibility 変更は owner に戻し、empty/zero で代用せず、不完全 mapping で v2 を有効化しない。

## Currentness, retention and guarded persistence

Q4-A は [dependency-ready scheduling](driver.md#dependency-ready-native-disk-frontend-binding) を再利用し、同じ current snapshot/graph の accepted PackageResolve、I SourceLoad/M Frontend、exact A/M SourceLoad/Frontend 祖先を要求する。Completed/CacheHit の同等扱いには genuine accepted current payload が必要。Store の存在から readiness を推測せず scheduler service を先行実行しない。祖先失敗/cancellation は通常 scheduling に従い partial preparation を禁じる。
消費前に三 SourceLoad と A/M Frontend の scoped IR owner、hit 時には reconstructed I も取得する。独立解析、lookup/decode、scheduler acceptance/consumption、最終検証まで全 closure を保持する。partial acquisition と success/miss/refusal、Store/decode/scheduler error、cancellation、supersession の全 owner を解放する。lower work/Store I/O/handoff 前後で physical validity、snapshot/request/lane currentness、cancellation/supersession、publisher authority を再確認する。retention/read lease は current-use/publication、atomic I/O lifetime、後日の disk freshness を与えない。
Q5-A は同じ whole-closure expectation の下、genuine accepted clean I output からの guarded best-effort PersistentPrefix write と lookup を組み合わせる。decode 前の完全 raw storage、semantic/side/named-input expectation、Cache key/produced-by binding、current SourceId rebinding、exact direct lineage を検証する。一 member 不適格で I lookup/write を抑止し、独立に適格な A/M/SourceLoad write は維持できる。guard 喪失は後続 write を抑止するが以前の正当な write は戻さない。Store 無効/失敗、miss、unsupported profile は通常結果と invalid-input/producer error precedence を保ち、新診断や偽成功を作らない。
新 public seam/schema/transitive-retention API は提案しない。

## Owner Q-decisions

Q2/Q4/Q5 は既承認の保護を新 admission 境界に適用する。
**Q1 — profile。** A: 上記 I/M=app、import-free A=core のみを許可。B: 現 admission を維持し延期。**A 推奨:** 既存 STEP6A47 producer を使い、任意 package topology は除外する。
**Q2 — authentication。** A: target 所有 context で独立 bottom-up full-source expectation と accepted payload 全体比較を維持。B: 別途承認する independent ancestor-receipt 設計まで延期。**A 推奨:** sealed-publication trust 単独では cache closure を認証できない。
**Q3 — compatibility。** A: 上記完全 coverage mapping と legacy byte 不変を条件に private v2 を再利用。B: 別途 freeze する private-version encoding 提案まで延期。**A 推奨:** v2 は既に全 target/relation を package で区別し、新 domain 単独では不足認証を補えない。mapping 不成立なら実装 admission 前に owner に戻す。
**Q4 — lifetime。** A: dependency-ready callback と五祖先 payload および reconstructed I の scoped owner を再利用。B: owner 承認の新 transitive-retention interface まで延期。**A 推奨:** package 境界は新たな physical lifetime model を必要としない。
**Q5 — persistence。** A: guarded genuine cold write と warm lookup を併せて導入。B: write を延期し positive hit evidence の前に別 genuine producer を承認。**A 推奨:** 同じ独立 closure 検査で両方を守り automatic cold/warm の観測可能性を維持する。

## Conditional verification and handoff

後続実装契約の六 family。今回の定義で実行した証拠ではない:
1. 既存二 package chain の識別可能/complete-empty local export。automatic cold write、warm/fresh-capture resident/blob hit、mixed Completed/CacheHit を、別 workspace/registry/empty Store・異なる SourceId の独立 uncached full run と比較する。worker/order/capture permutation で完全 key/byte/line-loading map/side/direct parent commitment/diagnostic/phase-session outcome を照合する。
2. A lexical declaration（M token は変化、M export/I environment は同じでもよい）、M local export、I source を独立編集。affected key は miss、edited-warm は independent clean と一致。I/M byte 固定で core version/edition/package config を変更し、workspace の他条件は正当とする。shared-lock/config association と既存 policy/runtime control は別に確認。不正 package/edition は通常エラーを維持する。
3. その他は正当な genuine record に対し、両 package の plan/index/version/edition/root/source binding、cross-edge provenance、summary/provider association、完全 payload を missing/surplus/duplicate/swapped/foreign/stale/collected evidence と coherent hash-rewritten corruption で攻撃。同じ local name/export でも拒否。lineage-swap control は genuine lower-owner publication/current authorization の成功を先に確認し、exact dependency-authentication refusal と successful rehydration ゼロを要求する。正当な package/list/local-ID permutation は key を維持する。
4. A/M readiness を遅延させ execute/hit を混在。祖先失敗/cancellation、preparation/I/O/handoff 周辺の cancellation/supersession/publisher 交換、partial acquisition を検証。早すぎる lookup がなく、consumption まで全祖先保持と全 terminal cleanup を要求する。
5. 正当な positive cache-write baseline の後、不適格祖先の試行を反復し、実際の phase/work-unit ごとの Store record path/byte を前後比較する。I hit/write と record 変更はなく、独立適格な dependency write は維持できる。unsupported profile、通常 conflict/qualification/alias、Store 無効/失敗は independent clean outcome/error precedence と一致する。
6. legacy v1 と同一 package v2 byte control、direct/retained/persistent/NoKey route、later-service/proof/reuse/STEP6C deferral を維持。N1/N2 修復は本 unit 外で再開しない。
