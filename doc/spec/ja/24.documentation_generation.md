ドキュメント ジェネレーター (`mizar doc`) は、source fileから構造化ドキュメントを抽出し、参照可能な相互参照された HTML 出力を生成します。ドキュメントのsourceは Mizar source自体です: 項目ラベル、型署名、定理ステートメント、および `:::` ドキュメント コメント (§2.9.1)。別のドキュメント言語は必要ありません。

ジェネレーターは、`*.mizir.json` アーティファクト (§23.5.1) から `exports` 配列を読み取り、どのアイテムが公開されるかを決定し、`@latex` 注釈 (§21.3) と同じアーティファクトからの解決された型を使用して数学的表記をレンダリングします。

## 24.1 ドキュメントのコメント構文

**ドキュメント コメント** は、名前付き項目 (定義、定理、登録、またはアルゴリズム) の直前にある `:::` 行コメントの連続ブロックです。コメント ブロックとその項目の間に空白行を入れてはなりません。空白行で関連付けが終了します。

```mizar
::: Computes the greatest common divisor of two positive integers
::: using the Euclidean algorithm.
:::
::: The result satisfies `result divides a`, `result divides b`, and
::: for any `d` dividing both `a` and `b`, `d divides result`.
terminating algorithm euclid_gcd(a, b) -> Nat
  requires a > 0 & b > 0
  ensures result = Gcd(a, b)
  ...
```

本文は **Markdown**、CommonMark 0.31.2 と次の Mizar 拡張として解釈する。parser 基準は `pulldown-cmark =0.13.6`、`default-features = false`、`Options::empty()`。tables、footnotes、task lists、strikethrough、smart punctuation、heading attributes、metadata blocks、native math を無効とする。heading、thematic break、container、code、reference definition、link/image/autolink、escape/entity、raw HTML を含む全 CommonMark を維持する。実装受入れ前に固定版 CommonMark example と Mizar 相互作用ケースを満たし、不一致は言語を狭めず owner に返す。raw HTML の解析は後続 sanitization/output 方針を決めない。

- バッククォートで囲まれたインライン コード (`` `code` ``) は、Mizar 構文の強調表示でレンダリングされます。内容が正確なラベルまたは FQN 参照である場合にのみリンクされます (§24.2)。
- `$$` で区切られた表示数学は数式としてレンダリングされます (§24.3)。
- `[文章](ref)` 形式の相互参照リンクは、§24.2 で説明されているように解決されます。

**ブロック構造。** ドキュメント コメントには、空白の `:::` 行で区切られた複数の段落が含まれる場合があります。リスト、コード ブロック、およびブロック引用符の警告は、`:::` 行内の標準の Markdown 構文を使用してサポートされます。

```mizar
::: Computes `n!` (n factorial) for a natural number `n`.
:::
::: ## Examples
:::
::: ```mizar
::: factorial(0) = 1
::: factorial(5) = 120
::: ```
:::
::: ## Mathematical definition
:::
::: $$n! = \prod_{k=1}^{n} k$$
:::
::: The algorithm terminates because `n` decreases at each recursive call.
terminating algorithm factorial(n) -> Nat
  ensures result = Factorial(n)
  decreasing n
  ...
```

**構造化タグ** 次のタグは、ドキュメント コメント内の段落の最初のtokenとして表示される場合があります。

|タグ |使い方 |
|---|---|
| `@param name` | `name` という名前のパラメータについて説明します。パラメータごとに 1 つのタグ。 |
| `@returns` |戻り値を文書化します。識別子 `result` は戻り値を参照します。 |
| `@requires` |前提条件の散文説明 (形式的な `requires` 句を補足します)。 |
| `@ensures` |事後条件の散文的な説明 (形式的な `ensures` 句を補足します)。 |
| `@see ref` | 「関連項目」相互参照リンク (§24.2) を追加します。 |
| `@since version` |アイテムが導入されたバージョンを記録します。 |
| `@deprecated version` | `version` 以降、項目を非推奨としてマークします。非推奨メッセージが続きます。 |

**Raw field model.** 各行の `:::` と直後の ASCII space 最大1個だけを除去し、global trim/deindent・二度目の正規化なしに残りと raw/reverse 写像を保持する。`W` は ASCII space、tab、CR、LF。tag を開始できるのは CommonMark paragraph の最初の inline source 位置だけで、quote・tight/loose list item の構造的 paragraph も event wrapper の省略にかかわらず含む。認識時は container/paragraph indentation だけを除き写像を保持する。heading・code・HTML・reference definition は tag を導入しない。marker は literal `@` と最大 non-W token で、小文字の既知名に完全一致する場合だけ認識する。escape/entity、code/emphasis/link wrapper、大文字、`@param,` は既知 tag を作らず、未知 tag は原文のまま保持する。
marker 後は同じ paragraph 内の W を飛ばし、`@param`・`@see`・`@since`・`@deprecated` は次の最大 non-W 原文 token を name/ref/version とする。markup decode・特別な引用・token/version/reference 文法を課さない。欠落 slot を別 paragraph から借りない。body は separator W 後の残り（slotless は marker-separator W 後）で、意味境界から separator W を除くが全 raw payload は保持する。soft/hard break は同一 field を継続し、次 paragraph/block で終わる。したがって以下の連続 `@param a`・`@param b`・`@returns`・`@requires`・`@see` 行は単一の `@param` field であり、別 field には空 paragraph が必要。後続 block は通常文書のまま。
display 認識後・inline math 前に論理 paragraph stream から field を抽出し、slot は math に対して不透明とする。各 segment を container 除去・comment 抽出・Artifact/loading 写像経由で実ソースに結び、架空の連続範囲を作らない。重複比較は継続行の container prefix を含む抽出原文 slice を使い、最終寄与行の終端改行の直前で終える。内部改行・末尾 space/tab は有意。`@param` は raw name 完全一致、`@returns`・`@since`・`@deprecated` は payload に関係なく singleton、repeatable `@requires`・`@ensures`・`@see` は tag 名と separator/末尾 W を含む全 post-marker payload の完全一致で比較する。同一の完全 provenance target の別 block もソース順で比較し、後の一致ごとに警告して merge/上書きしない。Unicode/whitespace/entity/markup/reference 正規化は禁止する。
`@returns`・`@requires`・`@ensures` と `@deprecated version` 後の body は non-W ソース文字を1個以上必要とし、markup のみでも満たす。`@param` 説明は任意、`@see`/`@since` は slot のみ必須。slot/body 欠如、承認済み重複、確立した metadata 不一致は原文を保持し §22.6.9 で警告する。raw parameter name は同一 target の権威 metadata だけと比較し、完全一覧だけが不在を確立でき、部分・利用不能一覧はできない。`@returns` は権威 metadata が戻り値なしと確立した場合だけ不一致。未文書 parameter・利用不能 metadata・未解決 ref は警告せず、signature を推測し prose と形式式を比較しない。tag は statement annotation でも形式 contract でもない。

```mizar
::: Divides `a` by `b` and returns the quotient.
:::
::: @param a  the dividend
::: @param b  the divisor; must be non-zero
::: @returns  the real number `a / b`
::: @requires `b <> 0`
::: @see mml.real.Real_div_mul
definition
  let a, b be Real;

  algorithm divide(a, b) -> Real
    requires b <> 0
    ensures result * b = a
  do
    return a / b;
  end;
end;
```

**moduleレベルのドキュメント。** source fileの先頭、`import` または定義ステートメントの前にあるドキュメント コメントは、module全体をドキュメント化します。これは、生成された出力のmoduleのインデックス ページに表示されます。

## 24.2 相互参照とハイパーリンク

ドキュメント ジェネレーターは、パッケージ全体とその依存関係にわたるラベル付き項目間の相互参照を解決します。参照は式ベースではなくラベルベースであるため、アイテムにoverloadされた表記法や複数の表面構文がある場合でも、ドキュメントのリンクは安定しています。

**インライン コード リンク。** バックティック スパンの内容が正確な項目ラベルまたは FQN である場合、ジェネレーターはその項目のドキュメント ページにリンクします。

```
::: The result equals `Gcd` as defined in `mml.nat.Gcd`.
```

**出現と比較。** 各出現の形式（code・明示リンク・`@see`）、raw spelling、利用可能なら解釈済み destination、写像済み source segments、付着先 module/item identity と publication provenance を保持する。§24.1 が渡す解釈済み destination を完全一致で比較し、追加 trim、大文字小文字変換、Unicode 正規化、式解析を行わない。raw text は診断用に残す。backtick 内の式・定理断片・overload 表記は code のままとし、一つの式を複数参照に分解しない。destination 分類の欠落・未対応は未解決の引継ぎであり、symbol を推測しない。

**探索と完全性。** target は元の完全な package/version/lock/module/edition identity、publication hash、export origin、FQN、実 label、visibility を保持し、再 export も格納済み identity を維持する。選択された文書 visibility 方針を適用するが検証権限を与えない。複数経路の完全 target identity が同一の場合だけ統合する。非修飾 label は現 module の export target が一つなら確定し、異なる target が複数なら曖昧、ゼロの場合だけ import を探索する。権威ある意味上の順序で全 import を巡回し、位置が異なっても異なる二 target が一致すれば曖昧とする。最初の候補を勝者にしない。現 module の確定結果がなければ import metadata の利用不能・不完全状態で解決成功を主張しない。順序付き import vector の利用不能・不完全・明示的完全空を区別し、保存順を意味上の import 順としない。

FQN 探索は明示的に束縛された有限の package/dependency 文書 closure のみを対象とする。package/version をまたぐ同一 FQN の異なる完全 identity は曖昧のままであり、新たな識別構文や version 選択を導入しない。探索 namespace と page/anchor が完全な場合だけ一意 target をリンクでき、完全探索後のゼロ件だけが未解決となる。欠落入力を否定結果や空 graph としない。dependency reference は package tuple、publication hash、index location を持つ。index consumer は使用前に schema・publication・完全 target identity を検証済み入力に照らして認証する。path や canonical sort では edge を認証できない。循環から source/dependency の再帰的発見を行わず、network lookup も行わない。

**明示的なリンク。** 標準の Markdown リンク構文 `[表示テキスト](ref)` は、`ref` の 3 つの形式を受け入れます。

|フォーム |例 | | に解決されます。
|---|---|---|
|ラベルまたは FQN | `(Gcd)`、`(mml.nat.Gcd)` |ラベル付きアイテムのドキュメント ページ |
|セクション参照 | `(§20.5.1)` |生成された仕様内のセクションアンカー |
| URL | `(https://...)` |外部 URL (変更せずにパススルー) |

```mizar
::: This algorithm implements the approach described in [§20.5.1](§20.5.1).
::: The result type is documented under [Element of R](algebra.struct.Element).
```

**自動後方参照。** 各定理 `T` の「Used by」は、注釈を要求せず、`by` 句で `T` を直接引用するすべての定理を列挙する。Artifact owner が引用元・引用先の定理 export identity、出現 provenance、どの定理本体・証明を対象としたかを含む完全性 scope を持つ、権威ある publication-bound 直接引用 record を供給する。既存 `exports` や `used_axioms` だけではこの graph を確立できず、既存 artifact field や新 schema を意味しない。producer 欠落・endpoint 未写像は利用不能・不完全であり引用ゼロではない。consumer は source、名前、受理済み証明 evidence から引用を再構成しない。

直接写像済み theorem-to-theorem edge のみを逆引きする。権威ある自己引用を含め、target ごとに引用元定理を一度表示し、package 間 edge は endpoint 束縛を要する。反復出現の provenance と順序は別に保持する。表示順は既存の完全 module identity 順、exact FQN、origin、最後に publication hash とする。`@see`、Markdown link、推移依存、`used_axioms` のみの entry は direct-by evidence ではない。不完全な coverage は利用不能と明示し、完全な空リストとしない。

**`@see` リンク。** ドキュメント コメント内の `@see ref` タグは、アイテムのページの下部にある「関連項目」リストにエントリを追加します。 `ref` は、明示的リンクと同じ 3 つの形式に従います。

**ページとアンカー命名。** 完全な module/publication identity を key とする別の allocation table が、選択 output root からの相対 module-page path を供給する。package/version を区別し、href 構築前に path collision を拒否する。directory spelling は選択しない。各文書 item の full DOM id は export label に由来する権威ある exact FQN とし、notation slug、正規化、suffix、改名を行わない。権威ある label が利用不能なら item-anchor readiness を、異なる item が同一 page の同一 full id を要求するならその page の link readiness を阻止する。item 参照先は割当済み module page と full FQN fragment であり、例えば `algebra.ring.AddAssoc` の論理 anchor は `#algebra.ring.AddAssoc` となる。

`#AddAssoc` 等の short alias は、page 上でその label を持つ異なる文書 target が一つだけで、どの full id・section id・他 alias とも衝突しない場合に限り省略可能な形で出力できる。full id が優先し、alias 抑制で full id を変えない。section heading は `#sec-20-5-1` を使い、section 参照は仕様 version・section id・page destination を束縛する明示的 generated-specification index を要する。欠落・不明 section は未解決のままとし、local module anchor にしない。

**Href encoding。** 割当済み path の各 segment で ASCII 英数字と `-._~` 以外の UTF-8 byte を percent-encode し、`/` は path separator のみとして残して相対 href を構築する。完全な論理 fragment も同じ byte 規則で encode する。DOM id は HTML attribute として escape しつつ exact FQN spelling を保つ。例えば割当 path `p/é%#.html` と論理 fragment `m.é%#` は `p/%C3%A9%25%23.html#m.%C3%A9%25%23` となり、DOM id は `m.é%#` のままである。filesystem layout・source-link routing は選択しない。

**縮退と実装ゲート。** 未解決・曖昧な適格参照は安全な非リンク text と決定的 Documentation warning で表示する。不完全な link/UsedBy 入力は completeness warning と利用不能表示を伴い、単なる未解決や完全空にしない。下位 reader の integrity/schema/binding 拒否は維持する。Doc10 は認証済みの順序付き import/dependency 入力と Artifact direct-by producer、検証済み page/anchor/仕様 section 割当、正確な共有診断 descriptor・detail/location・deduplication・ordering 規則の採用を引き続き要する。このリンクモデル採用ではそれら producer・allocation・diagnostics を実装しない。

ラベルはパブリック ドキュメント インターフェイスの一部です。定義には定義ラベルが使用されます。定理と登録については、定理または登録ラベルが使用されます。アルゴリズムの場合、アルゴリズム識別子はドキュメントのラベルです。将来の構文で別のアルゴリズム ラベルが導入された場合、ドキュメント ジェネレーターは代わりにそのラベルを使用します。

## 24.3 数式のレンダリング

生成されたドキュメントの数学的表記は、シンボル定義の `@latex` 注釈 (§21.3) とドキュメントのコメントに埋め込まれた LaTeX 式の 2 つのsourceから得られます。

**`@latex` 注釈。** functor、述語、モード、または属性定義に `@latex` 注釈が付けられている場合、ジェネレーターは、定理ステートメント、型署名、および数式表示など、レンダリングされた出力にシンボルが表示される場所であればどこでも、指定された LaTeX 文字列を置き換えます。 `@latex` 注釈が存在しない場合、シンボル名は等幅書体で表示されます。

```mizar
@latex("n!")
func Factorial(n) -> Nat;

@latex("\gcd(a, b)")
func Gcd(a, b) -> Nat;
```

ステートメントに両方の記号が含まれる定理は次のように表現されます。

> **定理** `gcd_factorial_coprime`: すべての $n \geq 2$ に対して、$\gcd(n!, n+1) = 1$。

ドキュメント コメント内の **インライン数式** では、標準の LaTeX 区切り文字が使用されます。

- インライン: `$formula$` — 周囲のテキストとともにインラインでレンダリングされます。
- 表示: `$$formula$$` を単独の行に表示 — 中央に配置された表示方程式としてレンダリングされます。

**Delimiter boundaries.** CommonMark fenced/indented code、HTML block、reference definition を先に認識し、次に display math とする。いずれも structured tag を含まない。残り paragraph で field を抽出後、code span・inline HTML・link/image/autolink 構造を inline math より先に認識し、label 以外の内部を保護する。backtick 内容は後続 highlighting・完全 label/FQN 照合へそのまま渡し、式を解決しない。display 外の標準 link を保持し、destination/`@see` の raw text・range を後続解決へ渡す。残り paragraph text では隣接 `$` のない unescaped 単一 `$` が同 paragraph 内の次の同条件 `$` と非空内部を挟んで対応する。escape は backslash 偶奇で決め、通貨 heuristic は使わない。math は emphasis より優先するが code/HTML・link/image/autolink 全体の境界を越えず、link label 内では同 label 内だけで対応する。`$[text](ref)$` は link と未対応 literal dollar（警告）を保持し、`[$x$](ref)` は label math を保持する。
display delimiter 行は container marker と最大3個の indentation space 後、周囲の任意 space/tab と `$$nonempty content$$` または `$$` だけからなる。後者は同一 container stack/list item 内の後続 `$$` 単独行を探し、保護 code/HTML/reference-definition block または container 終端で止まる。delimiter 行自体も保護 block 外に限る。中断した opener は未対応で途中を消費せず CommonMark parse を保持する。受理 display は paragraph/inline 処理より先で、内部には non-W 文字を必要とし、raw text/newline/map を後続 rendering へ不透明に保持する。他の dollar run は literal。単一行候補は最外 pair だけを使い内部 unescaped `$$` を許さず、それ以外は literal とする。対応 display の内部が W のみなら全原文を math node なしで保持して警告する。
未対応 emphasis/backtick・未閉鎖 fence を含む CommonMark literal/recovery だけでは警告しない。この面の警告は適格な未対応 math opener、W のみ display 内部、継承 tag 条件、実際の conversion/map 失敗だけ（§22.6.9）。拡張失敗は math node なしに原文を保持し、実際の conversion/map 失敗は対象 raw block を保持して既定 documentation build を継続する。下位 reader 拒否を表示成功にせず、欠落 map に架空の範囲を付けない。受理 math は不透明のまま。

ジェネレーターはビルド中に LaTeX 構文を検証しません。無効な LaTeX はレンダリング エンジンに渡され、出力でレンダリング エラーが発生する可能性があります。

**式の自動生成。** `@latex` 注釈のない項目の場合、ジェネレーターは、次のルールを使用して Mizar 曲面構文を LaTeX に変換することにより、デフォルトの数学的レンダリングを生成します。

| Mizar の構文 |デフォルトの LaTeX 出力 |
|---|---|
| `a + b` | `a + b` |
| `a * b` | `a \cdot b` |
| `a / b` | `\frac{a}{b}` |
| `a |^ n` | `a^{n}` |
| `a mod b` | `a \bmod b` |
| `a <= b` | `a \leq b` |
| `a <> b` | `a \neq b` |
| `a in S` | `a \in S` |
| `S c= T` | `S \subseteq T` |
| `for x being T holds P` | `\forall x \in T,\; P` |
| `ex x being T st P` | `\exists x \in T,\; P` |

自動翻訳は、`@latex` 注釈がオーバーライドしない場合にのみ適用されます。作成者は、非標準またはドメイン固有の表記法に対して `@latex` アノテーションを提供することをお勧めします。

**式の番号付け。** 定理ステートメント内の表示式には、HTML 出力で自動的に番号が付けられます。番号付けは `(chapter.section.item)` です。`item` は、アイテムのドキュメント ページ内の表示式の連続インデックスです。式の番号はハイパーリンクされており、ドキュメントのコメントで `$$\text{see }(24.3.1)$$` 構文を使用して参照できます。

## 24.4 HTML出力

ドキュメント ジェネレーターは、パッケージ マニフェストの `doc_dir` で指定されたディレクトリ (デフォルト: `docs/`) に静的 HTML サイトを書き込みます。

HTML 出力は、Web サーバーまたは GitHub ページでのホスティングに適した静的サイトです。クライアント側の数式レンダリングには **KaTeX** を使用しており、サーバー側の処理は必要ありません。

HTML 出力のディレクトリ構造:

```
docs/
├── index.html           ← package overview and module list
├── search.json          ← full-text search index
├── algebra/
│   ├── index.html       ← module index for `algebra`
│   ├── groups/
│   │   ├── basic.html   ← documentation for `algebra.groups.basic`
│   │   └── ...
│   └── ...
└── assets/
    ├── katex/           ← KaTeX library files
    ├── style.css
    └── search.js
```

**module インデックス ページ。** 各moduleのインデックス ページには、エクスポートされたすべてのアイテムとそのタイプ シグネチャ (可能な場合は `@latex` 注釈を使用してレンダリング)、ドキュメント コメントの最初の段落から抽出された 1 行の概要、および完全なアイテム ページへのリンクがリストされます。

**アイテム ページ。** 各名前付きアイテムには、次の内容を含む専用ページがあります。
- 数学的に表現された完全な型署名または定理ステートメント。
- HTML としてレンダリングされた完全なドキュメント コメント。
- `requires` 句と `ensures` 句 (アルゴリズムと関数用) は数学的にレンダリングされます。
- パラメータ テーブルとしてフォーマットされた `@param` タグと `@returns` タグ。
- 自動的に生成される「使用者」セクション (§24.2)。
- `@see` タグの「関連項目」リスト。
- source file内の関連行への「source」リンク (`*.mizir.json` の `source_range` を使用)。

**検索。** ジェネレーターは、エクスポートされたすべてのアイテムの FQN、アイテムの種類、1 行の概要、およびタイプ シグネチャを含む `search.json` インデックスを生成します。検索 UI (`search.js`) は、backendを必要とせずに、このインデックスに対してクライアント側の全文検索を実行します。

**バージョン付きドキュメント。** パッケージ マニフェストに `version` フィールド (§23.1) が含まれる場合、ジェネレーターはバージョン文字列をページ ヘッダーと `search.json` に埋め込みます。ホスティング インフラストラクチャはこれを使用して、複数のバージョンを同時に提供する場合があります。標準レイアウトでは、バージョン固有の出力が `docs/v2.3.1/` の下に配置されます。
